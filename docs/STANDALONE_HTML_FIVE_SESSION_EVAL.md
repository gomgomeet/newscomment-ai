# 단일 HTML 질문 챗봇 5회기 점검

점검일: 2026-08-26

## 점검 대상

- PR #20 `연수용 단일 프롬프트 + 단일 HTML 학생 챗봇`
- PR #21 `단일 프롬프트의 구조·교사 기입란·유의사항 안내`
- 생성 프롬프트: `docs/연수용-단일프롬프트-학생챗봇.md`
- 참조 구현: `webapp/질문챗봇-단일HTML.html`

실제 학생 자료나 API 키는 사용하지 않았다. GPT로 만든 가상 학년·성취기준·지문을
참조 HTML에 넣고, 키가 없는 지문 기반 엔진을 브라우저에서 실행했다.

## 가상 수업 5세트

| 회기 | 학년 | 가상 성취기준의 초점 | 지문 |
| --- | --- | --- | --- |
| 1 | 2학년 | 인물의 마음과 까닭 짐작 | 우산을 나눈 민지 |
| 2 | 3학년 | 관찰 사실과 까닭 구분 | 햇빛을 향한 강낭콩 |
| 3 | 4학년 | 중심 생각과 근거 찾기 | 급식 잔반을 줄인 약속 |
| 4 | 5학년 | 디지털 정보의 책임 있는 이용 | 사진을 올리기 전 세 가지 확인 |
| 5 | 6학년 | 수치 비교와 타당한 결론 | 두 이동 방법의 일주일 기록 |

회기마다 8개씩 총 40개 발화를 사용했다. 낱말의 사전 뜻과 문맥 뜻, 사실·수치,
까닭, 관찰 결과, 측정 방법, 다른 학교 적용, 학생의 원인 가설, 자료 밖 질문,
딴소리, 개인정보, 대필 요청, 종료를 포함했다.

## 첫 실행에서 발견한 문제

1. `주저하다`와 지문의 `주저했습니다`를 같은 낱말로 찾지 못했다.
2. 교사가 동사형 뜻을 적으면 `망설이다을 뜻해요`처럼 조사가 어긋났다.
3. 수치 변화, 관찰 사실, 측정 방법 질문에서 낱말만 겹친 다른 문장을 고르기도 했다.
4. 다른 학교에서도 같은 결과가 나오는 것처럼 읽힐 수 있는 답을 했다.
5. 학생이 제시한 원인을 가설과 확인된 사실로 구분하지 못했다.
6. 주소 공개 질문에 동의 문장만 제시하고 안전 여부를 먼저 답하지 못했다.
7. 학생의 `알겠어요`를 그대로 되풀이하며 종료했다.
8. 다음 학생을 시작할 때 직전 낱말과 근거가 남고, 번호를 다시 고를 경로가 없었다.
9. 같은 HTML에서 자료를 바꾸면 서로 다른 수업 기록이 섞일 수 있었다.

## 반영한 개선

- 프롬프트의 공통 대화 규칙을 15개에서 19개로 보완했다.
- 기본형·활용형 낱말 탐색과 `이라는/라는` 조사를 추가했다.
- 수치 변화, 측정·기록, 관찰 결과, 원인 문장을 질문 의도에 따라 우선한다.
- 자료에 없는 구체적인 수치와 측정 방법은 없다고 직접 밝힌다.
- 다른 환경으로의 적용과 동일한 결과 보장을 구분한다.
- 학생의 인과 설명을 가설로 표시하고 자료에서 확인된 사실과 나눈다.
- 개인정보 공개 질문에는 안전 여부를 먼저 답한다.
- [새 학생] 버튼과 대화 상태 초기화를 추가했다.
- 기록에 자료·학년·응답 엔진을 넣고 현재 자료의 기록만 내려받는다.

## 남은 한계

이번 점검은 키 없는 내장 엔진의 실제 실행 결과다. 프롬프트 안의 Gemini 지시문도 같은
규칙으로 보완했지만, 실제 유료 Gemini 키를 연결한 생성 답변의 자연스러움과 일관성은
별도 라이브 점검이 필요하다. 또한 생성형 AI가 이 프롬프트로 매번 만드는 HTML은 코드
구조가 달라질 수 있으므로, 연수생이 생성한 파일에는 문서의 최종 점검 발화를 다시 실행해야 한다.
