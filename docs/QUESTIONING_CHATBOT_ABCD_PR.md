# 질문 챗봇 A·B·C·D 구현

## 요약

- Notion 결과 저장을 고정 열이 아닌 현재 루브릭 기준으로 연결하고, 학생 기록 작성 프롬프트와 더 알아볼 질문을 남긴다.
- 어려운 문장은 원문의 사실·숫자·주체·시점을 지키며 쉬운 표현으로 바꾼다.
- 학생 질문 중심 1국면과 이해·성취기준·의견 질문 중심 2국면을 대화 이력만으로 운영한다.
- 질문하기, 지문 이해, 성취기준, 성찰질문과 의견 표현을 각각 0~5점으로 판정한다.

## 주요 변경

- B1/B2 전환과 2국면 질문 순서를 서버 판정기로 통합했다.
- 최근 대화 보존 범위를 18개 메시지로 늘려 국면과 채점 근거를 유지했다.
- 한국어 조사를 정규화해 `학교는`과 `학교에도`처럼 같은 주제를 놓치지 않게 했다.
- 지문에 실제로 없는 인용문은 어려운 문장 풀이의 원문으로 인정하지 않는다.
- 마지막 의견 답변 뒤에는 새 질문을 붙이지 않는다.
- Notion 점수 근거의 중복 점수 표기를 제거하고, 기존 `성취기준` 텍스트 열과 새 `성취기준 점수` 열의 충돌을 막았다.
- 교사용 `평가 불러오기`는 Notion에 저장된 실제 4개 판정 점수를 우선 사용하고, 저장 기록이 없는 학생만 Gemini 추천값을 사용한다.
- 평가표와 엑셀에 `도달 난이도`, `더 알아볼 질문`, 실제 점수 근거를 함께 연결했다.
- 교사용 제작보드, PRD, 1회성 프롬프트, 연수용 단일 프롬프트, 단일 HTML을 같은 규칙으로 맞췄다.

## 배포 게이트

Preview 배포에서 아래 Notion 결과 DB 열과 실제 학생 저장을 먼저 확인한다.

- 숫자: `질문하기`, `지문 이해`, `성취기준 점수`, `성찰질문과 의견 표현`
- 선택 또는 텍스트: `도달 난이도`
- 텍스트: `더 알아볼 질문`

필수 루브릭 열이 없으면 저장은 일부 기록을 남기지 않고 경고와 함께 중단한다. 운영 DB 스키마 확인과 Preview 통합 검증 전에는 Production으로 승격하지 않는다.

2026-08-26 읽기 전용 점검에서 현재 공유된 운영 결과 DB는 구형 평가 열만 가지고 있어 위 6개 열이 모두 부족했다. 코드는 누락을 감지해 안전하게 경고하며, 운영 DB에 열을 추가하고 실제 학생 1건의 저장→`평가 불러오기`→엑셀 흐름을 확인하기 전까지 Production 배포를 보류한다.

## 범위 밖

- 운영 Notion DB 스키마를 코드에서 자동 변경하지 않는다.
- 실제 학생 데이터나 로컬 `output/` 산출물을 커밋하지 않는다.
- 합성 대화 평가는 실제 학생 학습 효과 검증을 대신하지 않는다.
