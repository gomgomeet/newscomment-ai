# 노션 평가 대시보드 아이디어

질문 챗봇 결과 DB를 "학생 기록 창고"에서 "수업 끝나고 3분 안에 읽는 평가 화면"으로 바꾸기 위한 설계 아이디어를 모았다.

기준이 되는 현재 구조는 두 곳이다.

- 결과 DB 속성 정의: `docs/QUESTIONING_CHATBOT_NOTION_DB_TEMPLATE.md`
- 앱이 실제로 써 넣는 속성: `lib/notion/questioning-chatbot.ts`의 `buildResultProperties`
- 점수 체계: `lib/questioning-board.ts`의 `buildRubric` — 4개 기준 각 0~5점, 총점 0~20점

## 1. 지금 구조에서 대시보드가 막히는 지점

| 막히는 점 | 원인 | 결과 |
| --- | --- | --- |
| 반별로 못 나눈다 | `학교_반_번호`가 제목 한 덩어리다 | 그룹, 필터, 정렬을 반 단위로 걸 수 없다 |
| 차시별 비교가 안 된다 | 학생 한 명이 한 행이고 새 수업이 같은 행에 덮인다 | 지난 수업과 이번 수업을 나란히 볼 수 없다 |
| 총점만 있고 판정이 없다 | 도달 여부를 계산하는 속성이 없다 | 교사가 20점 만점 숫자를 눈으로 훑어야 한다 |
| 볼 순서를 못 정한다 | 정렬 기준이 되는 신호가 없다 | 30명 중 누구를 먼저 볼지 스스로 판단해야 한다 |
| 세특 칸을 바로 못 쓴다 | `세특용 피드백`에는 작성 프롬프트가 들어간다 | 대시보드에서 복사해 쓸 수 있는 문장이 아니다 |

## 2. 대시보드 화면 구성 아이디어

한 페이지에 여섯 개 구역을 쌓는다. 위에서 아래로 읽으면 "얼마나 됐나 → 누구를 볼까 → 무엇을 남길까" 순서가 된다.

### 구역 1. 오늘 수업 한 줄 요약

수업 자료 이름, 참여 학생 수, 학급 평균 총점, 도달 비율을 콜아웃 네 개로 둔다. 노션 수식과 롤업으로 채우고 숫자만 크게 보이게 한다.

### 구역 2. 도달 현황 보드

결과 DB를 보드 뷰로 만들고 `도달수준` 속성으로 그룹을 나눈다.

- 지원 필요 (총점 0~7)
- 부분 도달 (총점 8~11)
- 도달 (총점 12~15)
- 우수 (총점 16~20)

카드 앞면에는 학번, 총점, 도달 난이도만 보인다. 카드를 열면 질문모음과 점수 근거가 나온다. 교사가 카드를 옮기면 판정을 손으로 고칠 수 있게 수식 대신 선택 속성 + 자동 채움 버튼 조합도 고려한다.

### 구역 3. 기준별 평균 막대

노션 차트 블록으로 `질문하기`, `지문 이해`, `성취기준`, `성찰질문과 의견 표현` 네 기준의 학급 평균을 막대로 그린다. 어느 기준이 무너졌는지가 다음 차시 설계의 입력값이 된다.

### 구역 4. 먼저 볼 다섯 명

필터를 건 표 뷰 하나를 둔다.

- 총점 오름차순 정렬
- `지문 이해`가 2점 이하인 학생 우선
- 질문 수 0인 학생은 별도 표시

"성적이 낮은 학생"이 아니라 "다음 수업에서 먼저 말을 걸 학생" 목록으로 이름 붙인다.

### 구역 5. 빛나는 질문 갤러리

`더 알아볼 질문`이 비어 있지 않은 행만 갤러리 뷰로 모은다. 학번을 가리고 질문 문장만 큰 글씨로 띄우면 다음 시간 도입 자료로 그대로 쓸 수 있다.

### 구역 6. 세특 초안 작업대

`기록 상태` 속성(미확인 / 초안 있음 / 검토 완료)으로 그룹을 나눈 표 뷰를 둔다. 교사가 한 명씩 처리하며 상태를 옮긴다. 학기 말에 "검토 완료"만 필터해 내보낸다.

## 3. 새로 필요한 속성

앱이 이미 쓰는 속성은 그대로 두고, 대시보드를 위해 아래를 더한다.

| 속성 | 유형 | 채우는 주체 | 용도 |
| --- | --- | --- | --- |
| `반` | 선택 | 앱 | 반별 그룹과 필터 |
| `번호` | 숫자 | 앱 | 번호순 정렬 |
| `차시` | 텍스트 또는 선택 | 앱 | 수업 회차 구분 |
| `수업 코드` | 텍스트 | 앱 | 준비 DB와 연결 |
| `질문 수` | 숫자 | 앱 | 참여 여부 판단 |
| `도달수준` | 수식 | 노션 | 총점 구간을 판정으로 바꾼다 |
| `기록 상태` | 상태 | 교사 | 세특 처리 진행도 |

`학교_반_번호` 제목은 그대로 둔다. 학생 식별 규칙을 바꾸면 기존 누적 기록이 끊긴다.

### 도달수준 수식 예시

```text
if(prop("총점") >= 16, "우수",
  if(prop("총점") >= 12, "도달",
    if(prop("총점") >= 8, "부분 도달", "지원 필요")))
```

총점이 0이면 미참여일 가능성이 크므로 `질문 수`가 0인 경우를 먼저 걸러 "미참여"로 표시하는 분기를 앞에 둔다.

## 4. 노션 기능을 어디에 쓸지

- 관계형과 롤업: 준비 DB(수업)와 결과 DB(학생 응답)를 관계로 잇고, 준비 DB 쪽에서 학급 평균과 참여 인원을 롤업으로 받는다. 그러면 수업 한 줄이 곧 그 차시의 성적표가 된다.
- 노션 차트: 기준별 평균 막대, 차시별 평균 추이 선.
- 버튼: "이번 차시 대시보드 만들기" 버튼이 템플릿 페이지를 복제하고 필터를 이번 수업 코드로 맞춘다.
- 뷰 여러 개: 같은 결과 DB를 보드, 표, 갤러리, 타임라인으로 나눠 붙인다. DB를 늘리지 않는다.
- 싱크 블록: 학년 공유 페이지에 도달 현황만 싱크로 내보내고 개별 기록은 두지 않는다.

## 5. 세 단계 로드맵

### 1단계 — 앱 코드를 건드리지 않고 오늘 할 수 있는 것

`도달수준` 수식 속성과 `기록 상태` 속성을 노션에서 직접 만들고, 보드 뷰와 갤러리 뷰를 붙인다. 이미 저장된 총점과 더 알아볼 질문만으로도 구역 2, 3, 5, 6이 선다.

### 2단계 — 앱이 속성 몇 개를 더 써 준다

`buildResultProperties`에 `반`, `번호`, `차시`, `수업 코드`, `질문 수`를 더한다. `applyProperty`는 결과 DB에 그 속성이 없으면 조용히 건너뛰므로, 기존 교사의 DB를 깨지 않고 더할 수 있다. 이 단계가 끝나면 반별 그룹과 차시별 비교가 열린다.

### 3단계 — 웹앱 인사이트와 노션 대시보드의 역할을 나눈다

앱은 채점과 저장을 맡고, 노션은 보기와 기록을 맡는다. 앱의 `/dashboard` 인사이트 화면은 기준별 평균만 유지하고, 학급 운영에 필요한 시선은 노션 대시보드로 넘긴다. 같은 화면을 두 곳에서 관리하지 않는다.

## 6. 개인정보 유의

- 실명 대신 `학교_반_번호`를 계속 쓴다.
- 학년 공유 페이지에는 개별 학생 행을 싱크하지 않는다. 집계만 내보낸다.
- 갤러리 뷰로 질문을 공유할 때 학번 속성을 뷰에서 숨긴다.
- 학부모 공유용 개별 페이지는 만들지 않는다. 필요하면 교사가 문장으로 옮겨 적는다.
