# 질문 챗봇 API 저장 및 배포 가이드

이 문서는 질문 챗봇을 수업에서 바로 사용하기 위해 필요한 API 키 저장 방법과 배포 방식을 한곳에 정리한 자료이다.

## 2026-08-26 배포 게이트

현재 운영형 학생 챗봇은 학생 브라우저에서 교사 Gemini 키를 읽거나 전송하지 않는다. 학생용 외부 모델은 서버에서 아래 두 환경변수를 모두 켠 경우에만 사용하며, 기본값은 로컬 자료 기반 응답이다.

```text
QUESTIONING_STUDENT_LLM_ENABLED=true
QUESTIONING_STUDENT_PROVIDER=approved_gemini
```

운영 Notion 결과 DB에는 `질문하기`, `지문 이해`, `성취기준 점수`, `성찰질문과 의견 표현` 숫자 열과 `도달 난이도`, `더 알아볼 질문` 열이 필요하다. 필수 루브릭 열이 없으면 저장은 경고와 함께 중단된다.

배포 순서는 `브랜치 푸시 → Vercel Preview 빌드 → 수업 코드·2국면 대화·Notion 실제 저장 확인 → Production 승격`이다. 운영 DB 스키마와 Preview 통합 검증을 마치기 전에는 Production으로 승격하지 않는다.

## 1. 현재 챗봇 구성

- 교사용 제작보드: `/questioning-board`
- 학생용 챗봇: `/questioning-chatbot`
- 사용 API: Gemini API
- 기본 모델: `gemini-2.5-flash`
- API 경로:
  - `/api/questioning-board/analyze-image`
  - `/api/questioning-board/chat`

교사용 제작보드에서 질문 자료, 챗봇 설정, 평가 루브릭을 준비하면 같은 브라우저의 학생용 챗봇에 연결된다.

## 2. API 키 저장 방법

### 방법 A. 수업용 PC에서 직접 입력

가장 간단한 방법이다.

1. Google AI Studio에서 Gemini API 키를 발급한다.
2. 교사용 제작보드 `/questioning-board`를 연다.
3. 화면 상단의 `Gemini API 연결` 영역에 API 키를 입력한다.
4. 모델을 선택한 뒤 `키 저장`을 누른다.
5. 학생용 챗봇 `/questioning-chatbot`을 열어 응답을 테스트한다.

이 방식으로 저장한 키는 코드나 문서에 들어가지 않고, 현재 브라우저의 `localStorage`에만 저장된다.

공용 PC나 학교 PC에서 사용한 뒤에는 반드시 교사용 제작보드에서 `키 지우기`를 눌러 삭제한다.

### 방법 B. 서버 환경변수로 저장

정식 배포나 여러 기기에서 안정적으로 사용할 때 권장하는 방법이다.

`.env.local`에 아래 값을 넣는다.

```text
GEMINI_API_KEY=your-gemini-api-key
GEMINI_QUESTIONING_MODEL=gemini-2.5-flash
```

주의할 점은 다음과 같다.

- `.env.local`은 Git에 커밋하지 않는다.
- API 키를 Notion, 문서, 코드, 엑셀 파일에 붙여 넣지 않는다.
- 키가 노출되었다고 의심되면 Google AI Studio에서 즉시 폐기하고 새 키를 발급한다.

## 3. 수업 전 점검 순서

1. 로컬 서버를 실행한다.

```powershell
npm run dev
```

2. 교사용 제작보드를 연다.

```text
http://localhost:3000/questioning-board
```

3. Gemini API 키를 연결하거나 서버 환경변수가 적용되어 있는지 확인한다.
4. 질문 자료 원문이 학생용 챗봇에 전체 텍스트로 표시되는지 확인한다.
5. 학생용 챗봇을 연다.

```text
http://localhost:3000/questioning-chatbot
```

6. `채팅 시작`을 눌렀을 때 챗봇이 먼저 인사하는지 확인한다.
7. 사실 질문, 이유 질문, 생활 적용 질문을 각각 테스트한다.
8. 수업 자료와 상관없는 질문을 했을 때 수업 내용으로 돌아오도록 안내하는지 확인한다.
9. 활동지 정답 대필이나 개인정보 입력 요청을 제한하는지 확인한다.

## 4. 배포 방식 선택

### 로컬 실행 방식

교사용 컴퓨터 한 대에서 수업을 운영할 때 적합하다.

- 장점: 가장 빠르게 사용할 수 있다.
- 장점: API 키를 브라우저나 `.env.local`에만 둘 수 있다.
- 주의: 학생들이 각자 접속해야 한다면 같은 네트워크 접근 설정이 필요할 수 있다.

### 서버 배포 방식

학생 여러 명이 각자 기기에서 접속해야 할 때 적합하다.

- 배포 서버에 `GEMINI_API_KEY`를 환경변수로 저장한다.
- 배포 주소는 HTTPS를 사용한다.
- API 키는 브라우저에 노출하지 않는다.
- 실제 학생 정보를 저장하지 않는 방향으로 운영한다.
- 배포 권한과 키 교체 권한을 누가 갖는지 미리 정한다.

### 교사별 API 키 + 학생 링크 방식

교사 연수생이 자기 API 키를 적용해 학생에게 챗봇을 제공하고, 결과물을 교사 대시보드로 받는 최종 운영 방식이다.

권장 흐름은 다음과 같다.

1. 교사가 교사용 대시보드에서 자신의 Gemini API 키를 등록한다.
2. 교사가 질문 자료와 챗봇 설정을 저장한다.
3. 시스템이 수업별 학생 접속 링크를 만든다.
4. 학생은 링크로 접속해 질문 챗봇을 사용한다.
5. 학생 질문과 챗봇 답변은 `학교_반_번호` 식별값과 함께 서버에 저장된다.
6. 교사는 대시보드에서 학생별 결과물을 확인하고 평가 기록으로 정리한다.

이 방식에서 가장 중요한 원칙은 학생 브라우저에 교사 API 키를 보내지 않는 것이다. 학생이 질문하면 학생 화면은 서버 API에 질문만 보내고, 서버가 저장된 교사 키 또는 서버 기본 키로 Gemini를 호출해야 한다.

현재 보드의 `localStorage` 키 저장 방식은 교사 개인 실습과 단일 브라우저 시연에는 적합하다. 그러나 학생 각자 기기에 링크를 배포하는 수업에서는 `localStorage`만으로는 교사 설정과 학생 결과가 안전하게 공유되지 않는다. 학생 링크 배포형으로 가려면 수업 설정과 학생 결과를 서버 DB에 저장하는 구조가 필요하다.

### HTML 파일 배포 방식

API 없이 로컬 예비 응답 모드로만 쓸 때 가능하다.

- 장점: 인터넷 연결이나 API 키 없이 일부 활동을 진행할 수 있다.
- 한계: Gemini 응답, 이미지 분석, 확장 질문 처리가 제한된다.
- 주의: API 키가 들어간 HTML 파일을 배포하면 안 된다.

## 6. 개인정보 및 보안 원칙

- 학생 이름, 얼굴, 연락처, 상담 내용이 포함된 이미지는 업로드하지 않는다.
- 평가 기록에는 필요한 최소 정보만 남긴다.
- 테스트할 때는 가명이나 예시 학생 데이터를 사용한다.
- Gemini API 사용은 학교와 교육청의 생성형 AI 활용 지침을 확인한 뒤 진행한다.
- 수업 후 공용 PC에서는 API 키와 테스트 데이터를 삭제한다.
- API 키는 코드, GitHub, Notion, 수업자료, 캡처 화면에 남기지 않는다.

## 7. 수업 당일 운영 메모

- API 연결이 실패하면 질문 자료 원문을 기반으로 한 로컬 예비 응답 모드로 전환된다.
- 로컬 예비 응답은 수업 흐름을 유지하기 위한 보조 기능이므로, 실제 수업 전 Gemini 연결 테스트를 권장한다.
- 학생용 챗봇은 질문 유형 이름을 직접 설명하지 않고, 학생의 질문과 생각에 먼저 반응하도록 설계되어 있다.
- 교사용 보드의 질문 자료는 학생용 챗봇에서 요약하지 않고 전체 텍스트로 보여 준다.
- 학생 대화 기록을 교사용 평가 기록으로 자동 연결할지는 별도 결정이 필요하다.

## 7-1. 현재 HTML 보드에 구현하는 방법 제안

현재 구현에 바로 이어 붙일 때는 한 번에 완전한 플랫폼으로 바꾸기보다 아래 순서로 확장한다.

1. **교사용 보드에 `수업 저장` 버튼 추가**
   - 저장 내용: 성취기준, 질문 자료 전체 텍스트, 루브릭, 챗봇 동작 설정, 교사 API 키 사용 여부
   - 저장 위치: Supabase 같은 서버 DB

2. **수업별 학생 링크 생성**
   - 예: `/questioning-chatbot/abc123`
   - 링크에는 API 키를 넣지 않는다.
   - 학생 링크는 질문 자료와 챗봇 설정만 불러온다.

3. **학생 첫 화면에 학교·반·번호 입력**
   - 모둠 선택이나 실명 입력 없이 학교, 반, 번호만 입력하게 한다.
   - 교사용 대시보드와 평가 기록에는 `학교_반_번호` 한 열로 합쳐 저장한다.
   - 개인정보를 쓰지 말라는 안내를 짧게 보여 준다.

4. **학생 질문 저장**
   - 질문, 챗봇 답변, 질문 분류, 자료 근거, 다시 쓴 질문, 성찰 문장을 서버에 저장한다.
   - 학생 화면에는 질문 분류를 보여 주지 않고, 교사용 대시보드에서만 확인한다.

5. **교사용 대시보드 결과 영역 연결**
   - 현재 5번 평가 기록 영역을 서버 결과 목록과 연결한다.
   - 학생별로 질문모음, 챗봇 답변모음, 점수 근거, 세특용 피드백을 볼 수 있게 한다.

6. **엑셀 다운로드 확장**
   - 현재 다운로드 기능이 있다면, 서버에 모인 학생 결과를 기준으로 내려받도록 바꾼다.

1차 구현은 `수업 저장`, `학생 링크`, `학생 결과 저장`, `대시보드 결과 조회`까지로 잡는 것이 좋다. 교사별 API 키 암호화 저장과 사용량 관리는 그다음 단계에서 보강한다.

## 8. 빠른 체크리스트

- [ ] Google AI Studio에서 Gemini API 키를 준비했다.
- [ ] 교사용 제작보드에서 API 키 저장 또는 서버 환경변수 설정을 확인했다.
- [ ] 질문 자료 원문이 학생용 챗봇에 전체 표시된다.
- [ ] `채팅 시작` 후 챗봇 첫 인사가 나온다.
- [ ] 자료 관련 질문에 짧고 구체적으로 답한다.
- [ ] 자료 밖 질문과 개인정보 입력을 제한한다.
- [ ] 공용 PC 사용 후 API 키를 삭제한다.
- [ ] 학생 링크 배포형에서는 API 키가 학생 브라우저에 노출되지 않는다.
- [ ] 학생 결과물이 교사용 대시보드에 모이는지 확인했다.
