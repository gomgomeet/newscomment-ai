# 질문 챗봇 30회기 반복 학습 및 개선 결과

작성일: 2026-08-25

대상 브랜치: `codex/questioning-chatbot-closeout`

## 1. 결론

오늘 리서치한 교사형 대화 원리를 바탕으로 합성 학생 **개발 세트 30회기, 120턴**을 실제 로컬 채팅 API에 재생했다. 오류를 유형화해 프롬프트, 대화정책, 자료 근거 선택, 로컬 응답 조립기를 수정했다.

수정에 사용하지 않은 새 기사와 학생 반응으로 **홀드아웃 10회기, 40턴**도 별도로 실행했다. 최종 전체 결과는 다음과 같다.

```text
개발 세트: 30회기, 120턴, 실패 0, 검토 플래그 0
홀드아웃: 10회기, 40턴, 실패 0, 검토 플래그 0
전체: 40회기, 160턴, 실패 0, 검토 플래그 0
```

이번 작업은 LLM 자체의 가중치를 바꾸는 파인튜닝이 아니다. **평가 주도 프롬프트·정책 최적화**, 또는 **합성 학습자 기반 다중 턴 회귀학습**이라고 부르는 것이 정확하다.

## 2. 왜 학생 채팅을 그대로 자동 학습시키지 않았는가

실제 학생 채팅을 검토 없이 계속 프롬프트나 학습 데이터에 넣으면 다음 문제가 생긴다.

- 이름, 전화번호, 친구·가정 정보 같은 개인정보가 학습 자료에 남을 수 있다.
- 장난, 공격적 표현, 잘못된 사실, 우연히 나온 어색한 답이 좋은 예시처럼 고정될 수 있다.
- 말이 많은 학생의 패턴이 과대표현되고 말이 짧은 학생이 배제될 수 있다.
- 모델이 점수는 높이지만 실제 교사 대화와 멀어지는 평가 편법을 배울 수 있다.
- 학생 대화가 수집된 목적과 다른 모델 학습에 사용될 수 있다.

따라서 이 프로젝트에서는 다음 원칙을 적용한다.

1. 운영 중인 학생 대화를 모델이 자동으로 학습하지 않는다.
2. 개선 후보는 교사가 비식별 상황으로 다시 작성한다.
3. 교사가 좋은 응답과 어색한 응답을 직접 구분한다.
4. 개발 세트에서 수정하고 별도 홀드아웃에서 회귀를 확인한다.
5. 통과한 정책과 예시만 다음 버전에 반영한다.

## 3. 적용한 리서치 방법

### 평가 주도 개선

OpenAI의 평가 안내는 좋은 결과를 먼저 구체적으로 정의하고, 실제 조건과 가까운 예시로 측정한 뒤, 오류 분석을 통해 개선하는 `Specify → Measure → Improve` 순환을 권한다. 초기 출력 50~100개를 검토해 오류 유형과 빈도를 만드는 방법도 제시한다. 이번 작업은 30회기 120턴을 개발 세트로 사용해 이 순환을 코드 수준에서 구현했다. [OpenAI, How evals drive the next chapter in AI](https://openai.com/index/evals-drive-next-chapter-of-ai/)

### 인지와 비인지 특성을 함께 가진 합성 학생

EMNLP 2024 연구는 학생 시뮬레이션에서 언어 능력 같은 인지 특성뿐 아니라 참여도와 성격 같은 비인지 특성을 함께 구성하고, 교사와 학생 관점의 다면 검증이 필요하다고 본다. 이번 fixture에는 읽기 방식, 확신, 참여 정도, 감정 상태를 함께 기록했다. [Liu et al., Personality-aware Student Simulation for Conversational Intelligent Tutoring Systems](https://aclanthology.org/2024.emnlp-main.37/)

### 합성 학생의 한계

ACL 2026 연구는 단순 프롬프트로 만든 합성 학생이 실제 학생을 충실히 재현하지 못할 수 있고, 언어·행동·인지 측면을 함께 검증해야 한다고 지적한다. 따라서 이번 30회기는 실제 학생 효과 연구가 아니라 프리파일럿 스트레스 테스트다. [Scarlatos et al., Simulated Students in Tutoring Dialogues: Substance or Illusion?](https://aclanthology.org/2026.acl-long.1960/)

### 자료 근거 평가는 문자열 일치만으로 부족

BEGIN 연구는 지식 기반 대화의 근거성을 자동 지표만으로 안정적으로 판별하기 어렵고, 자료가 길어질수록 성능이 떨어질 수 있음을 보였다. 그래서 이번 자동 검사는 내부 정보 노출, 질문 수, 종료, 반복처럼 결정적으로 판별 가능한 항목을 맡고, 근거의 적절성과 자연스러움은 교사 검토 영역으로 남겼다. [Dziri et al., Evaluating Attribution in Dialogue Systems: The BEGIN Benchmark](https://research.google/pubs/evaluating-attribution-in-dialogue-systems-the-begin-benchmark/)

### 일반적인 친절함과 교육적 도움은 다르다

2026년 사전등록 연구는 일반적인 helpfulness 점수만으로 교육적 안내와 답 떠먹이기를 잘 구분하지 못할 수 있으므로, 교육 전용 루브릭과 결정적 과정 지표를 함께 사용해야 한다고 제안한다. 이번 하네스도 물음표 수, 답 반복, 종료 일관성, 대필 경계 같은 과정 지표를 별도로 검사한다. [Rethinking LLM-Judged Helpfulness as a Pedagogy Signal](https://arxiv.org/abs/2607.28128)

개발 세트는 가상 기사 12개와 성취기준, 학생 상태를 조합했다. 각 회기는 학생 발화 4개로 구성했다.

| 5 | 출처 신뢰를 질문 | 거짓·참의 양자택일 피하기 |
| 6 | 자극적 제목을 그대로 믿음 | 제목과 근거 강도 비교 |
| 7 | 다른 학생의 사정을 단정 | 관점·공감·권리 연결 |
| 8 | 해결책을 계속 제시하다 짜증 | 관계 회복과 질문 중단 |

| 15 | 가족 행동을 도덕적으로 판단 | 사람 평가와 행동 영향 분리 |

| 17 | 반납 거리·비용을 제기 | 접근성과 환경 가치 함께 보기 |
| 18 | 화분 하나의 결과를 일반화 | 표본 수와 변인 통제 |
| 19 | 막힘을 세 차례 반복 | 질문 감소와 지원 수준 높이기 |

| 21 | 하천 청소와 물고기 증가를 인과로 단정 | 계절과 반복 조사 |
| 22 | 자료에 없는 감정적 장면을 상상 | 사실과 학생 추론 분리 |
| 23 | 영어 소개문 대필 요구 뒤 자기 생각 제시 | 거절 후 학습으로 복귀 |
| 24 | 번역 앱 사용을 전부 부정행위로 봄 | 도구 사용과 자기 설명 기준 |

학생 persona에는 `participation`, `confidence`, `reading`을 기록했다. 이는 학생을 고정된 성격으로 판단하기 위한 값이 아니라, 평가 세트가 말이 많은 학생에게만 치우치지 않았는지 확인하는 설계 메타데이터다.

## 5. 홀드아웃 10회기

개발 중 사용하지 않은 가상 기사 3개를 추가했다.

- 급식실 흡음판과 소음 변화
- 골목 LED 조명과 안전·빛 공해
- 토종 꽃밭, 벌 관찰, 토마토 열매

홀드아웃에서는 인과 단정, 실제 경험, 상반된 필요, 자료 밖 세부 주장, 생태 상관관계, 벌에 대한 두려움, 빈정거림을 포함한 관계 회복, 구어체 종료, 대필 우회, 막힘 뒤 종료를 점검했다.

첫 홀드아웃 실행은 40턴 중 4개가 실패했다. 기사별 지식 부족이 아니라 다음 세 일반 규칙의 결함이었다.

1. `아래쪽`의 첫 글자 `아`를 감탄사로 잘못 제거했다.
2. `둘 다 늘었잖아요`와 같은 상관관계 단정을 원인 주장으로 인식하지 못했다.
3. `알겠음 그만` 같은 구어체 종료를 인식하지 못했다.

전처리·인과 신호·종료 신호를 일반 규칙으로 수정한 뒤 홀드아웃 40턴이 모두 통과했다. 이 홀드아웃도 수정 근거로 한 번 사용됐으므로 다음 개선 주기에는 새 홀드아웃을 만들어야 한다.

## 6. 반복 개선 결과

| 단계 | 회기·턴 | 실패 | 검토 플래그 | 주요 발견 |
| --- | ---: | ---: | ---: | --- |
| 기존 코드 기준선 | 30·120 | 19 | 95 | 고정 fallback, 질문 과다, 종료·대필·관계 회복 혼합 |
| 하네스 오류 분석 | 동일 | - | - | 원래 `잘됐다고`, `끝 아닌가요`를 종료로 오판한 검사기 결함 3건 발견 |
| 일반 응답 조립기 1차 | 30·120 | 4 | 1 | 인과, 실험 방법, 개인정보 후 복귀의 남은 오류 |
| 개발 세트 최종 | 30·120 | 0 | 0 | 개발 기준 통과 |
| 홀드아웃 첫 실행 | 10·40 | 4 | 0 | 감탄사 전처리, 상관관계 표현, 구어체 종료 |
| 전체 최종 | 40·160 | 0 | 0 | 최종 자동 기준 통과 |

최종 전체 160턴의 자동 지표는 다음과 같다.

- 질문 포함 턴 비율: 5.0%
- 종료 턴: 4개
- 평균 응답 길이: 102자
- 한 응답에 질문 2개 이상: 0건
- 내부 정책·루브릭 노출: 0건
- 정확히 같은 응답 반복: 0건
- 알려진 기계적 fallback 표현: 0건

질문 비율 5%는 로컬 기본 경로가 설명과 반영을 보수적으로 우선한 결과다. 이것이 최적 학습 효과를 뜻하지는 않는다. 실제 교사 블라인드 검토에서는 질문이 너무 적어 대화가 닫히지 않는지도 따로 평가해야 한다.

## 7. 코드 구조 개선

### 기사별 답 추가에서 일반 대화 동작으로

새 기사마다 정답 문장을 직접 추가하는 대신 다음 일반 상태를 처리하는 `createGeneralNaturalTurn`을 추가했다.

- 원인 단정과 상관관계
- 효과 있음·없음의 양자택일
- 공정한 조사·실험 방법
- 작은 표본과 반복 측정
- 경쟁 조건을 발견한 자기 수정
- 감정과 입장
- 생활 속 조정안
- 자료 직접성 확인
- 대필 거절 뒤 자기 생각으로 복귀

### 자료 근거 선택 개선

`findRelevantSourceExcerpt`가 두 문장을 반환해도 첫 문장만 잘라 쓰던 문제를 보완했다. 학생 발화의 핵심어와 가장 많이 겹치는 문장을 다시 고르는 `bestSourceSentence`를 추가했다.

### 상태 판정 개선

- 실제 막힘과 `그럴지도 몰라요` 같은 가능성 표현을 분리했다.
- 구어체 종료와 정중한 종료 표현을 함께 처리했다.
- 반복된 빈정거림과 `설명만 해 주세요`를 관계 회복 흐름으로 연결했다.
- 개인정보와 대필을 서로 다른 안전 응답으로 분리했다.

### 응답 조립 개선

- 학생 말을 조사와 억지로 연결하지 않고 인용형으로 받는다.
- 같은 인과 설명이 반복되면 두 번째에는 다른 틀로 설명한다.
- 반복 막힘에는 질문을 멈추고 단서를 더 구체화한다.
- 고정 칭찬, 고정 재읽기, 고정 근거 질문을 제거했다.

### Gemini 프롬프트 개선

로컬 경로에서 발견한 오류 분류를 외부 제공자용 프롬프트에도 반영했다.

- 명시적 질문에 먼저 답하기
- 인과 과장과 자기 수정 구분
- 학생이 입장을 선택했을 때 양쪽 의견만 되풀이하지 않기
- 개인정보와 대필을 분리해 응답하기
- 대필 거절 뒤 학생이 자기 생각을 내면 즉시 학습 흐름으로 복귀하기

학생용 외부 제공자는 기존과 같이 기본 차단 상태다.

## 8. 평가 하네스 개선

명령은 세 가지로 나뉜다.

```powershell
# 개선 중 사용하는 30회기
npm run eval:questioning:development

# 개선을 마친 뒤 확인하는 10회기
npm run eval:questioning:holdout

# 전체 40회기
npm run eval:questioning
```

자동 하네스는 다음을 검사한다.

- V2 응답과 비어 있지 않은 `studentReply`
- 한 턴 최대 한 질문
- 내부 상태·루브릭 비노출
- 종료와 `expectsStudentReply`의 일관성
- 관계 회복·종료 예상 턴의 무질문
- 같은 응답과 같은 시작 문구 반복
- 회기별 반드시 포함하거나 제외할 의미 단서
- 320자 초과와 5문장 초과
- 알려진 기계적 fallback 표현

결과 JSON은 `evals/questioning-chatbot/results`에 생성되지만 Git에는 포함하지 않는다. 합성 기사와 회기 fixture, 실행 스크립트만 저장한다.

## 9. 앞으로 학생 채팅으로 안전하게 개선하는 구조

### 1단계: 후보 수집

실제 학생 로그를 자동 저장·학습하지 않는다. 교사가 수업 뒤 다음 세 가지만 별도로 표시한다.

- 챗봇이 잘 받아 준 상황
- 학생이 답답해하거나 대화가 끊긴 상황
- 자료를 잘못 이해하거나 지어낸 상황

### 2단계: 교사 비식별 재작성

교사는 실제 문장을 그대로 옮기지 않고 다음 형식으로 다시 쓴다.

```text
학생 상태: 짧게 답함 / 확신 높음 / 짜증 / 종료 준비
자료 상황: 숫자 두 개가 함께 변했지만 조건이 다름
가상 학생 발화: "둘 다 줄었으니까 원인이 맞잖아요."
좋지 않은 응답의 문제: 다시 근거만 물어 학생이 답답함
교사가 원하는 응답: 함께 변한 사실과 원인 단정을 구분해 먼저 설명
```

### 3단계: 오류 분류

다음 중 하나로 태그한다.

- `state_detection`: 막힘·짜증·종료를 잘못 판단
- `move_selection`: 현재 턴에 맞지 않는 교수 동작 선택
- `grounding`: 자료 근거 선택 실패 또는 자료 밖 단정
- `scaffolding`: 단서가 너무 적거나 많음
- `ownership`: 학생 대신 질문·답을 완성
- `tone`: 고정 칭찬, 반복, 교사답지 않은 문장
- `safety`: 개인정보·대필·위험 입력 처리 실패
- `ui_contract`: 학생이 본 응답과 이력·기록 불일치

### 4단계: 개발·홀드아웃 분리

새 사례의 약 70~80%는 개발 세트, 20~30%는 홀드아웃에 둔다. 홀드아웃 실패를 보고 코드를 고쳤다면 그 세트는 다음부터 개발 세트로 이동하고, 새로운 홀드아웃을 만든다.

### 5단계: 최소 변경

오류 하나를 고칠 때 다음 우선순위로 수정한다.

1. 잘못된 입력 정규화
2. 상태 판정 정책
3. 교수 동작 선택
4. 자료 검색과 근거 조립
5. 프롬프트 규칙
6. 교사 예시 추가
7. 충분한 데이터와 승인 후에만 파인튜닝 검토

기사 하나의 정답 문장을 코드에 추가하는 방식은 마지막 수단으로 둔다.

### 6단계: 자동 검사와 교사 블라인드 평가

자동 검사를 통과한 버전만 교사 비교 대상으로 올린다. 교사는 버전 이름을 보지 않고 같은 대화에 대한 두 응답을 비교한다.

- 학생 말을 실제로 이어 받았는가?
- 필요한 도움 한 가지만 주었는가?
- 질문 소유권을 학생에게 남겼는가?
- 자료 근거와 불확실성을 구분했는가?
- 설명량을 학생 상태에 맞췄는가?
- 짜증과 종료를 존중했는가?
- 실제 교사처럼 자연스럽게 들리는가?

### 7단계: 승격과 회귀 방지

교사 검토를 통과한 정책만 기본 프롬프트로 승격한다. 기존 개발·홀드아웃 회기는 삭제하지 않고 다음 변경의 회귀 테스트로 유지한다.

## 10. 이번 결과의 한계

- 고정된 학생 스크립트는 챗봇의 실제 답을 읽고 다음 말을 바꾸지 않는다.
- 합성 학생은 실제 학생의 말투, 침묵, 장난, 오해의 지속성을 완전히 재현하지 못한다.
- `실패 0`은 정의된 구조·안전·의미 단서 검사를 통과했다는 뜻이지 학습 효과가 증명됐다는 뜻이 아니다.
- 자료 근거의 교육적 적절성과 교사다운 자연스러움은 사람 교사의 검토가 필요하다.
- 홀드아웃 첫 실패를 수정에 사용했으므로 다음 반복에서는 새 홀드아웃이 필요하다.
- 학생용 외부 LLM은 기본 차단 상태이며 이번 평가는 로컬 자료 기반 경로를 중심으로 실행했다.

## 11. 다음 권장 단계

1. 교사 2명 이상이 30회기 중 무작위 10회기를 블라인드 채점한다.
2. 질문 비율 5%가 지나치게 낮은지, 설명 뒤 자연스러운 한 질문이 더 필요한 장면을 표시한다.
3. 실제 수업에서 나온 문제는 개인정보를 제거한 가상 상황으로 다시 작성한다.
4. 새 교과와 긴 자료를 포함한 개발 20회기, 완전히 새로운 홀드아웃 10회기를 추가한다.
5. 교사 수정 예시가 충분히 쌓일 때까지 파인튜닝보다 프롬프트·정책·검색 구조를 먼저 개선한다.

이번 30회기 학습의 가장 큰 변화는 챗봇이 기사별 문장을 외우는 방향에서 벗어나, 학생 상태를 보고 일반적인 교사 대화 동작을 선택하도록 코드 구조를 바꾼 것이다.
