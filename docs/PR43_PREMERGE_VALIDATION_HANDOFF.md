## 머지 전 코드 차단 문제

### 1. 판단 유보가 0점으로 바뀔 수 있음

`generateAiEvaluation`에서 AI 응답에 특정 기준이 없으면 점수를 0으로 정규화하고, 근거를 “AI 평가 근거가 비어 있습니다.”로 저장한다. 이는 원문 누락·근거 부족을 낮은 점수가 아닌 판단 유보로 처리한다는 PR 원칙과 충돌한다.

필요한 수정:

- 평가 상태를 `completed | review_required | deferred | error` 등으로 분리
- 기준별 판단 유보 상태와 사유 저장
- 판단 유보 기준을 총점 0으로 계산하지 않기
- AI 출력에 누락 기준이 있으면 저장을 중단하거나 검토 대상으로 격리

### 2. 재채점 이력이 덮어써질 수 있음

AI 생성과 교사 저장이 모두 `comment_id, evaluator_id` 기준으로 `upsert`한다. 같은 교사가 다시 생성하면 이전 AI 점수, 피드백, 실행 ID, 교사 검토 결과가 덮어써질 수 있다.

권장 수정:

- AI 실행마다 새 평가 행 생성
- `previous_evaluation_id` 또는 별도 실행 이력 테이블 추가
- AI 원본과 교사 검토 결과 분리
- 현재 채택된 평가를 별도 상태 또는 참조로 표시
- 재채점은 명시적 사용자 동작으로만 허용

### 3. 교사 평가와 AI 평가가 같은 행을 사용함

수동 평가와 AI 평가 모두 로그인 사용자의 `user.id`를 `evaluator_id`로 사용한다. AI 재생성이 교사가 수정·확정한 내용을 덮어쓰지 않도록 구조를 분리해야 한다.

권장안:

- `evaluation_type: ai | teacher` 추가, 또는
- `ai_evaluations`와 `teacher_reviews` 분리

학교 평가의 감사 가능성을 고려하면 별도 테이블 분리가 가장 안전하다.

### 4. 기사·지문 원문이 AI 요청에 포함되지 않음

현재 AI 요청에는 학생 댓글, 루브릭, 성취기준, 평가 목표가 포함되지만 기사·지문 원문은 포함되지 않는다. 따라서 기사 이해, 사실 정확성, 기사 근거 활용 영역을 신뢰성 있게 채점할 수 없다.

필요한 수정:

- `assessment-spec-v1`에 기사·지문 원문 또는 안전한 원문 참조 추가
- 채점 시 원문과 학생 결과물을 함께 전달
- 원문이 없으면 해당 기준을 반드시 판단 유보
- 원문 부재를 낮은 점수로 변환하지 않기

### 5. Notion 쓰기 기능이 없음

평가 명세에 다음 속성명은 저장하지만 Notion 페이지를 갱신하는 API 호출은 없다.

- 학생 속성
- 결과물 속성
- 피드백 속성

이번 PR에 Notion 쓰기를 포함한다면 구현과 시험이 필요하다. 포함하지 않는다면 PR 설명과 UI에서 “속성 매핑 저장만 지원하며 실제 쓰기는 미지원”이라고 명시한다.

AI 전용 권장 속성:

- `AI 참고 점수`
- `AI 직접 근거`
- `AI 피드백 초안`
- `AI 피드포워드`
- `AI 분석 상태`
- `AI 실행 ID`
- `AI 루브릭 버전`
- `교사 검토 결과`

기본값으로 `교사 피드백`에 AI 결과를 쓰지 않는다.

### 6. 피드백·피드포워드 품질 규칙이 프롬프트에 부족함

스킬 문서의 원칙이 실제 앱 시스템 프롬프트에 충분히 반영되지 않았다.

프롬프트와 출력 검증에 포함할 것:

- 학생 원문에서 확인한 구체적인 강점
- 보완점 한 가지
- 다음 활동에서 실행할 행동 한 가지
- 다음 결과물에서 확인할 증거 한 가지
- 찬반 입장과 글 길이만으로 점수화하지 않기
- 직접 근거는 학생 원문에서 추출
- 원문에 없는 사실·성장·태도를 만들지 않기

### 7. 부분 저장 가능성

평가 행 저장 후 `evaluation_scores` 저장이 실패하면 평가 본행만 남을 수 있다.

필요한 수정:

- Supabase RPC 또는 데이터베이스 함수로 평가와 기준별 점수를 트랜잭션 처리
- 실패 시 전체 롤백
- 오류 행만 격리하고 사용자에게 구체적 사유 표시
