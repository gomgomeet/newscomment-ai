# 질문하기 수업 HTML 보드형 챗봇 PRD

## 1. 목적

교사가 성취기준을 고르고, 학생 평가 루브릭을 확인한 뒤, 수업 자료 이미지를 넣어 자료 범위 안에서만 작동하는 질문 도우미 챗봇을 준비하는 보드형 도구를 만든다.

이 챗봇은 학생이 한 질문·대답·생각을 먼저 구체적으로 받아 주고 수업 자료와 연결해 대화한다. 질문 종류나 분석 결과를 학생에게 설명하지 않으며, 짧고 자연스러운 후속 질문으로 학생이 스스로 더 분명하고 깊은 질문을 만들도록 돕는다. 활동지 정답 전체 작성이나 수행평가 대필은 하지 않는다.

교사용 보드의 최상단에는 Gemini API 연결 영역을 둔다. Google AI Studio에서 발급한 Gemini API 키를 브라우저에 저장하면 이미지 분석과 학생 챗봇 응답에 사용하고, 키가 없으면 서버 기본 설정 또는 로컬 예비 모드로 사용할 수 있게 한다.

구현은 두 개의 HTML 화면으로 나눈다.

- 교사용 보드: `/questioning-board`
- 학생용 질문 도우미 챗봇: `/questioning-chatbot`
- 기본 성취기준 자료: `2022 개정 교육과정 및 성취기준 분석 — 질문하기 수업·챗봇 활용`

## 2. 핵심 사용자

| 사용자 | 사용 목적 |
| --- | --- |
| 교사 | 성취기준 선택, 평가 루브릭 확인, 수업 자료 입력, 챗봇 제작 PRD 준비 |
| 학생 | 수업 자료에 대한 질문·대답·생각을 나누며 새로운 궁금증으로 대화 이어 가기 |
| 교사/실습생 | 학생 질문 유형, 대화 내용, 개선 제안을 평가·피드백 자료로 활용 |

## 3. 주요 흐름

1. 교사가 학년·교과·단원을 적고 성취기준을 선택하거나 직접 입력한다.
2. 보드는 성취기준을 핵심 성취, 내용 요소, 수행 행동, 평가 요소, 학생 산출물로 분석한다.
3. 분석 결과를 바탕으로 선택한 성취기준에 맞는 0~5점 평가 루브릭을 만든다.
4. 교사가 질문 자료 이미지를 업로드하거나 학생에게 보여 줄 전체 텍스트를 직접 입력한다.
5. AI는 이미지의 전체 텍스트를 원래 순서와 문단 구조대로 추출하고, 내부 판단용 요약·핵심 개념·질문 씨앗·오개념 가능성을 별도로 정리한다.
6. 교사용 보드는 학생용 챗봇에 들어갈 제작 PRD와 설정을 생성한다.
7. 학생이 `채팅 시작`을 누르면 챗봇이 먼저 인사하고 질문 자료에서 눈에 들어온 내용이나 궁금한 점을 묻는다.
8. 학생용 챗봇은 교사용 보드의 질문 자료 전체 텍스트를 요약하거나 생략하지 않고 보여 주며, 학생의 질문·대답·생각을 먼저 받아 주고 자료와 연결해 응답한다.
9. 챗봇은 자연스러운 후속 질문 하나로 대화를 잇고, 학생이 질문 종류를 의식하지 않아도 더 분명하고 깊은 궁금증으로 나아가게 한다. 질문 분류와 루브릭 분석은 교사용 내부 정보로만 처리한다.
10. 교사는 학생이름, 성취기준·자료 연결, 자료 근거 확인, 질문 유형 확장, 질문 다시 쓰기·성찰, 총점, 점수 근거, 질문모음, 챗봇 답변모음, 세특용 피드백을 평가 기록으로 정리한다.

## 3-1. 최종 운영 모델

연수와 실제 수업에서 목표로 삼을 운영 모델은 다음과 같다.

1. 교사가 교사용 대시보드에서 자신의 Gemini API 키를 등록한다.
2. 교사가 성취기준, 질문 자료, 챗봇 역할, 평가 루브릭을 준비한다.
3. 시스템이 해당 수업용 학생 접속 링크를 만든다.
4. 학생은 링크로 접속해 질문 챗봇과 대화한다.
5. 학생 화면에는 교사의 API 키가 절대 노출되지 않는다.
6. 학생 질문, 챗봇 답변, 질문 다시 쓰기, 성찰 내용, 내부 분류 결과가 서버 DB에 저장된다.
7. 교사는 대시보드에서 학생별 결과물을 확인하고 평가 기록과 세특용 피드백으로 정리한다.

현재 구현은 교사용 보드와 학생용 챗봇이 같은 브라우저의 `localStorage`로 연결되는 기본형이다. 이것은 교사 실습, 시연, 단일 PC 운영에는 적합하지만, 학생 각자 기기에서 접속하고 결과물이 교사 대시보드로 모이는 수업 운영에는 서버 저장 구조가 추가로 필요하다.

## 4. 기능 요구사항

| 영역 | 요구사항 |
| --- | --- |
| 성취기준 선택 | Notion 기본 자료에서 선별한 2022 개정 국어·사회 성취기준과 직접 입력 모드를 제공한다. |
| 생성형 AI API 연결 | Gemini API 키와 모델을 브라우저 localStorage에 저장하고, 이미지 분석과 학생 챗봇 응답 요청에만 사용한다. |
| 교사별 API 키 운영 | 실제 배포형에서는 교사별 Gemini API 키를 학생 브라우저에 보내지 않고 서버에서만 사용한다. 키는 암호화 저장하거나, 최소 구현 단계에서는 교사 세션과 연결된 서버 환경·비밀 저장소에 둔다. |
| 성취기준 분석 | 성취기준 문장을 핵심 성취, 내용 요소, 수행 행동, 평가 요소, 학생 산출물로 정리한다. |
| 루브릭 제작 | 성취기준을 평가 가능한 행동과 산출물로 분석해 성취기준·자료 연결, 자료 근거 확인, 질문 유형 확장, 질문 다시 쓰기·성찰을 0~5점으로 제시한다. |
| 루브릭 토글 | 교사용 보드에서는 전체 루브릭을 하나의 토글로 펼쳐 확인한다. |
| 이미지 자료 입력 | 교사가 이미지를 업로드하고 미리 볼 수 있다. |
| AI 자료 분석 | Gemini API 키가 있으면 이미지의 전체 텍스트를 요약 없이 추출한다. API 키가 없으면 교사가 전체 내용을 직접 입력해 사용할 수 있다. |
| 챗봇 제작 PRD | 교사용 보드의 4번 영역에서 학생용 챗봇에 반영할 수업 정보, 지식베이스, 루브릭, 기록 필드, 안전 규칙을 정리한다. |
| 챗봇 동작 편집 | 교사가 HTML 보드에서 교사용 내부 판별 표현, 범위 밖 응답, 짧거나 막연한 발화 이어가기, 추가 지시를 수정하고 학생용 챗봇에 적용한다. |
| 학생용 질문 챗봇 | 교사용 보드에서 연결한 질문 자료 전체 내용을 그대로 보여 주고 학생의 질문·대답·생각과 대화한다. 학생 화면에는 평가 기준, 질문 분석, 별도 활동 기록 작성란을 두지 않는다. |
| 채팅 시작 | 질문 대화 상단의 버튼을 누르면 챗봇이 먼저 인사하고 첫 질문을 건넨 뒤 입력창을 활성화한다. |
| 상호작용 우선 응답 | 학생이 한 말을 먼저 구체적으로 받아 준 뒤, 최근 대화와 연결되는 후속 질문 하나를 제시한다. |
| 질문 분류 | 사실 질문, 추론 질문, 적용 질문, 확장 질문, 성찰 질문, 범위 밖 질문, 안전 확인으로 분류하되 교사용 내부 평가 정보로만 사용한다. |
| 평가 기록 | 학생이름, 성취기준·자료 연결, 자료 근거 확인, 질문 유형 확장, 질문 다시 쓰기·성찰, 총점, 점수 근거, 질문모음, 챗봇 답변모음, 세특용 피드백을 기록한다. |
| 학생 결과 수집 | 학생 접속 링크, 학생 별칭 또는 번호, 대화 기록, 질문 개선 과정, 챗봇 답변 모음, 교사용 내부 평가 데이터를 교사 대시보드로 모은다. |
| 안전장치 | 개인정보, 정답 대필, 자료 밖 질문, 원문 전체 복사 요청을 제한한다. |

## 5. 성취기준 분석 구조

성취기준은 바로 점수표로 바꾸지 않고, 먼저 평가 가능한 언어로 풀어 쓴다.

기본 성취기준 선택지는 Notion 페이지 `2022 개정 교육과정 및 성취기준 분석 — 질문하기 수업·챗봇 활용`의 초3-4, 초5-6, 중1-3, 고등학교 국어·사회 성취기준을 바탕으로 구성한다.

| 분석 항목 | 내용 |
| --- | --- |
| 핵심 성취 | 이 수업에서 학생이 최종적으로 보여야 할 수행 |
| 내용 요소 | 학생 질문과 답이 다루어야 할 자료 내용 |
| 수행 행동 | 파악하기, 설명하기, 비교하기, 적용하기, 성찰하기 등 관찰 가능한 행동 |
| 평가 요소 | 루브릭 항목으로 바꿀 수 있는 판단 기준 |
| 학생 산출물 | 질문모음, 근거 확인 내용, 챗봇 답변모음, 질문을 다시 쓰고 바꾼 과정 등 평가할 증거 |

## 6. 평가 루브릭 구조

점수만 제시하지 않고, 교사가 실제 산출물에서 볼 수 있는 관찰 증거와 다음 피드백 방향을 함께 제공한다.

| 항목 | 관찰 증거 | 배점 |
| --- | --- | --- |
| 성취기준·자료 연결 | 첫 질문, 근거 표시, 답 확인 메모에서 성취기준의 핵심 행동이 드러나는가 | 0~5점 |
| 자료 근거 확인 | 챗봇 답을 자료 속 문장·장면·표로 다시 확인했는가 | 0~5점 |
| 질문 유형 확장 | 사실 질문에서 추론·적용·성찰 질문으로 사고가 확장되는가 | 0~5점 |
| 질문 다시 쓰기·성찰 | 처음 질문을 다시 쓰고 바꾼 이유를 설명하는가 | 0~5점 |

## 7. 챗봇 응답 규칙

1. 학생 발화가 질문이면 질문 자료의 구체적인 사실과 표현을 근거로 2-4문장으로 짧게 답한다.
2. 학생 발화가 챗봇의 후속 질문에 대한 대답이나 생각이면 그 내용을 먼저 구체적으로 받아 주고 앞선 대화와 연결한다.
3. 응답 뒤에는 학생이 생각을 더 말하거나 새로운 궁금증을 만들 수 있는 짧고 자연스러운 후속 질문을 정확히 하나만 제시한다.
4. 최근 대화를 함께 참고해 같은 설명이나 후속 질문을 기계적으로 반복하지 않는다.
5. 답변과 후속 질문에서는 사실·추론·적용·확장·성찰 같은 질문 유형 이름이나 질문 분석 결과를 말하지 않는다.
6. 질문 분류, 자료 근거 분석, 질문 개선 제안, 루브릭 점수는 교사용 내부 데이터로만 생성한다.
7. 학생 화면에는 교사용 보드의 질문 자료 전체 텍스트를 요약하거나 생략하지 않고 표시하며, 챗봇은 그 전체 내용·핵심 개념·교사 메모 안에서 답한다.
8. 자료에는 없지만 수업 내용과 직접 관련 있는 질문은 `확장 질문`으로 분류한다.
9. 확장 질문은 수업 내용과의 연결을 밝히고, 실시간 검색이나 추가 자료가 없으면 출처를 지어내지 않은 채 확인할 검색어·출처 유형·점검 질문을 제안한다.
10. 수업 내용과 상관없는 질문에는 “수업 내용과 관련된 질문에 대해서만 응답할 수 있어요.”라고 답하고 자료로 돌아오는 후속 질문을 건넨다.
11. 학생 발화가 짧거나 막연해도 가능한 의미를 먼저 받아 준 뒤 후속 질문으로 생각을 구체화하도록 돕는다.
12. 이름, 연락처, 사진 속 학생 식별 정보, 상담 정보 입력은 금지한다.
13. 활동지 정답 전체 작성이나 수행평가 대필은 거절하고 사고 단계를 안내한다.

## 8. 테스트 케이스

| 테스트 | 입력 예시 | 기대 동작 |
| --- | --- | --- |
| 사실 질문 | 자료에서 확인할 수 있는 문제는 무엇인가요? | 자료에서 직접 답한 뒤 새롭게 궁금해진 점을 자연스럽게 묻는다. 질문 유형 이름은 말하지 않는다. |
| 학생의 대답 | 게시판에서 확인할 수 있어요. | 학생이 말한 내용을 먼저 받아 주고 자료와 연결한 뒤 생각을 한 단계 이어 가는 질문을 한다. |
| 추론 질문 | 왜 이런 일이 생겼을까요? | 단서 기반으로 직접 설명한 뒤 학생 생각을 자료 장면과 연결해 말하게 한다. |
| 적용 질문 | 우리 반에서는 어떻게 해결할 수 있나요? | 적용 방법을 답한 뒤 학생이 먼저 할 행동을 묻는다. |
| 확장 질문 | 자료에는 없지만 비슷한 다른 사례가 있나요? | 수업 내용과 연결됨을 밝히고 추가 리서치·출처 확인이 필요함을 안내한다. |
| 성찰 질문 | 내 질문은 더 좋아질 수 있나요? | 질문의 명확성, 자료 연결, 다음 질문을 점검한다. |
| 범위 밖 질문 | 오늘 급식은 뭐예요? | 자료 밖 질문임을 알리고 수업 질문으로 전환한다. |
| 개인정보 | 제 이름과 전화번호는... | 개인정보 입력 금지를 안내한다. |
| 정답 대필 | 활동지 답을 다 써 주세요. | 대필을 거절하고 생각할 순서를 안내한다. |

## 9. 구현 메모

- 교사용 보드 경로: `/questioning-board`
- 학생용 챗봇 경로: `/questioning-chatbot`
- API 경로: `/api/questioning-board/analyze-image`, `/api/questioning-board/chat`
- Gemini 모델: `GEMINI_QUESTIONING_MODEL`, 없으면 `gemini-2.5-flash` 사용
- 서버 기본 Gemini 키: `GEMINI_API_KEY`
- 교사용 보드에 입력한 Gemini API 키는 브라우저 `localStorage`에만 저장하고 코드, PRD, 엑셀 파일에는 포함하지 않는다.
- 이미지와 대화 내용은 기본적으로 저장하지 않는다.
- 교사용 보드와 학생용 챗봇은 같은 브라우저의 `localStorage` 설정으로 연결한다.
- 교사용 보드에서 적용한 챗봇 동작 설정은 열려 있는 학생용 챗봇 탭에도 즉시 갱신한다.
- 학생용 챗봇은 최근 대화 8개를 API에 함께 보내 앞선 답과 자연스럽게 이어서 응답한다.
- 로컬 예비 분류와 Gemini API 응답은 같은 교사 설정을 사용한다. 기존 저장 데이터에 동작 설정이 없으면 안전한 기본값을 자동으로 보완한다.
- 평가 기록 엑셀에는 `평가 기록`, `성취기준 분석`, `루브릭`, `평가 기록 작성 기준` 시트를 포함한다.
- API 키가 없을 때도 교사가 질문 자료 전체 내용을 직접 입력하면 로컬 직접 응답·후속 질문·분류·피드백 모드로 사용할 수 있다.

## 10. 현재 HTML 보드에서 배포형으로 확장하는 제안

현재 HTML 보드형 구현을 실제 수업 배포형으로 확장하려면 아래 순서가 적절하다.

1. **수업 세션 저장**: 교사용 보드에서 `수업 만들기`를 누르면 성취기준, 질문 자료, 루브릭, 챗봇 설정을 `questioning_sessions` 같은 서버 테이블에 저장한다.
2. **학생 링크 생성**: 저장된 수업 세션마다 `/questioning-chatbot/[sessionId]` 형태의 학생용 링크를 만든다. 학생은 이 링크만 받는다.
3. **API 키 보호**: 교사 API 키는 학생 페이지로 보내지 않는다. 학생 질문은 `/api/questioning-sessions/[sessionId]/chat`으로 보내고, 서버가 교사 키 또는 서버 기본 키로 Gemini를 호출한다.
4. **학생 식별 최소화**: 학생은 실명 대신 번호, 별칭, 모둠명 정도만 입력한다. 개인정보 입력 안내를 첫 화면에 둔다.
5. **대화 결과 저장**: 학생 질문, 챗봇 답변, 내부 질문 분류, 자료 근거, 다시 쓴 질문, 성찰 문장을 `questioning_submissions` 또는 `questioning_messages`에 저장한다.
6. **교사 대시보드 수집**: 교사용 보드 하단의 평가 기록 영역을 서버 저장 결과와 연결해 학생별 질문모음, 챗봇 답변모음, 점수 근거, 세특용 피드백을 불러오게 한다.
7. **내보내기 유지**: 현재 엑셀 다운로드 기능은 서버에 모인 학생 결과를 기준으로 내려받도록 바꾼다.

가장 작은 1차 구현은 `localStorage` 연결은 유지하되, `수업 저장`, `학생 링크`, `결과 제출` 세 기능만 추가하는 방식이다. 이후 교사 로그인, 교사별 API 키 암호화 저장, 수업별 접근 제한을 단계적으로 붙인다.
