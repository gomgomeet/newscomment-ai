# Codex GAS 챗봇 경량화 — 무엇을 지우고 무엇을 합칠 것인가 · 2026-09-05

「질문챗봇-연수-대시보드-템플릿」은 시트 17장, `TURNS` 한 장에 열 40개, `CONFIG` 키 28개, 카드 88장이다. 한 학급 한 시간 수업에 필요한 것은 그 삼분의 일이다. 무거운 이유는 세 가지다 — **같은 사실이 여러 시트에 겹쳐 적히고**, **연수에 쓰지 않는 기능(모델 두 개 라우팅·AI 카드 생성·외부 자료·합성 평가)이 시트와 열을 차지하고**, **한 턴에 AI를 두 번(분석·조립) 부른다.**

## 1. 시트 17장 → 7장

| 지금 | 처리 | 이유 |
| --- | --- | --- |
| `START_HERE` | **유지** | 안내문. 코드가 안 읽음 |
| `CONFIG` | **유지, 28 → 11개 키** | 3절 |
| `MATERIAL` | **유지** | 지문·학년·성취기준 |
| `CHUNKS` | **유지** | 검색 단위. 캡션 구간은 비활성 |
| `VOCABULARY` | **유지, 96 → 25개 이하** | 4학년 지문에 96개는 교사가 검토 못 한다. `questionPatterns` 열은 지운다 — "식생활가 뭐예요"처럼 조사가 틀린 자동 패턴이고, 실행 시 낱말 + 조사 규칙으로 만들면 된다 |
| `KNOWLEDGE` | **유지, 열 25 → 9** | 사실·개념·경계 지식이 검색의 알맹이. 그러나 `version`·`sourceHash`·`generationId`·`promptVersion`·`analysisModel`·`validationStatus`·`teacherDecision`·`approvedAt`·`updatedAt`·`explanationGradeCode`는 지운다. 상태는 `status` 하나면 된다 |
| `CARDS` | **유지, 88 → 15장 안팎** | DEF-* 70장은 `VOCABULARY`의 복사본(낱말마다 사전 답 카드) — 지운다. 어휘 답은 `VOCABULARY` 행에서 실행 시 만든다. AI-* 카드 8장은 질문→힌트 카드로 `KNOWLEDGE`와 겹친다 — 지운다. 남기는 것은 **교사가 손으로 쓴 대화 카드**(힌트 3단계·근거 확인·수정 인정·종료)뿐이다. 옛 자료 C001~C010은 어차피 비활성 |
| `BOARD` | **삭제** | 시나리오 6개는 테스트 픽스처. `runSmokeTests()` 코드 안에 두면 된다. 시트에 두면 자료를 바꿀 때마다 같이 안 바뀐다(지금 옛 자료 시나리오가 남은 이유) |
| `SESSIONS` | **삭제** | `TURNS`에서 세션별 첫·끝 시각을 세면 된다. 두 시트가 어긋날 일도 없어진다 |
| `TURNS` | **유지, 열 40 → 16** | 2절 |
| `RETRIEVAL_LOG` | **삭제 → `TURNS`에 흡수** | `query`·`retrievedIds`·`topScore`·`outcome`·`decisionReason`은 이미 `TURNS`에도 있다. 같은 턴이 두 시트에 적힌다 |
| `REVIEW_QUEUE` | **유지, 열 19 → 7** | "미답변 질문 → 교사 답 → 다음 학생부터 씀" 고리는 값지다. 다만 `candidateVocabularyIds`·`candidateKnowledgeIds`·`candidateExternalSourceIds`·`candidateCardIds`·`candidateChunkIds` 다섯 열은 `candidateIds` 하나로. 인사·잡담은 큐에 넣지 않는다 |
| `DASHBOARD` | **유지, 학생별 행으로** | 지금은 총계 12칸. 교사가 수업 중 보는 것은 "누가 몇 개 물었고 누가 아직인가"다. 2국면 열(질문 수·관련 질문 수·이해/성취기준/의견 응답)을 학생별로 |
| `READINESS` | **삭제** | 점검 8항목은 메뉴에서 실행하면 대화창으로 보여 주면 된다. 시트에 시각과 JSON을 쌓을 이유가 없다 |
| `EVALUATION_LOG` | **삭제** | 합성 자료 9케이스 결과. 평가는 저장소 `scripts/`에 두고 결과도 저장소에 남긴다. 검토 문서 2-⑦ 참조 |
| `GENERATION_LOG` | **삭제** | AI 카드 생성 이력(토큰 수·응답 ID). 카드 생성을 지우면 같이 없어진다 |
| `SOURCE_LIBRARY` | **삭제** | 비어 있다. 외부 자료(리서치) 기능은 연수 범위 밖. 저장소 웹앱도 이 기능을 **기본 꺼짐**으로 둔다 |

남는 7장: `START_HERE` `CONFIG` `MATERIAL` `CHUNKS` `VOCABULARY` `KNOWLEDGE` `CARDS` `TURNS` `REVIEW_QUEUE` `DASHBOARD` — 데이터 시트는 **7장**(안내문 제외 · `CHUNKS`와 `KNOWLEDGE`를 합치면 6장이지만 검색 단위가 달라 둔다).

## 4. 코드에서 지울 것 — 시트보다 이것이 더 무겁다

`.gs`를 못 봤으니 시트에 남은 흔적으로 판단한다.

| 기능 | 흔적 | 처리 |
| --- | --- | --- |
| **한 턴에 AI 두 번 호출** (분석 → 조립) | `aiStatus = analysis:ok\|compose:ok`, `stateConfidence`, `rewrittenQuery`, `activeConcept` | **한 번으로.** 학생 행동 분류는 규칙(정규식)으로 충분하다 — 저장소 `questioning-dialogue-policy.ts`가 그렇게 하고 49회기 회귀를 통과한다. 조립 한 번만 모델에 맡긴다. 지연이 절반, 비용이 절반 |
| 모델 두 개 라우팅 + 폴백 | `AI_ROUTING_MODE` `AI_MODEL_FAST/QUALITY` `AI_CARD_TERRA_FALLBACK`, DASHBOARD "Luna 응답 0" | **모델 하나.** Luna 응답이 0건이다 — 쓰이지 않는 코드다 |
| AI 카드 생성 파이프라인 | `GENERATION_LOG`, `AI-*` 카드, `DEF-*` 카드 70장, `validationStatus`·`teacherDecision`·`generationId`·`promptVersion` | **지운다.** 지문 분석은 `KNOWLEDGE`(지식 팩)와 `VOCABULARY` 생성 하나로 충분하다. 카드는 교사가 쓴다 |
| 외부 자료·리서치 | `SOURCE_LIBRARY`, `*ExternalSourceIds` 3열, `approvedExternalSourceCount` | **지운다.** 필요해지면 그때 |
| 검색 캐시 | `RETRIEVAL_CACHE_SECONDS` | 지운다 (3절) |
| 준비도 점검 시트 기록 | `READINESS` | 함수는 두고 시트 기록만 지운다. 결과는 대화창 |
| 합성 평가 | `EVALUATION_LOG`, `knowledge-rag-eval-v1` | 저장소로 옮긴다 |
| 승인 상태 세 겹 | `status` + `validationStatus` + `teacherDecision` + `active` + `teacherApproved` | **`status`(draft/approved) + `active` 둘만.** 다섯 개가 서로 다른 값을 가지면 어느 것이 진짜인지 코드도 사람도 모른다 |

## 5. 지우는 순서 — 깨지지 않게

시트를 먼저 지우면 그 시트를 읽는 함수가 죽는다. 순서가 중요하다.

1. **사본을 만든다.** 파일 → 사본 만들기. 원본은 그대로 둔다.
2. **`CONFIG`에서 끈다** — `AI_ROUTING_MODE`를 단일로, 카드 생성 키 삭제. 실행해서 오류가 나는 함수가 곧 지울 함수다.
3. **코드에서 참조를 지운다** — 분석 호출, 라우팅, 카드 생성, 외부 자료, 캐시, `READINESS`·`EVALUATION_LOG`·`GENERATION_LOG`·`SESSIONS`·`RETRIEVAL_LOG`·`BOARD` 쓰기. `runSmokeTests()`에 BOARD 시나리오를 옮긴다.
4. **`TURNS`·`KNOWLEDGE`·`REVIEW_QUEUE`·`CONFIG` 열을 줄인다** — 열 이름으로 읽는 코드면 안 쓰는 열을 지우기만 하면 되고, 열 번호로 읽는 코드면 이때 같이 고친다.
5. **시트 8장을 지운다** — `BOARD` `SESSIONS` `RETRIEVAL_LOG` `READINESS` `EVALUATION_LOG` `GENERATION_LOG` `SOURCE_LIBRARY`.
6. **카드·낱말을 줄인다** — DEF-*·AI-*·C001~C010 삭제, `VOCABULARY` 25개로.
7. `runSmokeTests()` → 교사 미리보기로 점검 발화 18개 → 배포.

3·4는 `.gs`가 있어야 한다. 1·2·5·6은 시트에서 바로 할 수 있지만 **3 전에 5를 하면 웹앱이 멈춘다.**

## 6. 줄이고 나서 얻는 것

| | 지금 | 뒤 |
| --- | --- | --- |
| 시트 | 17 | 7 (+안내문) |
| `TURNS` 열 | 40 | 16 |
| `CONFIG` 키 | 28 | 11 |
| 카드 | 88 | ~15 |
| 낱말 | 96 | ≤25 |
| 한 턴 AI 호출 | 2 | 1 |
| 승인 상태 열 | 5 | 2 |
| 교사가 검토할 것 | 카드 88 + 낱말 96 + 지식 16 = 200 | 카드 15 + 낱말 25 + 지식 16 = 56 |

마지막 줄이 핵심이다. 연수에서 교사가 **자기 지문으로 30분 안에 검토를 끝낼 수 있는 양**이 56이다. 200은 아무도 다 안 본다 — 그러면 옛 자료 카드가 살아남는 일(검토 문서 2-①)이 되풀이된다.

## 7. 2국면과의 관계

경량화가 2국면 이식보다 **먼저**다. `TURNS` 열이 정리돼야 `phase`·`managedKind`·`responseScore` 세 열을 어디에 둘지 분명하고, AI 호출이 한 번이어야 `[지금 할 일]`을 넣을 자리가 하나다. 순서: 경량화(반나절, 코드 있을 때) → 2국면(하루).
