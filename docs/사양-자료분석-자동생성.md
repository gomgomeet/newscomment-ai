# 사양 — 자료를 저장하면 지문 분석·낱말·주제어가 저절로 만들어지게

`gas/CONTRACT.md` 2절대로 `Code.js` · `KnowledgePack.js` · `SheetService.js` · `Teacher.html`은 **Codex 소유**다. 아래는 Claude가 재 보고 쓴 사양이며, 코드는 그대로 붙여 넣을 수 있게 적었다. 근거는 `docs/교사-입력-효율화-제안.md`와 `node scripts/check-material-rag.mjs`(PASS 6 · FAIL 0)다.

## 먼저 — 지금 무엇이 있고 무엇이 없나

`generateKnowledgePackDrafts()`가 이미 지문 분석을 만든다. 없는 것은 셋이다.

1. **자동 실행이 아니다.** 교사가 `4. 수업 자료·보충 설명 확인`에서 버튼을 눌러야 한다.
2. **프롬프트가 정작 쓸모 있는 것을 만들지 말라고 한다.** 지금 지시문에 이 줄이 있다.
   > 원문에서 바로 찾을 수 있는 사실이나 **문단별 요약을 반복 생성하지 마세요.**
   그런데 실측에서 "식품 포장재가 몇 퍼센트예요?"에 **87%로 답하게 만든 것이 바로 그 문단 요약(paragraph_summary)**이었다. 지금 프롬프트는 '보충 설명'을 만들라는 것이지 '검색해 쓸 지문 분석'을 만들라는 것이 아니다. **목적이 다르다.**
3. **낱말 뜻과 주제어는 아예 만들지 않는다.**

## ① 저장하면 지문 분석이 저절로 — `Code.js` `saveTeacherSetup()`

**잠금 밖에서 불러야 한다.** 지금 이 함수는 `lock.waitLock(20000)` 안에서 저장한다. 모델 호출은 10~30초가 걸리므로 잠금 안에서 부르면 **그동안 학생들의 대화가 멈춘다.** 그래서 잠금을 놓은 뒤에 부른다.

지금 구조는 `try { … return {…}; } finally { flushAndReleaseLock_(lock); }` 다. 반환값을 변수에 담고, `try/finally` **바깥에서** 분석을 부른 뒤 메시지만 덧붙인다.

```javascript
  // (기존 try 블록 안) return 대신 결과를 담아 둔다
    var response = {
      ok: true,
      message: archivedTurns
        ? '저장되었습니다. 지문이 바뀌어 지난 대화 ' + archivedTurns + '건을 TURNS_ARCHIVE 시트로 옮겼어요. 학생은 새로 시작합니다.'
        : '저장되었습니다. 학생 앱 새로고침부터 바로 반영됩니다.',
      // … 나머지 필드 그대로 …
    };
  } finally {
    flushAndReleaseLock_(lock);
  }

  // 잠금을 놓은 뒤에 분석한다. 키가 없거나 모델이 실패해도 저장은 이미 끝났다.
  try {
    var analysis = generateKnowledgePackDrafts(teacherAccessToken, response.materialId, false);
    var count = (analysis.items || []).length;
    if (count) {
      response.analysisCount = count;
      response.message += ' 지문 분석 초안 ' + count +
        '개를 만들었어요. 「4. 수업 자료·보충 설명 확인」에서 훑어보고 승인해 주세요.';
    }
  } catch (error) {
    response.analysisError = String(error.message || error);
    response.message += ' (지문 분석은 나중에 「4. 수업 자료·보충 설명 확인」에서 만들 수 있어요.)';
  }
  return response;
```

`forceRefresh`는 **`false`**로 준다. 지문이 그대로면 `findReusableKnowledgePack_()`이 지난 초안을 다시 쓰므로 저장할 때마다 헛돈이 나가지 않는다.

## ② 프롬프트 — `KnowledgePack.js` `makeKnowledgePackRequest_()`

`instructions` 배열에서 **이 줄을 뺀다.**

```javascript
'최대 ' + maxItems + '개의 꼭 필요한 보충 설명만 제안하세요. 원문에서 바로 찾을 수 있는 사실이나 문단별 요약을 반복 생성하지 마세요.',
```

**대신 이 세 줄을 넣는다.**

```javascript
'이 지식은 학생이 물었을 때 검색해서 답의 근거로 쓰는 자료입니다. 아이들이 실제로 물어볼 것을 기준으로 만드세요.',
'최대 ' + maxItems + '개를 만들되 이 순서로 채우세요 — 글 전체의 중심 생각 하나(overview), 숫자·비율이 나오는 문단의 요약(paragraph_summary), 아이들이 물어볼 핵심 사실(fact), 까닭이나 관계(relation), 어려운 개념(concept), 이야깃거리(discussion), 글에 없는 것(boundary).',
'제목과 본문 첫 문장에 아이들이 쓸 말을 그대로 넣으세요. 예: 제목 "몇 퍼센트인가 · 87% 식품 포장재", 본문 시작 "몇 퍼센트인지 보면, …". 검색이 제목과 본문 앞부분으로 이루어집니다.',
```

**왜 이렇게 쓰나.** 실측에서 개념 항목의 본문을 "포장재를 가볍게 만들거나…"로 시작했더니 퍼센트 질문에 그것이 끼어들어 **넣기 전보다 나쁜 답**이 나왔다. 본문을 "재사용과 리필은 …"으로 바꾸자 바로잡혔다. 제목만 밋밋하게 바꿔서는 나빠지지 않았다 — **본문 첫 문장이 검색을 끈다.**

## ③④ 낱말 뜻과 주제어 — `KnowledgePack.js`에 함수 하나

한 번의 호출로 둘 다 받는다. 낱말은 **지문에 있는 말만**, 주제어는 거꾸로 **지문에 없는 말만** 남긴다(있으면 이미 관련 판정에 들어가 있어 넣을 값어치가 없다).

```javascript
/** 자료를 저장할 때 낱말 뜻과 주제어 초안을 한 번에 만들어 VOCABULARY_LIBRARY에 넣는다. */
function generateVocabularyDrafts(teacherAccessToken, materialId) {
  assertTeacherAccess_(teacherAccessToken);
  const settings = getAISettings_(readConfig_());
  if (!settings.enabled || !getOpenAIApiKey_()) {
    throw new Error('먼저 질문 챗봇 메뉴에서 OpenAI API 키를 연결해 주세요.');
  }
  const material = getActiveMaterial_();
  if (materialId && String(material.materialId) !== String(materialId)) {
    throw new Error('현재 활성 자료가 바뀌었습니다. 교사 화면을 새로 열어 주세요.');
  }
  const policy = requireSupportedGrade_(material.gradeCode || material.grade);
  const passage = String(material.text || '');
  const value = callOpenAIJson_(makeVocabularyRequest_(material, settings)).value || {};

  const rows = [];
  const seen = {};
  const add = function (term, definition, group) {
    const key = normalizeVocabularyTerm_(term);
    if (!key || seen[key]) return;
    if (String(definition || '').trim().length < 2) return;
    seen[key] = true;
    rows.push(Object.assign(
      makeVocabularyRow_(material, term, definition, policy, 'AI 초안'),
      { wordGroup: group, status: 'approved', active: true, teacherApproved: false,
        sourceHash: material.sourceHash, version: material.version }
    ));
  };
  (value.words || []).forEach(function (item) {
    if (passage.indexOf(String(item.term || '')) < 0) return;      // 지문에 없는 말은 뜻풀이하지 않는다
    add(item.term, item.easyDefinition, String(item.wordGroup || ''));
  });
  (value.themeWords || []).forEach(function (item) {
    if (passage.indexOf(String(item.term || '')) >= 0) return;     // 지문에 있으면 주제어로 넣을 값어치가 없다
    add(item.term, item.easyDefinition, '주제어');
  });
  if (rows.length === 0) throw new Error('만들 낱말이 없습니다.');
  appendObjectsToSheet_(getSpreadsheet_().getSheetByName('VOCABULARY_LIBRARY'), rows);
  return {
    ok: true,
    wordCount: rows.filter(function (r) { return r.wordGroup !== '주제어'; }).length,
    themeCount: rows.filter(function (r) { return r.wordGroup === '주제어'; }).length
  };
}

function makeVocabularyRequest_(material, settings) {
  const entry = {
    type: 'object',
    properties: {
      term: { type: 'string' },
      easyDefinition: { type: 'string' },
      wordGroup: { type: 'string' }
    },
    required: ['term', 'easyDefinition', 'wordGroup'],
    additionalProperties: false
  };
  return {
    model: settings.model,
    reasoningEffort: settings.reasoningEffort,
    maxOutputTokens: 2000,
    schemaName: 'teacher_vocabulary_drafts',
    schema: {
      type: 'object',
      properties: {
        words: { type: 'array', maxItems: 20, items: entry },
        themeWords: { type: 'array', maxItems: 10, items: entry }
      },
      required: ['words', 'themeWords'],
      additionalProperties: false
    },
    instructions: [
      '한국어 수업용 질문 챗봇의 낱말 도우미입니다.',
      'words: 지문에 실제로 나오는 말 가운데 대상 학년이 어려워할 낱말을 최대 20개 고르고, 대상 학년보다 한 단계 쉬운 말로 한 문장 뜻을 쓰세요.',
      'themeWords: 이 글을 읽은 대상 학년 학생이 물어볼 만한 말 가운데 **지문에는 나오지 않는** 낱말을 최대 10개 고르세요. 글의 주제와 이어지는 것만 고르고, 뜻도 같은 방식으로 쓰세요.',
      '뜻에 어려운 한자어를 쓰지 말고, 낱말 자체를 뜻풀이에 되풀이하지 마세요.',
      'wordGroup은 같은 갈래끼리 묶는 짧은 이름이며 없으면 빈 문자열로 두세요.'
    ].join(' '),
    input: JSON.stringify({
      grade: material.grade,
      gradeCode: material.gradeCode,
      title: material.title,
      standard: material.standard,
      text: material.text
    })
  };
}
```

**`status: 'approved'` · `active: true`로 바로 넣되 `sourceLocation`을 `'AI 초안'`으로 둔다.** 교사 화면의 낱말 표에 `출처·확인 상태` 열이 있어 어느 것이 AI 초안인지 그 자리에서 보이고, 이상한 것은 그 표에서 고치거나 지우면 된다. 이렇게 하면 **⑥(별도 승인 화면)을 만들지 않아도 된다.** 검토 없이 학생에게 나가는 것이 마음에 걸리면 `status: 'draft'` · `active: false`로 두고 승인 화면을 따로 만든다 — 대신 `Teacher.html`에 40~60줄이 붙는다.

①과 같은 자리(잠금 밖)에서 `generateVocabularyDrafts(teacherAccessToken, response.materialId)`를 `try/catch`로 한 번 더 부르면 저장 한 번에 셋이 다 생긴다.

## ⑥ 남은 한계 — `RetrievalEngine.js`

"중심 생각이 뭐예요?" · "글쓴이가 하고 싶은 말이 뭐예요?"는 분류기가 **낱말 뜻 질문(`ask_definition`)**으로 본다. 그 경로는 `scoreKnowledgeTypeRelevance_`에서 `vocabulary` 지식만 점수를 주므로, 이 수업의 성취기준 그 자체인 `overview` 지식이 붙지 않는다.

```javascript
  if (move === 'ask_definition') {
    // 중심 생각을 묻는 것은 낱말 뜻 질문이 아니다 — overview를 함께 본다.
    if (/(중심\s*생각|주제|하고\s*싶은\s*말|글쓴이)/.test(String(dialogue.query || ''))) {
      return ['vocabulary', 'overview'].indexOf(type) >= 0 ? 5 : 0;
    }
    return type === 'vocabulary' ? 5 : 0;
  }
```

`dialogue`에 질문 원문이 없으므로 `rankEvidenceCandidates_`에서 `dialogue.query = query`를 함께 넘겨야 한다.

**주의 — 답을 그냥 건네면 안 된다.** 중심 생각 찾기 수업에서 챗봇이 중심 생각을 바로 말해 버리면 수업이 무너진다. 근거로 쓰되 힌트 단계(`hintLevel`)를 지켜 "글에서 되풀이되는 말이 무엇인지 찾아볼까요?" 쪽으로 이끄는지 반드시 확인한다. 이 한 가지는 코드보다 수업 설계 판단이라 **교사와 상의한 뒤에 넣는다.**
