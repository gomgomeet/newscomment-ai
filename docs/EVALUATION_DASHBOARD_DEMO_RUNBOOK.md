# 평가 대시보드 시연 실행서

## 1. 사용자가 먼저 할 일

시연 전에 아래 네 가지만 준비한다. Supabase 데이터 구조와 보안 정책은 이미 적용되어 있다.

1. `.env.local`의 `OPENAI_API_KEY`에 OpenAI API 키를 넣는다.
2. `.env.local`의 `NOTION_API_KEY`에 Notion Integration의 내부 통합 토큰을 넣는다.
3. 학생 결과 데이터베이스와 선택 저장용 상위 페이지를 같은 Notion Integration에 연결한다.
4. Supabase 로그인 계정을 만들고 이메일 인증을 완료한다.

토큰은 채팅이나 화면에 붙여 넣지 않는다. `.env.local`에만 저장하고 개발 서버를 다시 시작한다.

학교 PDF는 실제 학생 정보가 없는 파일만 사용한다. 별도 파일이 없으면 `/dashboard/forms`의 `시연용 샘플 PDF 받기`를 사용한다.

## 2. Supabase에서 한 번만 확인할 일

Supabase Dashboard의 **Authentication → Sign In / User Security**에서 유출 비밀번호 차단(Leaked password protection)을 켠다. 평가 대시보드 테이블, 비공개 Storage, RLS 정책, 외래키 인덱스는 이미 적용되어 있다.

## 3. 10분 시연 순서

### 0:00~1:00 · 연결 상태 확인

1. 로그인한다.
2. `설정`에서 Supabase·OpenAI·Notion 연결 상태를 확인한다.
3. `대시보드`에서 전체 진행 단계와 남은 작업을 확인한다.

### 1:00~3:00 · 평가 준비 프렙

1. `수업활동`에서 시연할 활동을 연다.
2. `평가 준비 프렙`을 열어 학년·교과·수업 맥락을 적는다.
3. 성취기준·평가 목표와 루브릭을 확인한다.
4. Notion 데이터베이스 URL, 학생 식별 필드, 결과 필드를 지정한다.
5. 안전 안내·학생 안내·샘플 평가 메모를 채운다.
6. `평가 준비 확정`을 눌러 변경 불가능한 평가 기준 버전을 만든다.

확인할 상태: 준비도 6단계가 완료되고 `활성 버전`이 표시된다.

### 3:00~4:00 · Notion 결과 읽기

1. 프렙의 `Notion 결과 미리보기`를 연다.
2. 처음 3건의 학생 식별자·결과 본문·읽기 상태를 확인한다.
3. 새 결과와 수정 결과만 가져온다.

확인할 상태: 같은 Notion 페이지가 수정되지 않았다면 중복 저장되지 않고, 수정된 페이지는 이전 근거를 남긴 새 버전으로 들어온다.

### 4:00~6:00 · 자동채점과 교사 검토

1. 수업활동에서 `미초안 전체 생성`을 누른다.
2. `교사 확인 우선` 필터로 낮은 신뢰도·근거 부족·경계 점수 결과를 먼저 본다.
3. 원결과물, AI 근거 인용, 기준별 점수, 판단 이유, 평가 포워드를 함께 확인한다.
4. 점수·피드백·다음 평가 포워드를 고치고 변경 이유를 남긴 뒤 `교사 최종 확정`을 누른다.

확인할 상태: AI 초안과 교사 확정 평가가 구분되고, 재확정할 때마다 수정 이력이 누적된다.

### 6:00~7:00 · 평가 결과

1. 활동의 `평가 결과`를 연다.
2. 제출·교사 확정 수, 취약 기준, 학생별 최종 결과를 확인한다.
3. 원 Notion 결과 링크로 근거를 다시 확인한다.

확인할 상태: 교사 확정 결과만 최종 결과로 나타난다.

### 7:00~8:30 · 성장 기록 보드(생기부)

1. `성장 기록 보드(생기부)`를 연다.
2. 학생별 점수 변화, 반복 검토 이유, 최근 평가 포워드를 확인한다.
3. 학생의 `종합 기록 만들기`를 누른다.
4. 평가 근거 타임라인과 활동 간 변화를 읽고 세특 초안을 수정한다.
5. `교사 최종 확정`을 누른다.

확인할 상태: 한 번뿐인 관찰은 반복 성장으로 단정하지 않으며, 포함된 평가 ID가 근거로 남는다.

### 8:30~10:00 · 학교 PDF와 선택 Notion 저장

1. `학교 양식 작성`을 연다.
2. 샘플 PDF 또는 학교 PDF를 업로드한다.
3. 감지된 입력 칸을 평가 데이터 키에 연결하고 글자·줄 수를 저장한다.
4. 확정된 학생 기록에서 `PDF 다운로드` 또는 `생성·보관`을 누른다.
5. 필요할 때만 성장 기록 화면에서 Integration에 공유한 상위 Notion 페이지 URL을 넣고 `Notion 새 페이지로 저장`을 누른다.

확인할 상태: PDF와 Notion 모두 교사가 확정한 기록만 내보내며, 내보내기 성공·실패가 감사 로그에 남는다.

## 4. 시연 중 빠른 복구

- OpenAI 버튼이 비활성화됨: `OPENAI_API_KEY` 저장 후 개발 서버를 다시 시작한다.
- Notion 404: 데이터베이스와 상위 페이지를 Integration에 다시 공유한다.
- Notion 결과 0건: 프렙의 학생 식별 필드·결과 필드 이름을 실제 속성명과 맞춘다.
- PDF 필드 0건: 일반 PDF이므로 `수동 영역 추가`에서 페이지·X·Y·너비·높이를 지정한다.
- PDF 문장 잘림 경고: 해당 필드의 글꼴 크기를 줄이거나 영역 높이·줄 수를 늘린다.
- 성장 기록이 비어 있음: 먼저 교사 수동 평가를 `최종 확정`한다.

## 5. 완료 판정

- 프로덕션 빌드 성공
- 로그인 화면에 브라우저 오류와 Next.js 오류 오버레이 없음
- 비로그인 사용자의 대시보드 접근이 로그인으로 이동
- 시연 샘플 PDF가 `application/pdf`로 제공됨
- 평가 대시보드 관련 Supabase RLS 보안 오류 없음
- 외래키 미인덱스 경고 없음
- 프렙 → Notion 읽기 → AI 초안 → 교사 확정 → 결과 → 성장 기록 → PDF/Notion 선택 저장 동선 연결
