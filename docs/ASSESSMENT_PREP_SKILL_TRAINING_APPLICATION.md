# 평가 준비 스킬 연수 적용안

## 목적

참가자가 프로젝트 전체나 복잡한 평가 대시보드를 배우는 것이 아니라, 자신의 Notion 수업자료를 평가 가능한 구조로 바꾸고 Claude Code 또는 Codex의 평가 준비 스킬을 이용해 실제 수업에 쓸 평가안을 완성하도록 한다.

## 연수에서의 위치

이 스킬은 연수의 최종 산출물이 아니라 **평가를 준비하는 작업 도구**다. 연수자는 스킬을 배포하고, 참가자는 자신의 자료를 넣어 다음 네 가지를 완성한다.

1. 평가 목표와 성취기준
2. 지문·결과물 기반 서술형 문항과 루브릭
3. 결과물을 받을 Notion 폼과 평가 DB 속성
4. 여러 응답을 검토할 Claude 평가 프롬프트와 피드포워드

## 두 스킬의 실행 순서

연수에서는 두 스킬을 한 묶음으로 사용한다.

```text
1번 notion-claude-assessment-prep
성취기준·수업 의도 → 문항·루브릭 → 평가 DB·노션폼 → 교사 승인

2번 notion-claude-assessment-grader
승인된 루브릭 → 결과물·기사 원문 조회 → 시험 채점 → 자동채점 기록 → 교사 검토
```

2번 스킬은 1번 스킬이 만든 평가 준비안 없이 실행하지 않는다. 첫 1~3건의 시험 채점에서 교사가 점수·근거·피드백을 확인한 뒤 나머지를 3~5건씩 자동 기록한다.

자동채점 스킬이 기록하는 영역은 AI 점수, 직접 근거, AI 평가 초안, 학생 피드백, 평가 포워드, 분석 상태다. 학생 원문, 교사 점수, 교사 판단, 교사 피드백, 교사 확인, 학생기록은 수정하지 않는다.

1번 스킬의 마지막 산출물은 `assessment-spec-v1` 평가 실행 명세다. 활동 ID, 루브릭 버전, 기준 ID, 판단 유보 조건, 실제 Notion 속성 매핑, 수정 금지 속성, 시험 채점 건수, 배치 크기, 교사 승인 상태를 포함한다. 2번 스킬은 승인된 명세만 실행한다.

2번 스킬은 자동채점 이후 교사 검토도 이어서 지원한다. 판단 유보·낮은 확신도·기준별 점수 차이·기사 연결 불완전·재채점 행을 우선 보여 주고, 교사가 유지·수정·보류를 선택하도록 한다. 학급 공통 어려움은 학생 순위가 아니라 다음 수업에서 다시 확인할 기준과 지원 활동으로 정리한다.

## 3차시 운영안

### 1차시: 평가 준비 시작하기

**핵심 질문:** 이 수업에서 학생이 무엇을 배우고, 어떤 결과물에서 그것을 확인할 것인가?

참가자는 다음 자료를 준비한다.

- 수업 자료 또는 지문 Notion 링크
- 학생 결과물·제출물 Notion 링크
- 기존 평가 DB 링크 또는 새 평가 DB를 만들 Notion 페이지 링크
- 성취기준 또는 수업 의도
- 학습자 수준과 결과물 형식

스킬에 다음 명령을 입력한다.

```text
notion-claude-assessment-prep 스킬로 이 수업의 평가를 준비해줘.
먼저 내가 제공해야 할 Notion 링크와 정보를 확인해줘.
```

완성물:

- 평가 목표 1개
- 핵심 아이디어와 핵심어
- 평가 문항 2~4개
- 문항별 평가 의도
- 평가 기준 초안

### 2차시: 평가 DB와 폼 만들기

**핵심 질문:** 학생의 배움을 확인하려면 어떤 결과물을 어떤 방식으로 받아야 하는가?

참가자는 1차시 산출물을 바탕으로 스킬에 다음을 요청한다.

```text
이 평가안을 바탕으로 평가 DB에 필요한 속성과 노션폼 질문을 설계해줘.
학생용 질문과 교사용 관찰 항목을 분리하고, 자기평가도 포함해줘.
```

평가 DB는 다음 영역으로 최소화한다.

- 학생·활동·차시·결과물 원문
- 자기평가와 교사 관찰
- 평가 기준과 참고 점수
- 직접 근거와 AI 평가 초안
- 교사 판단과 피드백
- 평가 포워드와 다음 활동

Notion Relation은 원본 추적에 필요할 때만 사용한다. Relation이 없으면 결과물 ID와 활동명으로도 평가가 가능해야 한다.

완성물:

- 평가 DB 속성표
- 학생 제출용 노션폼 질문
- 학생 자기평가 체크리스트
- 교사 관찰 입력안

### 3차시: 결과물 평가와 다음 활동 설계

**핵심 질문:** 평가 결과를 학생의 다음 행동과 다음 수업으로 어떻게 바꿀 것인가?

참가자는 같은 활동의 결과물 3~5건을 준비해 다음 프롬프트를 사용한다.

```text
같은 활동의 결과물만 학생 ID와 결과물 ID를 보존하여 평가해줘.
교사의 평가 기준을 우선 사용하고, 점수는 참고값으로만 제시해줘.
각 학생마다 직접 근거, 판단, 근거 부족, 피드백, 다음 활동의 피드포워드를 제시해줘.
```

교사는 Claude 초안을 그대로 확정하지 않고 다음 세 단계로 검토한다.

1. 원문과 직접 근거 대조
2. 판단과 참고 점수의 유지·수정·보류
3. 학생 피드백을 다음 활동의 행동과 확인할 새 증거로 변환

완성물:

- 학생별 평가 초안
- 교사 피드백
- 다음 활동의 피드포워드
- 후속 결과물에서 확인할 증거

## 실습 자료 제공 방식

연수자는 프로젝트 전체를 공유하지 않는다. 다음 중 하나만 배포한다.

- 독립형 스킬 ZIP
- Codex용 `.agents/skills/.../SKILL.md`
- Claude Code용 `.claude/skills/.../SKILL.md`

참가자는 자신의 Notion 링크를 입력한다. 학생 개인정보가 포함된 자료는 비식별화하거나 연수용 합성 자료를 사용한다.

### ZIP 설치 실습

초보 교사에게는 GitHub Fork나 Clone을 요구하지 않고 `notion-claude-assessment-prep.zip`만 제공한다. 참가자는 압축을 푼 스킬 폴더를 Codex의 `%USERPROFILE%\\.codex\\skills` 또는 Claude Code 프로젝트의 `.claude\\skills`에 복사한 뒤 도구를 다시 시작한다. 연수자는 배포 ZIP에 개인 학생 자료나 Notion 링크를 포함하지 않는다.

설치 확인 문장:

```text
notion-claude-assessment-prep 스킬을 사용해서 평가 준비를 시작해줘.
먼저 필요한 Notion 링크와 정보를 질문해줘.
```

## 연수에서 강조할 오해 방지

- 스킬은 자동 채점기가 아니라 평가 준비와 교사 판단 보조 도구다.
- 점수는 피드백보다 앞서지 않는다.
- 챗봇 활동과 NIE 기사 댓글은 서로 다른 활동 기준으로 평가한다.
- 활동을 연결하는 목적은 점수 합산이 아니라 다음 활동을 설계하는 피드포워드다.
- AI가 만든 평가 문장은 교사의 최종 판단이나 학생기록을 대신하지 않는다.
- 노션폼·공유 링크·QR이 실제로 생성되지 않았다면 생성되었다고 보고하지 않는다.

## 참가자 제출 체크리스트

- [ ] 수업자료 또는 지문 링크를 제공했다.
- [ ] 학생 결과물 링크 또는 연수용 결과물을 제공했다.
- [ ] 성취기준과 수업 의도를 입력했다.
- [ ] 평가 문항과 기준을 교사 관점에서 확인했다.
- [ ] 학생용 폼과 자기평가를 만들었다.
- [ ] 같은 활동의 결과물 3~5건을 평가했다.
- [ ] AI 초안과 원문을 대조했다.
- [ ] 학생별 피드백을 작성했다.
- [ ] 다음 활동의 피드포워드를 정했다.

## 연수 성공 기준

참가자가 Notion의 모든 기능을 설명하는 것이 목표가 아니다. 자기 수업의 자료로 평가 목표, 문항, 기준, 폼, 학생별 피드백, 다음 활동을 하나의 짧은 평가 루트로 완성하면 성공이다.
