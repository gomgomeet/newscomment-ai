# Track A — Notion 설정 기록

연수용 자료(사용 설명서·교사용 PPT)에 그대로 반영할 목적의 작업 로그입니다.
Notion 데이터베이스에 가한 변경을 **무엇을 · 왜 · 교사에게 어떻게 설명할지**로 남깁니다.

이 문서만 Korean으로 작성합니다. 나머지 저장소 문서는 영어이지만, 이 내용은 한국 교사 대상
연수 자료로 직행하기 때문입니다.

대상 데이터베이스: `💬 학생 댓글 · 생각 나누기`
(`7f88a558-0743-440a-a98b-ed759275b301`)

## 결정 사항

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 평가 척도 | **0~5**, 3영역, 총점 15 | 사용자 결정 (2026-08-21). PRD §13 미결정 항목을 확정 |

## 2026-08-21 · 스키마 정리

### 1. 영역 점수의 주체를 이름에 드러냄

| 이전 | 이후 |
| --- | --- |
| `기사 이해` | `AI 이해` |
| `생각 연결` | `AI 연결` |
| `생각 표현` | `AI 표현` |

**왜**: 이름만 봐서는 AI 점수인지 교사 점수인지 알 수 없었습니다.

**교사에게 설명할 말**: "AI가 매긴 점수와 선생님이 매긴 점수를 나란히 두려고 이름을 나눴습니다."

### 2. 교사용 영역 점수 신설

`교사 이해` · `교사 연결` · `교사 표현` (숫자, 0~5)

**왜**: 이전에는 교사 쪽에 총점 하나뿐이라 **AI가 어느 영역에서 틀렸는지 짚을 수 없었습니다.**
PRD §F5가 요구하는 AI-교사 대조가 성립하지 않았고, 연수의 핵심 메시지(AI 판단을 교사가
고친다)를 보여줄 수단이 없었습니다.

**교사에게 설명할 말**: "AI가 세 영역으로 나눠 봤으니, 선생님도 같은 세 영역으로 봐 주세요.
그래야 어디서 생각이 갈리는지 보입니다."

### 3. 총점을 손입력에서 수식으로

| 속성 | 이전 | 이후 |
| --- | --- | --- |
| `AI 총점` | 숫자 (손입력) | 수식 = AI 이해 + AI 연결 + AI 표현 |
| `교사 총점` | 숫자 (손입력) | 수식 = 교사 이해 + 교사 연결 + 교사 표현 |

수식 (빈 칸을 0으로 처리해 채점 도중에도 총점이 보이도록):

```
if(empty(prop("AI 이해")), 0, prop("AI 이해"))
  + if(empty(prop("AI 연결")), 0, prop("AI 연결"))
  + if(empty(prop("AI 표현")), 0, prop("AI 표현"))
```

**왜**: 총점은 계산 결과지 입력값이 아닙니다. 손으로 넣으면 영역 점수와 어긋납니다.

**교사에게 설명할 말**: "총점 칸은 건드리지 마세요. 세 영역만 넣으면 저절로 더해집니다."

### 4. 중복 속성 제거

- `AI 점수`(0~5) 삭제 — `AI 총점`과 중복. 전 행에 값이 없어 손실 없음.

**왜**: 3영역이 있는데 별도 총괄 점수가 또 있으면 교사가 "어느 게 진짜 점수인가"에서 멈춥니다.

## 연수 자료에 반영할 포인트

### 실습에서 교사가 직접 할 것 / 미리 만들어 둘 것

| | 연수에서 직접 | 템플릿에 미리 |
| --- | --- | --- |
| 관계(Relation) 연결 | O | |
| 롤업(Rollup) 만들기 | O | |
| 필터 뷰 만들기 | O | |
| **수식 입력** | X | O |

**수식을 타이핑시키면 안 됩니다.** 따옴표·괄호 하나 틀리면 오류가 나고, 40명 중 절반이 손을
들면 진행이 멈춥니다. 관계 → 롤업 → 필터 세 가지가 Notion 데이터베이스의 핵심 개념이고,
이 셋만 직접 해보면 충분합니다.

### 40건을 다 채점하지 않는다

교사가 40건을 전수 채점하는 시나리오는 시간상 불가능하고, 가르칠 내용도 아닙니다. 대신:

> "40건을 다 보지 마세요. **AI가 자신 없어 하는 것부터** 보세요."

`AI 확신도 = 낮음` + `교사 우선 검토` 필터가 그 트리아지 역할을 합니다. 연수에서 실제로
채점하는 건 2~3건이면 충분하고, 나머지 시간은 "왜 이것들이 검토 대상으로 올라왔는가"를
읽는 데 씁니다. PRD §3-1 "AI는 초안, 교사가 최종 판단자"를 40건 규모에서 구현하는 방법입니다.

### 짧은 글 = 낮은 점수가 아니다

샘플 두 건이 이 대비를 보여줍니다.

| 학생 | 댓글 | 길이 | 질 |
| --- | --- | --- | --- |
| S902 | "체험학습 좋아요. 많이 가면 좋겠다." | 짧음 | 기사 근거 없음 |
| S905 | "말랑이에서 유해물질이... 확인해 봐야겠다" | 짧음 | 기사 인용 + 행동 |

PRD §F3의 "짧다는 이유만으로 무조건 낮은 점수를 주지 않는다"를 설명할 때 이 두 건을
나란히 띄우면 됩니다. 글자 수는 "성의 없이 낸 사람 훑기"용 참고 지표로만 쓰고, 점수 필드와
분리해 둡니다.

### 개인정보

학생 DB의 제목은 `S001` 형식 ID로 두고 실명은 넣지 않습니다. PRD §F2 "실명 대신 수업용
학생 ID 사용을 기본값으로"에 해당하며, 이 템플릿이 다른 교사에게 복제된다는 점에서 더
중요합니다.
