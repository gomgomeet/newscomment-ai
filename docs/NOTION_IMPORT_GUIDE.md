# Notion 가져오기 안내

NewsComment AI는 Notion 데이터베이스에 모은 학생 결과물을 바로 읽어올 수 있다. Notion에서 수집한 학급 토론 기록이나 학생이 복제한 템플릿 결과물을 복사해 붙여 넣지 않고, 루브릭 평가 프로젝트로 연결하기 위한 기능이다.

Notion 데이터베이스의 한 행은 앱에서 평가 결과물 하나가 된다. 결과물은 데이터베이스 속성에 있거나 각 행의 페이지 본문에 있을 수 있다.

## 1. Notion 데이터베이스 만들기

학생 댓글 한 개가 한 행이 되도록 Notion 데이터베이스를 만든다. 간단한 구조면 충분하다.

| 속성 | 유형 | 용도 |
| --- | --- | --- |
| `이름` | 제목 또는 텍스트 | 학생 이름, 별칭, 학생 번호 |
| `댓글` | 텍스트 | 학생이 쓴 댓글 |
| `주제` | 선택 또는 텍스트 | 기사나 수업 주제, 선택 사항 |

속성 이름은 교사가 정해도 된다. 가져오기 화면에서 속성명을 직접 입력하면 되고, 대소문자와 앞뒤 공백은 크게 문제 되지 않도록 처리한다.

읽을 수 있는 속성 유형은 제목, 텍스트, 선택, 다중 선택, 상태, 사람, 숫자, 체크박스, URL, 이메일, 전화번호, 날짜, 생성 시간, 마지막 수정 시간, 고유 ID, 파일, 수식, 롤업이다.

## 2. Notion 연동 만들기

1. <https://www.notion.so/my-integrations>를 연다.
2. **New integration**을 선택한다.
3. `NewsComment AI`처럼 알아볼 수 있는 이름을 붙인다.
4. 수업 페이지가 있는 워크스페이스를 선택한다.
5. 결과물 가져오기만 사용한다면 **Read content**만 유지한다. 성장 기록을 Notion 페이지로 선택 저장할 때만 전용 상위 페이지에 필요한 쓰기 권한을 추가한다.
6. **Internal Integration Token**을 복사한다.

## 3. 연동 범위 좁히기

Notion 연동은 명시적으로 공유된 페이지만 읽을 수 있다. 하지만 상위 페이지를 너무 넓게 공유하면 의도보다 많은 페이지에 접근할 수 있다.

예를 들어 개인 워크스페이스의 최상위 페이지에 연결하면 금융, 건강, 개인 메모까지 포함된 수많은 하위 페이지가 열릴 수 있다.

범위를 좁게 유지한다.

1. 수업 자료만 담는 상위 페이지를 하나 만든다. 예: `NewsComment AI 수업 자료`
2. 기사 데이터베이스와 댓글 데이터베이스를 그 페이지 아래로 옮긴다.
3. Notion 연동은 그 상위 페이지에만 연결한다.

토큰이 실제로 어디까지 접근할 수 있는지 확인하려면 Notion API의 `search` 엔드포인트로 점검할 수 있다. 결과에 수업과 관련 없는 데이터베이스가 보이면 연동 범위가 너무 넓은 것이다. 새 연동을 좁은 범위로 다시 만들고 토큰을 교체한다.

## 4. 데이터베이스와 연동 연결하기

Notion 연동은 교사가 명시적으로 공유한 페이지만 볼 수 있다.

1. Notion에서 데이터베이스 페이지를 연다.
2. 오른쪽 위 `...` 메뉴를 선택한다.
3. **Connections** 또는 **Add connections**를 선택한다.
4. 앞에서 만든 연동을 선택한다.

이 단계를 하지 않으면 토큰이 맞아도 “데이터베이스를 찾을 수 없음” 오류가 난다.

## 5. 앱에 교사별 토큰 연결하기

서버 운영자는 로컬 `.env.local`과 Vercel 환경변수에 평가 연결 전용 암호화 키를 한 번 설정한다.

```bash
EVALUATION_SECRET_ENCRYPTION_KEY=16자_이상의_충분히_긴_임의_문자열
NOTION_API_VERSION=2022-06-28
```

교사는 로그인한 뒤 **평가 준비 프렙 → 내 Notion 연결**에서 자기 Internal Integration Token을 입력하고 **연결 확인 및 저장**을 누른다. 토큰은 서버에서 연결 시험을 거친 뒤 암호화되어 저장되며 브라우저에 다시 표시되지 않는다.

`NOTION_API_KEY`는 단일 사용자 또는 시연용 서버 공용 연결이 필요할 때만 선택적으로 사용한다. 여러 교사가 쓰는 운영 환경에서는 교사별 연결을 사용한다.

## 6. Supabase 마이그레이션 적용

가져오기 기능은 프로젝트별 Notion 데이터베이스 URL과 속성 매핑을 기억한다. 이를 위해 새 열이 필요하다.

Supabase SQL Editor에서 아래 파일 내용을 실행한다.

```text
supabase/migrations/002_project_notion_source.sql
supabase/migrations/20260828151841_evaluation_notion_connections.sql
```

두 번째 마이그레이션은 교사별 토큰 암호문과 연결 상태를 저장한다. RLS와 명시적 권한이 포함되어 로그인한 교사는 자기 연결 행만 다룰 수 있다.

## 7. 가져오기 실행

1. 대시보드에서 프로젝트를 연다.
2. 오른쪽 열의 **Notion 결과물 읽어오기** 카드를 찾는다.
3. Notion 데이터베이스 URL을 붙여 넣는다.
4. 학생 결과물이 데이터베이스 속성에 있는지, 각 학생 페이지 본문에 있는지 선택한다.
5. 데이터베이스 속성을 선택했다면 결과물 내용이 들어 있는 속성명을 입력한다.
6. 필요하면 학생 이름과 주제 속성명도 입력한다.
7. **Notion 결과물 읽어오기**를 선택한다.

앱은 이 설정을 프로젝트에 저장한다. 이후에는 한 번의 클릭으로 같은 설정을 다시 사용할 수 있다.

## 8. 동작 방식과 제한

- 이미 가져온 행은 건너뛰므로 다시 실행해도 새 댓글만 추가된다.
- 한 번에 최대 200개 댓글을 가져오며, Notion 생성 시간 순서로 가져온다.
- 결과물 하나는 최대 5000자로 잘린다.
- 선택한 결과물 속성 또는 페이지 본문이 비어 있는 행은 건너뛴다.
- 페이지 본문은 하위 블록을 순서대로 읽으며, 중첩 블록은 최대 6단계까지 읽는다.
- 읽어온 뒤 Notion에서 수정한 내용은 앱에 이미 저장된 결과물에 자동 반영되지 않는다. 평가 근거가 조용히 바뀌지 않게 하기 위한 현재의 안전 장치다.
- 앱은 Notion 원본 페이지에 평가 결과를 쓰거나 수정하지 않는다.
- Notion 토큰 평문은 서버에서만 사용한다. Supabase에는 AES-GCM 암호문만 저장되고 브라우저에는 워크스페이스 이름과 확인 시각만 전달된다.

## 9. 문제 해결

| 메시지 | 원인 |
| --- | --- |
| `교사별 Notion 연결 마이그레이션을 적용...` | 새 연결 테이블 마이그레이션이 아직 적용되지 않았다. |
| `EVALUATION_SECRET_ENCRYPTION_KEY...` | 서버 암호화 키가 없거나 16자보다 짧다. |
| `Notion 토큰이 올바르지 않습니다.` | 토큰이 틀렸거나 다른 워크스페이스의 토큰이다. |
| `Notion 데이터베이스를 찾을 수 없습니다.` | 데이터베이스가 연동과 공유되지 않았거나 URL이 일반 페이지를 가리킨다. |
| `... 속성이 없습니다.` | 입력한 속성명이 실제 속성명과 맞지 않는다. 오류 메시지에 사용 가능한 속성명이 표시된다. |
| `가져올 댓글을 찾지 못했습니다.` | 속성은 있지만 모든 행이 비어 있거나 잘못된 속성을 선택했다. |

## 10. 개인정보 주의

Notion에서 가져오면 학생 글이 Supabase 데이터베이스로 복사된다. 다른 학생 데이터와 같은 기준으로 관리한다.

- 실명보다 학생 번호나 별칭을 우선 사용한다.
- 학교 정책을 확인한다.
- 실제 수업 전 샘플 행으로 먼저 테스트한다.
