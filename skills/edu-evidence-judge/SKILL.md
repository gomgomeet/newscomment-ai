# 승인 기준 기반 평가·교사 검수·Notion 저장

승인된 평가기준안의 버전을 고정하고 학생 원문의 직접 근거로 Claude 평가 초안을 만든다. 교사가 원문을 대조해 유지·수정·보류를 결정하고 피드백과 평가 포워드를 확정한 뒤, 명시적으로 승인한 결과만 Notion 결과 페이지에 저장한다.

## 실행 경계

- 평가기준안과 루브릭이 승인되지 않았으면 평가하지 말고 기준 승인부터 요청한다.
- 결과물을 보고 새 루브릭을 만들거나 기존 기준의 성공기준·수준 경계를 바꾸지 않는다.
- 학생 이름·학번·연락처·사진·계정·상담·건강·가정 배경이 남아 있으면 중단하고 익명 사본을 요청한다.
- 학생 원문에 없는 태도·성격·잠재력·의도를 추정하지 않는다.
- AI 결과는 `평가 초안`이며 교사 검수 전에는 최종평가·확정점수·생활기록부 문장이 아니다.
- 후속 제출물이나 수업 관찰 증거가 없으면 학생의 성장을 확인했다고 쓰지 않는다.
- 학생의 답이나 완성 문장을 대신 작성하지 않는다.
- Notion에 쓰기 전까지 읽기 전용으로 작업한다. 대상 페이지와 변경값을 보여 주고 교사의 명시적 승인을 받은 뒤에만 저장한다.

## 필요한 입력

다음 입력을 확인한다.

1. 성취기준 코드와 원문
2. 승인된 루브릭 버전과 승인일
3. 평가 요소와 수준별 기술문 또는 점수 기준
4. 평가 과제·수업 의도·필요한 자료 맥락
5. E01, E02처럼 증거 ID가 붙은 익명 학생 원문
6. 학생 결과 페이지 또는 익명 원문이 있는 Notion 페이지
7. 빠진 자료와 판단할 수 없는 범위

Notion 연결이 없으면 학생 원문을 익명화해 복사·붙여넣기로 받는다. 연결이 있더라도 평가 대상 페이지, 학생, 활동, 원자료 Relation이 맞는지 먼저 읽기 전용으로 확인한다.

## 0단계 · 평가 대상과 기준 잠금

1. 대상 페이지의 제목과 URL을 표시한다.
2. 학생 식별정보가 제거되었는지 확인한다.
3. 활동 결과물과 기사·자료 원문 Relation이 맞는지 확인한다.
4. 사용할 성취기준과 승인된 루브릭 버전을 표시한다.
5. 누락·충돌이 있으면 평가하지 않고 `교사 확인 필요`로 멈춘다.

다음 확인표를 먼저 출력한다.

| 확인 항목 | 확인값 | 상태 | 교사 확인사항 |
| --- | --- | --- | --- |
| 대상 페이지 | 제목·URL | 확인/불일치 |  |
| 익명화 | 제거된 식별정보 | 확인/중단 |  |

| 평가기준 | 성취기준·루브릭 버전 | 잠금/미승인 |  |

## 1단계 · Claude 평가 초안

1. 각 평가 요소마다 관련 증거 ID와 짧은 원문 근거를 찾는다.
2. 수준별 기술문과 근거를 대조해 가장 잘 맞는 수준을 제안한다.
3. 두 수준 사이에 걸리거나 맥락이 부족하면 높은 수준을 추정하지 말고 `교사 확인 필요`로 둔다.
4. 근거가 없으면 `근거 없음`, 자료가 없어 판단할 수 없으면 `확인 불가`로 쓴다.
5. 확인된 강점 1개와 우선 보완점 1개를 고른다.
6. 수정 행동·제안 이유·완료 기준을 갖춘 피드백과 답을 대신하지 않는 재작성 질문을 제안한다.

## 2단계 · 교사 원문 검수

교사가 각 평가 요소를 `유지`, `수정`, `보류`, `추가 증거 필요` 중 하나로 결정하게 한다. 교사가 결정하지 않은 요소를 자동 확정하지 않는다.

| 평가 요소 | Claude 초안·근거 | 교사 결정 | 수정 수준·점수 | 수정 근거·이유 |
| --- | --- | --- | --- | --- |

사용자가 요청한 경우에만 Notion AI 결과와 비교한다. 이 비교는 선택 활동이며 두 AI의 점수를 평균 내거나 다수결로 확정하지 않는다. 언제나 승인된 기준, 학생 원문, 교사의 전문적 판단을 우선한다.

## 3단계 · 피드백과 평가 포워드 확정

교사가 검수한 판단으로 학생에게 돌려줄 내용을 정리한다.

- **강점 피드백**: 학생 원문의 직접 근거와 연결한다.
- **우선 개선 피드백**: 한 번에 실행 가능한 행동으로 쓴다.
- **제안 이유**: 이 행동이 어떤 성공기준을 충족시키는지 설명한다.
- **완료 기준**: 수정이 끝났다고 판단할 관찰 가능한 조건을 쓴다.
- **평가 포워드**: 다음 제출 또는 다음 수업에서 확인할 성공기준 1개를 정한다.
- **성장 상태**: 후속 증거 전에는 `성장 확인 전`, 후속 증거가 있으면 이전·현재 근거를 함께 제시한다.

## 4단계 · 교사 승인 후 Notion 결과 저장

쓰기 전에 반드시 다음 미리보기를 보여 준다.

- 저장할 Notion 페이지 제목과 URL
- 각 필드의 `현재값 → 새 값`
- 교사가 승인한 최종 수준·점수와 근거
- 피드백·평가 포워드·성장 상태
- 변경하지 않을 필드

`이 변경값으로 저장해 주세요`와 같은 교사의 명시적 승인을 받은 뒤에만 쓴다.

저장 가능한 필드는 교사가 승인한 평가 초안/최종평가, 교사 피드백, 평가 포워드, 검수 상태, 루브릭 버전, 평가일 등으로 제한한다. 학생 원문, 원자료, 승인된 루브릭, 수식·집계 필드, 기존 종합 세특·최종 기록은 자동으로 수정하지 않는다.

저장 후 페이지를 다시 읽어 다음을 검증한다.

1. 승인한 대상 페이지에만 반영되었는가?
2. 승인값과 저장값이 같은가?
3. 원문·루브릭·수식·기존 기록이 보존되었는가?
4. 실패하거나 일부만 반영됐으면 재시도 전에 차이를 보고했는가?

## 품질 점검

- 승인된 루브릭 버전을 끝까지 유지했는가?
- 모든 판단에 학생 원문 증거 ID가 연결되었는가?
- `근거 없음`과 `확인 불가`를 억지로 점수화하지 않았는가?
- AI 초안과 교사 최종판단이 분리되었는가?
- 피드백에 수정 행동·이유·완료 기준이 모두 있는가?
- 후속 증거 없이 성장을 단정하지 않았는가?
- 쓰기 전 대상 URL과 변경값을 보여 주고 명시적 승인을 받았는가?
- 저장 후 결과를 다시 읽어 검증했는가?
