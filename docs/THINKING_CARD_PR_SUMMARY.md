## 목적

생각 카드를 "AI가 미리 만든 답변 모음"이 아니라 **학생 질문에 답하기 위해 미리 조사하고
구조화해 놓은 지식 단위의 네트워크**로 다시 만들었다. 이전에는 카드가 만들어지자마자
프롬프트 텍스트로 녹아 사라졌다. 이제 카드는 DB에 남고, 실제로 챗봇 답변에 쓰인다.

## 주요 변경

### 1. 카드 8종과 지문 기반 생성기 (`lib/questioning-cards.ts`)

AI 없이 지문에서 기계적으로 뽑는 카드들. 배경·리서치 카드는 지문 밖 지식이라 여기서
만들지 않는다 — 출처 없이 만들면 지어낸 카드가 된다.

- 낱말 카드 — 문맥 문장이 실제 본문에 있으면 `verified`, 없으면 `needs_review`
- 사실·추론 카드 — 연결 표현(때문·반면·위해…)이 있는 문장은 추론 카드 + `reasoning_type`
- 대화 설계 카드 — **교사 메모 한 줄 = 카드 한 장**. trigger·prompt·goal로 나뉜다
- 예상 질문 카드 — 답을 담지 않고 관련 카드로 잇는 **라우터**

**관점별 라우팅**: 낱말 질문은 낱말 카드로, 까닭 질문은 인과 추론 카드로. 근거 문장만으로
이으면 "왜 잔반이 줄었나요?"가 "잔반이 20kg으로 줄었다"는 *사실* 카드에 붙는다. 사실은
맞지만 까닭의 답이 아니다.

### 2. Teacher AI — 낱말·배경·리서치 카드 (`lib/gemini/questioning-cards.ts`)

이 파일의 핵심은 카드 생성이 아니라 **지어낸 출처를 막는 검증**이다.

- 리서치 카드 URL은 실제 검색 근거(`groundingMetadata`)에서만 받는다
- 근거 없는 `research`는 배경 카드로 둔갑시키지 않고 **버린다**
- 출처 등급 A(정부·공공·학술) / B(주요 언론·전문기관) / C(일반 웹) / D(위키·블로그) —
  **A·B만 기본 사용**
- 낱말은 상세한 사전 뜻(뜻 갈래 구분) + 이 글에서의 문맥 뜻 + 아이 눈높이 예문.
  '석 달'처럼 띄어 쓴 말·세는 말도 낱말로 다룬다. **교사 어휘표가 우선**이고 AI는 빈 곳만 채운다

### 3. 저장 계층과 API

`lib/questioning-card-store.ts`, `app/api/questioning-board/cards/`

카드 연결은 임시 id → uuid 두 단계로 기록한다(순서를 지키지 않으면 없는 카드를 가리키는
연결이 남는다). ⑧을 다시 누르면 새 지문 행이 생기고 챗봇은 최근 것만 본다.
**AI가 실패해도 저장은 끝나고**, 카드 API가 실패하면 ⑧은 조용히 이전 방식으로 진행한다.

### 4. 카드가 답변에 실린다

- `findRelevantCards` — 매 질문마다 저장된 카드 중 이어지는 것을 점수화(문턱 4점)해
  Gemini 프롬프트에 싣는다. 교사 카드는 "선생님이 알려 준 내용", 리서치 카드는 출처와 함께
- **실시간 리서치** — 주제와 이어지는데 자료에 없는 질문은 검색해서 A·B 출처 근거가
  있을 때만 2~3문장 + 출처로 답하고, **리서치 카드로 저장해 다음 학생부터 재사용**
- Gemini 실패 시 1.5초 후 1회 재시도 → 그래도 실패면 로컬 규칙 엔진 폴백

### 5. 평가 흐름 — [질문 분석] → 표 → 엑셀

서버가 모든 학생 발화를 기록한다(`questioning_student_questions`, 실명 없이
`학교_반_번호`만). [질문 분석] 버튼이 학생별 질문모음·챗봇 답변모음·**루브릭 추천
점수(0~5, 실제 질문만 근거)**·세특형 피드백 초안으로 평가 기록 표를 채우고, 표에서
수정한 그대로 엑셀로 내려받는다. 참여 현황도 서버 기록으로 자동 채움.

### 6. 확인 창과 보드 정리

확인이 필요한 둘(교사 메모 해석 / 웹 리서치)만 한 화면에 한 번. 확인할 게 없으면 창이
뜨지 않는다. 이미지 업로드 옆 [AI 추출기], ⑦ 챗봇 수업 메모, ⑧ 모두 적용 및 노션 저장
(수업 연결 갱신 포함), [학생 챗봇 시작] 배너. 학교·학년반·인원은 ③에서 정하고 학생은
번호만 선택한다.

### 7. 스키마 (`004`, 선택 `005`)

표 4개(지문 / 카드 / 카드 연결 / 학생 질문 기록), RLS + `service_role` 전용.
pgvector는 005로 분리 — 004는 어디서나 적용된다. **2026-08-25 실제 Supabase 적용 완료.**
