### 답변 엔진 두 갈래

키가 있으면 Gemini 2.5 Flash를 **브라우저에서 직접** 호출하고, 키가 없거나 호출이
실패하면 말없이 죽지 않고 지문 기반 내장 엔진으로 넘어가며 화면에 한 줄 알린다.
키는 `localStorage`에만 두고 파일에 하드코딩하지 않는다.

### 어떻게 검증했나 — 브라우저 5회

프롬프트를 먼저 쓰지 않았다. **HTML을 만들어 Chromium에서 5회 돌린 뒤 실제로 깨진 것만**
프롬프트 규칙으로 옮겼다.

| 회차 | 잡은 것 |
| --- | --- |
| 1 | `‘잔반’은(는)` 조사 리터럴 노출 · 제목 줄을 근거로 인용 · 같은 답 반복 · 딴소리와 자료 밖 질문을 구분 못 함 |
| 2 | 따옴표 때문에 받침 판별이 깨짐 · 마무리 발문이 매 턴 동일 |
| 3 | 개인정보(이름) 무방비 · 숙제 대필 요청 수용 · "몰라요" 처리 없음 · 숫자를 낱말로 오인 · `…라고 짚었군요`가 로컬 엔진에 되살아나 있었음 |
| 4 | 2단계 어휘(사전 뜻 → 문맥 뜻)가 아예 없었음 · "결론이 뭐야"를 낱말로 오인 |
| 5 | `quote()`를 문장 중간에 넣어 `…나와 있어요. 여기에 쓰였어요`로 두 번 맺힘 → `bare()` 분리 |

마지막 회차는 아홉 마디 모두 서로 다른 답이 나왔고 페이지 오류 0건.
가짜 키로 Gemini 실패 대체 경로도 확인했다.

### 가장 값진 확인

3회차의 `짚었군요`는 웹앱에서 **이미 고쳤던 문제**인데 새로 쓴 로컬 엔진에 다시 들어갔다.
대화 규칙은 엔진마다 다시 심어야 한다. 그래서 프롬프트에 규칙 15개를 명문화했다.

## 2. 긴 기사가 학생 화면에서 사라지던 문제 (#17)

지문이 **1,800자를 넘으면 자동으로 "교과서를 살펴보세요"로 바뀌는** 규칙 때문에
평범한 신문 기사(1,000~2,000자)가 통째로 숨었다.

| | 전 | 후 |
| --- | --- | --- |
| 자동 전환 기준 | 1,800자 | **4,000자** |
| `교과서` 낱말 감지 | 제목 + 본문 앞 180자 | **제목에서만** |
| 첫 줄이 60자 넘을 때 제목 | 포기 → `교사 입력 질문 자료` | **첫 문장을 쓰고, 그것도 길면 끊어서** |

자동 전환이 걸리면 보드에 알린다 — 체크박스를 누르지 않았는데 지문이 사라지면
원인을 알 길이 없기 때문이다.

머지 전에 `main`이 세 번 움직여서(#18·#19·#20) 같은 파일을 건드린 #19와 의미 충돌이
없는지 확인한 뒤, main을 브랜치에 합쳐 다시 검증하고 머지했다.

## 3. 프롬프트 구조·교사 기입란·유의사항 (#21)

프롬프트를 받아 든 교사가 **어디를 고쳐야 하는지 바로 보이게** 했다.

- **8개 블록 구조표** — `■` 여덟 덩어리이고 각 블록이 무엇을 정하는지.
  대화 규칙 15개가 답의 품질을 결정하는 왕드다.
- **교사가 직접 적는 칸은 셋뿐** — 학년·성취기준·지문. 비워 두면 무엇이 무너지는지 함께 적었다.
  낱말 뜻·인원·메모·Gemini 키는 **프롬프트가 아니라 완성된 챗봇 화면에서** 넣는다.
  이걸 헷갈리면 키를 프롬프트에 적게 된다.
- **유의사항 8개** — 키를 파일에 적지 않기, 학생 기기에는 키 없는 파일, 무료 키는 시연용,
  저작권, 실명 미수집, UTF-8, 배포 전 점검, 교사 확인.
