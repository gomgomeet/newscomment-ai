# 평가 대시보드 설계 계획

뉴스 댓글 루브릭 평가(`/dashboard/*`)를 "데이터가 쌓이는 곳"에서 "교사가 수업 뒤에 열어 보는 화면"으로 바꾸는 계획이다. 질문 챗봇과는 무관하다.

평가 데이터는 **Supabase에 있다.** Notion은 댓글을 가져오는 입구일 뿐 평가 결과를 담지 않는다. 그래서 대시보드는 앱 안에서 키운다.

## 1. 먼저 — 데이터 모델에 막는 것이 있었다

계획을 세우기 전에 확인해야 할 사실이 하나 있었다.

`001_initial_schema.sql`의 `evaluations` 표에는 이런 제약이 있다.

```sql
unique (comment_id, evaluator_id)
```

그런데 수동 채점과 AI 초안이 **둘 다 같은 값으로** 이 표에 쓴다.

| | `evaluator_id` | `model_name` | 저장 방식 |
| --- | --- | --- | --- |
| 수동 채점 (`saveEvaluation`) | 로그인한 교사 | `teacher-manual` | `onConflict: comment_id,evaluator_id` |
| AI 초안 (`generateAiEvaluation`) | **같은 교사** | `gpt-5.6` 등 | **같은 onConflict** |

기존에는 두 경로가 같은 행을 놓고 다퉜다. 결과는 셋이었다.

1. **수동 채점을 저장한 뒤 AI 초안을 만들면 교사의 점수와 근거가 사라진다.** 경고도 없다.
2. **AI 초안을 만든 뒤 수동으로 저장하면 AI 결과가 사라진다.** 이쪽은 의도에 가깝지만, 초안을 다시 못 본다.
3. **`/dashboard/compare`는 비교할 것이 없다.** 댓글 하나에 행이 하나뿐이라 "AI는 3점, 나는 4점"을 볼 수가 없다. 화면 이름이 하는 일과 맞지 않는다.

이 문제는 `007_evaluation_sources.sql`에서 `source` 열을 추가하고, 유일 제약을 `(comment_id, evaluator_id, source)`로 바꾸면서 해결 방향을 반영했다. 이제 교사 수동 평가는 `teacher-manual`, AI 초안은 `ai-draft`로 따로 저장된다.

## 2. 지금 대시보드가 보여주는 것

| 화면 | 내용 |
| --- | --- |
| 홈 | 프로젝트 수, 루브릭 수, 평가 수 — 숫자 세 개 |
| Insights | 기준별 평균 (`평균 3.2 / 5`) |
| Compare | 저장된 평가를 프로젝트·댓글로 묶어 나열 |
| Evaluation | 채점할 프로젝트 고르기 |

집계는 **개수 셋과 기준별 평균**이 전부다. 화면이 데이터 모델(프로젝트·루브릭·평가)을 그대로 비추고 있고, 교사가 하는 일의 순서를 비추지 않는다.

## 3. 설계 원칙 — 교사의 일에는 리듬이 있다

댓글 평가는 이 순서로 돈다.

```
① 준비        루브릭을 만든다
② 수집        수업이 끝나고 댓글을 가져온다
③ 채점        30개를 한 번에 다 못 한다. 며칠에 나눠 한다
④ 확인        다 하고 나서 학급이 어땠는지 본다
⑤ 기록        기록으로 옮긴다
```

지금 대시보드는 **④를 약하게** 지원하고 나머지는 지원하지 않는다. 특히 ③이 비어 있다. 교사가 가장 오래 머무는 단계인데, "어디까지 했더라"에 답하는 화면이 없다.

이 계획의 방향은 하나다. **평균이 아니라 진행률과 분포를 보여준다.**

- `평균 3.2 / 5`는 아무 행동도 부르지 않는다. 좋다는 건지 나쁘다는 건지 알 수 없다.
- `30명 중 12명 채점함`은 다음 행동을 정해 준다.
- `1점대 7명`은 누구를 볼지 정해 준다.

## 4. 대시보드가 답해야 할 질문 여섯 개

각 질문에 답하는 데 필요한 데이터가 이미 있는지 표시한다.

| 질문 | 답하는 화면 | 데이터 |
| --- | --- | --- |
| 지금 뭘 해야 하나 | 홈 | ✅ `comments` ⟕ `evaluations`로 계산 가능 |
| 이 학급은 어땠나 | 프로젝트 리포트 | ✅ `evaluation_scores` |
| 누구를 먼저 봐야 하나 | 프로젝트 리포트 | ✅ 총점 하위 정렬 |
| 어떤 기준이 무너졌나 | 프로젝트 리포트 | ✅ 기준별 평균 (지금 Insights가 하는 것) |
| AI를 믿어도 되나 | 대조 화면 | ✅ 총점·피드백 비교 가능, 기준별 일치율은 추가 필요 |
| 무엇을 기록으로 남기나 | 기록 작업대 | ⚠️ `feedback` 열은 있으나 상태 관리가 없다 |

여섯 중 넷은 **스키마를 건드리지 않고** 쿼리와 화면만으로 된다. 이것이 단계를 나누는 근거다.

## 5. 화면 재구성

### 홈 — "지금 할 일"

숫자 세 개를 걷어내고 **진행 중인 프로젝트 카드**를 놓는다. 카드 하나에

```
6학년 3반 · 인공지능 기사 댓글
댓글 30 · 채점 12 · 남음 18          [████░░░░░░] 40%
마지막 채점 2일 전
                                    [이어서 채점하기]
```

교사가 대시보드를 여는 이유 대부분은 "어디까지 했지"다. 그 답을 첫 화면에 둔다.

### 프로젝트 리포트 — 채점이 끝난 뒤 여는 화면

한 프로젝트의 결과를 네 덩어리로 보여준다.

1. **점수 분포** — 총점 구간별 인원 막대. 평균 한 줄보다 분포가 수업을 더 잘 설명한다.
2. **기준별 평균** — 지금 Insights가 하는 것을 프로젝트 안으로 옮긴다. 어느 기준이 낮은지가 다음 수업 설계의 입력이다.
3. **먼저 볼 학생** — 총점 하위, 또는 특정 기준이 유독 낮은 학생. "성적이 낮은 학생"이 아니라 **다음 시간에 먼저 말을 걸 학생** 목록으로 이름 붙인다.
4. **눈에 띄는 댓글** — 상위 점수 댓글. 학생 이름을 가리고 다음 시간 예시 자료로 쓴다.

### 채점 작업대 — 프로젝트 상세

지금도 채점은 여기서 한다. 두 가지를 더한다.

- **안 한 것만 보기** 필터 — 30개를 훑지 않고 남은 18개만 본다
- **AI 초안을 옆에 두고 채점** — 초안이 교사 점수를 덮지 않으므로 나란히 놓을 수 있다

### 대조 화면 — Compare를 제 이름값 하게

댓글별로 `AI 3점 / 교사 4점`을 나란히 놓고, 프로젝트 전체의 **일치도**를 낸다. 현재 1차 구현은 댓글별 교사 평가와 AI 초안의 총점·종합 피드백 비교까지 지원한다. 다음 단계는 기준별 점수 일치율이다.

```
기준별 일치율     논거   82%   표현   64%   태도   91%
AI가 낮게 준 경우 7건    AI가 높게 준 경우 3건
```

이것이 있어야 교사가 "이 루브릭에서 AI를 얼마나 믿을 수 있는지"를 스스로 판단한다. AI 채점 보정의 근거도 여기서 나온다.

### 기록 작업대

`evaluations.feedback`에 이미 피드백을 저장한다. 여기에 **처리 상태**(미확인 / 초안 있음 / 검토 완료)를 더해 학기말에 "검토 완료"만 모아 내보낸다.

## 6. 단계별 로드맵

### 평가자료 입력 3경로 — 연수 적용 계획

평가 대상을 댓글 한 종류로 한정하지 않고 다음 세 경로로 확장한다.

| 경로 | 읽는 범위 | 평가에서 얻는 것 | 구현 순서 |
| --- | --- | --- | --- |
| Notion 페이지 링크 | 페이지 제목과 중첩된 전체 블록 본문 | 완성 결과물의 성취기준별 근거, 강점, 보완점 | **구현 완료 · PR #45 검토 중 · 이번 연수 실습** |
| Google Sheets | 학생별 행/탭, 시간순 수정·대화 로그 | 참여 지속성, 수정 과정, 질문 변화 | 다음 단계 |
| 이미지·PDF·Word | OCR 텍스트, 문서 본문, 페이지·문단 위치 | 서식이 있는 제출물의 근거 문장과 교사 확인 위치 | 다음 단계 |

세 경로는 모두 `원자료 → AI 초안 → 교사 확인 → 최종 평가` 순서를 공유한다. AI가 읽지 못한 이미지·첨부·표는 “확인 완료”로 단정하지 않고 교사 확인 필요로 표시한다.

Notion 경로의 완료 조건:

- 학생 페이지 링크와 식별명을 입력한다.
- 페이지의 중첩 블록을 순서대로 읽어 하나의 학습자 결과물로 저장한다.
- 원본 페이지 링크와 읽은 블록 수를 평가자료 메타데이터에 남긴다.
- 연결된 루브릭이 있으면 같은 동작에서 성취기준별 AI 초안을 만든다.
- 평가 카드에서 원본 링크, AI 점수·근거·피드백, 교사 최종 평가를 한 화면에서 대조한다.
- 같은 페이지를 중복으로 가져오지 않는다.

#### 이번 연수의 Notion 템플릿 운영 결정

이번 연수에서는 평가보드가 템플릿을 자동 생성하지 않는다. 강사가 제공한 **NIE 신문평가 기본 템플릿을 공동 연수용 Notion 워크스페이스 안에 복제하고**, 복제한 학생 결과물 페이지 링크를 평가보드에 연결한다. 현재 평가보드는 서버의 단일 `NOTION_API_KEY`를 사용하므로 서로 다른 개인 워크스페이스를 한 공용 보드에 연결할 수 없다.

- 기본 템플릿으로 첫 실습의 입력 구조와 평가 언어를 통일한다.
- 참가자는 강사가 지정한 공동 연수용 상위 페이지에 각자 사본을 만들어 원본 템플릿을 훼손하지 않는다.
- 학생 활동과 수정 과정은 Notion에, AI 초안과 교사 최종평가는 평가보드에 둔다.
- 수정본은 현재 v1 페이지를 보존하고 v2 페이지를 새로 복제해 연결한다.
- 상세 절차는 [NIE Notion 복제 템플릿과 평가보드 연결 안내](NIE_NOTION_TEMPLATE_LINKING_GUIDE.md)를 사용한다.

평가보드에서 교사 워크스페이스에 템플릿을 자동 생성하고 학생별 페이지를 일괄 만드는 기능은 후속 개발로 기록한다. 교사별 Notion OAuth 또는 토큰 암호화 저장, 쓰기 권한, 템플릿 버전, 수업활동·루브릭 자동 연결, v1·v2 수정 이력까지 함께 설계한 뒤 구현한다.

이번 연수에서 사용할 보드 실습 순서:

1. 제공된 NIE 기본 템플릿을 강사가 지정한 공동 연수용 Notion 위치에 복제한다.
2. 수업활동에 성취기준 루브릭을 연결한다.
3. 복제한 학생 결과물 페이지에 평가 앱 통합을 연결한다.
4. 별칭과 페이지 링크를 입력하고 `페이지 읽고 평가하기`를 실행한다.
5. 원본 페이지와 AI의 기준별 근거를 대조한다.
6. 교사가 점수와 피드백을 수정해 최종 평가로 저장한다.

후속 구현은 Google Sheets 입력, 이미지·PDF·Word 입력, 다출처 증거 포트폴리오 순서로 진행한다.

### 0단계 — 데이터 모델 고치기 (완료)

**이것 없이는 「AI를 믿어도 되나」에 영영 답하지 못한다.** A안을 적용했다.

**A안 — 유일 제약에 출처를 더한다** *(권장)*

```sql
alter table public.evaluations
  add column if not exists source text not null default 'teacher-manual'
    check (source in ('teacher-manual', 'ai-draft'));

alter table public.evaluations drop constraint evaluations_comment_id_evaluator_id_key;
alter table public.evaluations
  add constraint evaluations_comment_evaluator_source_key
    unique (comment_id, evaluator_id, source);
```

- 기존 행은 전부 `teacher-manual`이 되므로 데이터 손실이 없다
- `saveEvaluation`은 `source: 'teacher-manual'`, `generateAiEvaluation`은 `source: 'ai-draft'`로 `onConflict`를 바꾼다
- 지금 화면들은 `.eq("source", "teacher-manual")` 한 줄만 더하면 그대로 동작한다

**B안 — AI 초안을 별도 표로 뺀다**

`ai_evaluation_drafts` 표를 새로 만든다. 개념은 더 깔끔하지만 표 하나와 조회 경로가 늘고, 지금 규모에서 얻는 것이 A안과 같다. **A안을 권한다.**

적용된 변경:

- `supabase/migrations/007_evaluation_sources.sql` 추가
- `lib/db/types.ts`에 `evaluations.source` 타입 추가
- `saveEvaluation`은 `source: 'teacher-manual'`로 저장
- `generateAiEvaluation`은 `source: 'ai-draft'`로 저장
- 홈, 프로젝트 상세, Insights는 교사 수동 평가만 기본 집계
- Compare는 댓글별 교사 평가와 AI 초안을 나란히 표시

### 1단계 — 진행률 (완료)

`comments`를 왼쪽으로 두고 `evaluations`를 붙여 채점 여부를 센다. 홈 카드와 "안 한 것만 보기" 필터가 여기서 나온다. **오늘 할 수 있는 것 중 교사에게 가장 크게 와닿는 변화다.**

적용된 변경:

- 홈 대시보드에 남은 채점이 많은 수업활동 카드 표시
- 댓글 수, 교사 평가 수, 남은 댓글 수, 진행률 표시
- 마지막 채점 시각 표시
- 프로젝트 상세에 "안 한 것만 보기" 필터 추가
- 남은 댓글 채점 링크 추가

### 2단계 — 프로젝트 리포트 (완료, 스키마 변경 없음)

`evaluation_scores`를 프로젝트 단위로 모아 분포, 기준별 평균, 하위 학생, 상위 댓글을 낸다. 지금 Insights의 계산 로직을 프로젝트 안으로 옮기고 확장한다.

적용된 변경:

- 수업활동 상세에서 `학급 리포트`로 이동
- 교사가 확정한 평가만 리포트 집계에 사용
- 총점 구간별 학생 수와 학급 평균 표시
- 성취기준별 평균을 낮은 순서로 표시
- 낮은 점수와 취약 기준을 이용해 `먼저 확인할 학생` 제안
- 상위 결과물은 학생 이름을 숨긴 `수업 예시 후보`로 표시
- Notion 원자료 링크와 개별 평가 카드로 돌아가는 경로 제공

### 3단계 — AI 대조 (완료)

일치도와 기준별 일치율. AI 채점 보정의 근거가 여기서 만들어진다.

적용된 변경:

- AI 초안과 교사 최종평가가 모두 있는 결과물만 기준별 비교
- 전체 정확 일치율, 평균 점수 차이, 교사·AI가 더 높게 준 횟수 표시
- 성취기준별 정확 일치율과 ±1점 이내 일치율 표시
- 성취기준별 교사 평균, AI 평균, 평균 차이 표시
- 개별 결과물에서 교사 근거와 AI 근거를 나란히 대조
- 일치율이 낮거나 차이가 큰 기준부터 제시

### 4단계 — 기록 작업대

`evaluations`에 상태 열을 더하고, 검토 완료분을 내보낸다.

### 학생 결과물 향상 제안

평가 결과는 현재 수준을 설명하는 데서 끝나지 않고, 학생이 결과물을 다시 개선할 수 있는 행동으로 이어져야 한다. 새 AI 평가 초안은 성취기준마다 다음 내용을 함께 만든다.

- 현재 판단 근거: 왜 이 기준에서 보완 또는 확장이 필요한가
- 향상 방법: 학생이 직접 수행할 수 있는 구체적인 수정 행동
- 완료 확인: 수정 결과가 좋아졌는지 학생과 교사가 확인할 조건
- 재작성 질문: 답을 대신 써 주지 않고 학생의 독립적인 수정을 돕는 질문

이미 잘 충족한 기준은 결함을 억지로 찾지 않고 `유지·확장` 제안을 제공한다. 향상 제안도 AI 초안이므로 교사가 원자료와 학생 수준을 확인한 뒤 최종 피드백에 반영한다.

| 단계 | 스키마 | 크기 | 얻는 것 |
| --- | --- | --- | --- |
| 0 | **변경** | 완료 | 덮어쓰기 버그가 사라진다 |
| 1 | 없음 | 완료 | "어디까지 했지"에 답한다 |
| 2 | 없음 | 완료 | "학급이 어땠나"에 답한다 |
| 3 | 0단계 완료 | 완료 | "AI를 믿어도 되나"에 답한다 |
| 4 | 변경 | 작음 | 학기말 기록이 편해진다 |

## 7. 결정하지 않은 것

- **집계 단위** — 지금은 댓글 하나가 한 행이다. 한 학생이 댓글을 둘 이상 쓰면 학생 단위 집계가 갈린다. `comments.student_name`은 자유 텍스트라 동명이인과 표기 흔들림을 견디지 못한다. 학생 표를 따로 둘지, 프로젝트 안에서만 이름을 정규화할지 정해야 한다.
- **기준 최대 점수 변경** — 낮춰도 기존 점수가 정규화되지 않는다(README 「알려진 제한」). 분포 화면을 만들면 이 문제가 눈에 보이기 시작한다.
- **삭제 흐름** — 아직 없다. 잘못 가져온 댓글을 지우지 못하면 진행률이 영원히 100%에 못 닿는다. 1단계와 함께 검토한다.

## 8. Notion은 어디에 두나

평가 결과를 Notion으로 내보내는 방안도 있었지만 이번에는 하지 않는다.

- 평가 데이터는 Supabase에 있고 RLS로 교사별로 갈라져 있다. 내보내면 그 경계를 한 겹 더 관리해야 한다.
- 지금 Notion 연동은 **읽기 전용**이다. 내보내려면 쓰기 권한과 내보내기 코드가 새로 필요하다.
- 대시보드가 답해야 할 질문 여섯 개 중 다섯이 앱 안에서 더 잘 풀린다.

Notion은 **댓글을 모아 오는 입구**로 그대로 둔다. 그쪽 안내는 [Notion 가져오기 안내](NOTION_IMPORT_GUIDE.md)에 있다.

## 9. 저장소를 나눌 것인가

지금은 나누지 않는다. 코드 결합도는 이미 거의 없지만(평가 → 챗봇 참조 0건, 반대 방향은 함수 하나), **두 도구가 Supabase 프로젝트 하나를 함께 쓰고 마이그레이션 번호가 한 줄로 이어져 있다.** 저장소를 나누면 두 저장소가 한 데이터베이스에 순서 없이 마이그레이션을 던지게 된다.

대신 저장소 안에서 경계를 분명히 한다. 마이그레이션 표에 귀속을 적었고(README), 문서 목록을 두 도구로 나눴다.

나눌 시점은 이 중 하나가 올 때다.

- 다른 교사가 **평가 대시보드만** 복제해 쓰기 시작할 때
- Supabase 프로젝트를 분리할 때
- 질문 챗봇을 별도 도메인으로 배포할 때
