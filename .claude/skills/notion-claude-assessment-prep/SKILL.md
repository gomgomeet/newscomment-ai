# Notion × Claude 평가 준비

노션 수업자료와 학습자 결과물을 평가 가능한 구조로 만들고, 교사의 기준을 반영한 클로드 평가 초안을 생성한 뒤 교사의 피드백과 다음 활동의 방향까지 정리한다.

## 핵심 경계

- 목적은 원본 Notion DB를 완벽하게 연결하는 것이 아니라 평가를 실행하는 것이다.
- 챗봇 활동과 NIE 기사 댓글은 서로 다른 활동으로 평가한다.
- 같은 학생이라는 이유로 활동 결과를 한 평가 행에 합치거나 자동 점수화하지 않는다.
- 한 활동의 피드백은 다음 활동의 목표·질문·지원으로 전환할 수 있지만, 실제 전이가 확인되기 전에는 성취 증거로 해석하지 않는다.
- 점수는 참고 신호다. 직접 근거와 교사의 최종 판단이 우선이다.
- 원문에 없는 사실, 성장, 태도, 세특 표현을 만들지 않는다.

## 실행 모드

요청을 다음 모드 중 하나로 판별한다.

1. `평가 준비`: 성취기준, 수업 의도, 지문, 문항, 루브릭, 자기평가, DB 속성, 폼을 설계한다.
2. `결과 처리`: 이미 수집된 결과물을 활동별로 평가하고 학생별 피드백·피드포워드를 만든다.
3. `일괄 처리`: 같은 활동의 결과물 3~5건을 묶어 평가 초안을 만든다.
4. `교사 검토`: AI 초안과 직접 근거를 대조해 유지·수정·보류한다.

## 시작 시 요구할 Notion 링크

Notion 자료를 평가하려는 요청이면 평가를 시작하기 전에 사용자의 자료 링크를 요구한다. 링크는 페이지 링크 또는 데이터베이스 링크 모두 허용한다.

필수 확인 항목:

- 수업 자료 또는 지문 DB 링크
- 학생 결과물·제출물 DB 링크
- 학생 명단 DB 링크 또는 비식별 학생 ID 사용 여부
- 기존 평가 DB 링크가 있으면 그 링크
- 새 평가 DB를 만들 경우 평가 DB를 만들 위치가 될 Notion 페이지 링크

선택 확인 항목:

- 자기평가 응답 DB 또는 노션폼 링크
- 교사 관찰 기록 DB 링크
- 후속 결과물 DB 링크

링크를 받은 뒤 다음을 확인한다.

1. 각 링크가 페이지인지 데이터베이스인지 구분한다.
2. 현재 작업 계정에 읽기 또는 편집 권한이 있는지 확인한다.
3. DB의 제목 속성, 결과물 원문 속성, 학생 식별 속성, 활동·차시 속성을 확인한다.
4. 자료의 활동명을 확인하여 챗봇 활동과 NIE 기사 댓글을 분리한다.
5. 기존 DB를 수정하기 전에 복제 또는 새 평가 DB 사용 여부를 확인한다.

링크가 없거나 접근할 수 없으면 다음을 명확히 보고하고 멈춘다.

- 확인하지 못한 링크
- 필요한 권한
- 사용자가 제공해야 할 대체 링크
- 링크 없이 먼저 작성할 수 있는 평가 준비안의 범위

Notion DB 링크를 받았다는 이유만으로 모든 DB를 Relation으로 연결하지 않는다. 평가에 필요한 원문과 맥락을 확인하고, 필요한 속성만 평가 DB에 옮긴다. 연결되지 않은 자료도 결과물 ID와 활동명으로 평가할 수 있어야 한다.

## 평가 준비 절차

1. 먼저 성취기준 또는 확인하려는 배움, 수업 의도, 학습자 수준, 지문 원문, 결과물 형식, 점수 사용 목적을 확인한다.
2. 지문의 중심 생각과 핵심 개념을 추출한다. 확인되지 않은 기사 내용은 사실처럼 쓰지 않는다.
3. 중심 생각 파악, 내용 이해, 자신의 생각과 근거 표현처럼 서로 다른 능력을 서술형 문항으로 분리한다.
4. 문항별 평가 의도, 관찰 가능한 기준, 수준별 예시, 판단 유보 조건을 만든다.
5. 학생용 자기평가 체크리스트와 교사용 관찰 포인트를 만든다.
6. 평가 DB의 최소 속성을 제안한다: 결과물 ID, 비식별 학생 ID, 활동명, 차시, 원문, 자기평가, 교사 관찰, 평가 목표, 기준 1~3, 직접 근거, AI 초안, 참고 점수, 교사 판단, 피드백, 평가 포워드, 다음 활동, 후속 결과물, 처리 상태.
7. 노션폼 질문과 응답 형식을 설계한다. 실제 폼·공유 링크·QR을 만들지 못하면 설계안이라고 명시한다.
8. 사용자가 승인하기 전에는 확정 점수나 완료 평가로 표현하지 않는다.

## 결과물 처리 절차

1. 활동명으로 결과물을 먼저 분류한다.
2. 같은 활동·같은 기준의 결과물만 묶는다.
3. 학생 ID와 결과물 ID를 보존한다.
4. 원문에서 직접 확인되는 근거를 먼저 적는다.
5. 기준별 판단과 점수 참고값을 근거와 함께 제시한다.
6. 근거 부족, 원문 누락, 지문 불일치, 중복은 낮은 점수가 아니라 `판단 유보` 또는 `처리 보류`로 표시한다.
7. 학생별 강점과 보완할 점을 정리한다.
8. 피드백은 학생이 다음에 할 수 있는 행동으로 쓴다.
9. 피드포워드는 다음 활동에서 확인할 질문·행동·새 증거로 쓴다.
10. AI 초안과 교사 최종 판단을 별도 영역에 둔다.

## 클로드 평가 프롬프트

```text
너는 교사의 평가 판단을 돕는 평가 초안 작성자다. 최종 판단은 교사가 한다.

활동명: {활동명}
평가 목표: {평가 목표}
평가 기준과 수준 설명: {기준}
점수체계와 점수의 의미: {점수체계}
결과물: {결과물 ID, 비식별 학생 ID, 원문, 자기평가, 교사 관찰}

학생별로 다음을 출력하라.
1. 기준별 직접 근거
2. 기준별 판단과 참고 점수
3. 근거 부족 또는 판단 유보
4. 강점
5. 교사 피드백 초안
6. 다음 활동 피드포워드 초안

원문에 없는 사실을 만들지 말라.
다른 활동의 참여 사실만으로 성취를 추론하지 말라.
점수만 제시하지 말고 근거를 함께 제시하라.
AI 출력은 교사 검토 전 초안으로 표시하라.
```

## 피드백 → 피드포워드 변환

현재 결과물의 직접 근거 → 현재 활동의 강점·어려움 → 학생 피드백 → 다음 활동에서 시도할 행동 → 다음 활동에서 확인할 새 증거의 순서로 작성한다.

예: NIE 댓글에서 기사 근거가 약하면 다음 챗봇 활동에서 근거를 찾는 질문 만들기를 제안할 수 있다. 그러나 챗봇 결과는 질문 생성 활동의 별도 목표로 평가하며, NIE 성취를 자동 증명하지 않는다.

## 일괄 처리 안전 규칙

- 한 번에 3~5건만 처리한다.
- 활동명이 다른 자료를 한 묶음에 섞지 않는다.
- 원문은 수정하지 않고 수정본은 새 버전으로 저장한다.
- AI 초안이 교사 평가를 덮어쓰지 않게 한다.
- 점수 분포나 학생 순위를 우선 출력하지 않는다.
- 학생기록·세특은 여러 교사 확인 근거가 쌓인 뒤 별도 단계에서 작성한다.
- 개인정보가 포함된 원문은 비식별화 후 처리하고, 불확실하면 보류한다.

## 완료 보고 형식

완료 보고에는 다음을 포함한다.

- 처리한 활동명과 결과물 수
- 사용한 평가 목표·기준
- 생성된 AI 초안 수
- 교사 확인이 필요한 항목
- 근거 부족·보류 항목
- 학생 피드백과 다음 활동 피드포워드
- 실제로 생성·수정한 Notion 페이지, DB, 폼, 파일의 링크 또는 절대 경로

완성되지 않은 폼, 링크, QR, 점수, 학생기록은 완료된 것처럼 보고하지 않는다.
