# Codex가 만든 Google Apps Script 챗봇 검토 · 2026-09-05

검토 대상: 구글 시트 **「질문챗봇-연수-대시보드-템플릿」** (2026-09-03 생성, 09-05 수정). 시트 17장의 데이터만 읽었다 — **`.gs` 코드는 시트 안에 없어 보지 못했다.** 아래 지적은 시트에 남은 설정값·카드·실제 대화 기록·검색 로그에서 읽어 낸 것이다. 코드를 보면 원인이 더 정확해진다(8절).

## 2. 실제 대화 기록에서 보이는 문제 — 우선순위 순

`TURNS` 시트의 실제 세션 7개(09-03)를 읽었다. 점검 발화가 아니라 **사람이 친 말**이라 값지다.

### ① 옛 자료의 카드가 새 자료에서 그대로 나간다 — 가장 급함

```text
학생> 잔반이 뭐예요?
봇  > 교사가 제공한 자료에서는 반찬 양을 직접 고른 변화와 잔반 감소가 함께 제시됩니다.
      두 내용을 이어 주는 문장을 찾아 말해 볼까요?            [C009 카드]
```

지금 자료는 **NON-GMO 기사**인데 답은 **푸른초 급식 잔반 기사**(이전 시연 자료)의 것이다. `CARDS`의 C001~C010(힌트 3단계, 근거 확인, 잔반 카드)과 `BOARD` 시나리오 6개가 모두 옛 자료용인데 `materialId`가 같은 `MAT-001`이고 `sourceHash`가 비어 있어 **자료를 바꿔도 살아남았다.** `CHUNKS`에도 옛 구간(`CHK-MAT-001-v1-001` 푸른초)이 같은 ID로 비활성 상태로 남아 있다.

- 고침: 카드·시나리오는 반드시 `sourceHash`를 갖고, `MATERIAL`의 해시가 바뀌면 **해시가 다르거나 비어 있는 카드를 전부 비활성**으로 돌린다. 옛 자료 청크는 ID 충돌이 나지 않게 `materialId`를 새로 딴다(`MAT-002`).
- 지금 당장: C001~C010, BOARD S01~S06을 비활성으로 바꾼다. `READINESS`가 이것을 잡지 못했으므로 점검 항목에 "활성 카드의 sourceHash = 자료 해시"를 더한다.

### ② 사실 질문에 답을 주지 않고 되묻는다

```text
학생> 학생들은 고추장을 만들 때 어떤 재료를 사용했나요?
봇  > 자료에서 고추장에 섞은 재료를 찾아보세요. 조청, 고춧가루, 메줏가루 중
      어떤 것들이 나오는지 말해 볼까요?
```
```text
학생> 비유전자변형이라는 말이 있는 문장을 찾아줘
봇  > ‘비유전자변형’이라는 말 자체가 있는 문장을 찾기보다, 글에서 NON-GMO 식품을
      어떻게 설명하는지 확인해 보세요. 자료 구간 8을 다시 읽고 …
```

지문에 답이 그대로 있다(조청·고춧가루·메줏가루 / `NON-GMO(비유전자변형)`는 3구간). 카드 정책이 `ask_fact → check_evidence`로 고정돼 **사실 질문을 퀴즈로 바꾼다.** 저장소가 30회기 대화에서 얻은 첫 번째 규칙이 "학생이 물으면 먼저 답한다. 되묻기는 그다음"이다(`docs/연수용-단일프롬프트-학생챗봇.md` 규칙 2, 웹앱 V2 정책). 4학년이 세 번 되물음을 받으면 다음 질문을 안 한다.

- 고침: `ask_fact`·`ask_definition`은 **근거 청크로 먼저 답하고** 그 뒤에 한 문장 이내로 다음 걸음을 권한다. `check_evidence`는 학생이 **주장**했을 때(`attempt_answer`, `give_evidence`)만 쓴다. 이것이 2국면(4절)의 전제이기도 하다 — 1국면은 학생이 묻고 챗봇이 답하는 국면이다.

### ③ 위치·근거를 지어낸다

- "자료 구간 8을 다시 읽고" — 비유전자변형은 **3구간**이다. 8구간은 비빔밥 그림책 단락.
- `원산지는 무슨 말이야?` → "글의 **괄호 안 풀이**를 다시 보고" — 원산지에는 괄호 풀이가 없다. 앞 턴 NON-GMO 답의 "괄호" 틀이 그대로 새어 나왔다.
- `정체성이라는 말은 무슨 뜻이에요?` → 사전 뜻은 맞지만 "주변의 한 가지를 떠올리고 … 특징을 말해 보세요" — 지문의 `'배움으로서의 학교급식'이라는 정체성`으로 돌아오지 않는다.

- 고침: 응답의 위치 표현("구간 N", "괄호 안")은 모델이 쓰게 두지 말고 **검색된 청크 ID에서 코드가 만든다.** 어휘 답은 저장소의 두 걸음(사전 뜻 → 학생이 이어 물으면 `VOCABULARY.exampleText`로 문맥 뜻)을 따른다. 데이터는 이미 있다 — 96개 낱말 모두 `exampleText`가 채워져 있다.

### ④ 인사·잡담이 사실 질문으로 분류되고 검토 큐에 쌓인다

```text
학생> 안녕하세요?
봇  > 승인된 자료에서 바로 연결되는 근거를 찾지 못했어요. 지문의 어느 부분을 보고
      그렇게 생각했는지 알려 주세요.                       → REVIEW_QUEUE(EVIDENCE_GAP)
```

`studentMove`에 인사·잡담·개인정보·대필 요청이 없다. 저장소 정책의 `safety_redirect`·`repair`·딴소리 갈래를 옮긴다. 검토 큐에는 **지문 관련 낱말이 하나라도 든 질문만** 넣는다 — 지금은 큐 6건 중 1건이 "안녕하세요?"다.

### ⑤ 같은 질문에 결과가 다르다

`NON-GMO는 무슨 뜻이에요?`가 한 세션에서는 `top=0 → 확인할 수 없는 낱말`, 다른 세션에서는 `top=60.2 → 비유전자변형이라는 뜻`이다. 어휘 승인이 그 사이에 됐거나 300초 캐시가 옛 결과를 돌려준 것 — **코드를 봐야 안다.** 어느 쪽이든 승인 직후 캐시를 비워야 한다.

### ⑥ 잔소리 — 그러나 저장소가 이미 배운 것들

- "좋은 질문이에요"로 시작하는 답 3건. 저장소 `claude/privacy-and-greeting` 브랜치가 금지한 첫마디다(칭찬 대신 답).
- 거의 모든 답이 "…찾아보세요 / 말해 보세요"로 끝난다. 한 턴에 한 가지 도움, 물음표는 필요할 때만.
- 사진 설명 구간(`/정예준 기자 … 모습`, 005·009·012·015)이 승인·활성이라 근거로 뽑힐 수 있다. 저장소가 "제목 줄을 근거로 쓰지 않는다"에서 겪은 것과 같다 — 바이라인·캡션 패턴은 청크에서 뺀다.
- `ASK_NICKNAME = TRUE`("대화에서 사용할 이름이나 별명") — START_HERE의 "실명 대신 익명 활동 코드"와 어긋난다. 별명이라도 아이들은 이름을 적는다. 끈다.
- `AI_MAX_OUTPUT_TOKENS = 500` + `reasoning low` — OpenAI Responses API는 추론 토큰이 출력 한도에 든다. 사고가 길어지면 본문이 잘려 `compose:skipped`로 떨어진다. 단일 HTML의 Gemini와 같은 문제. 1,500 이상으로.

### ⑦ `EVALUATION_LOG`의 100점 vs 34점은 실제 품질의 증거가 아니다

9개 케이스(화분 싹·증발·나무 그늘·해조류…)는 **지금 자료가 아닌 합성 자료**에 미리 심은 KN/VOC/CHK 항목으로 돈 것이고, 비교 대상 "legacy"의 답("어두운 곳의 화분 나가 더 잘 자랐어요", "기화 엔탈피")은 일부러 틀리게 만든 것처럼 보인다. 파이프라인이 도는지 보는 연기 시험으로는 좋지만, 위 ①~⑤는 모두 이 시험을 통과한 뒤 실제 대화에서 나왔다. **실제 대화 7세션이 더 정직한 평가다.** 저장소의 점검 발화(`scripts/check-standalone-chatbot.mjs` 18개)를 이 웹앱 주소로 돌리는 것을 권한다.

## 3. 저장소 설계와 무엇이 같고 다른가

| | Codex GAS | 저장소 (`docs/구글-앱스스크립트-챗봇-2국면-설계.md`) |
| --- | --- | --- |
| 모델 | OpenAI gpt-5.6 (terra/luna 라우팅) | Gemini 2.5 Flash — **어느 쪽이든 상관없다.** 질문은 상태기가 소유하므로 |
| 검색 | 청크·지식·어휘 3갈래, 문턱 3, 캐시 | 카드 + 문장 창 — GAS 쪽이 더 낫다 |
| 대화 정책 | studentMove 8종 → primaryMove 5종 → 힌트 0~3 | 학생 상태 6종 → 허용 동작 → 지원 수준 0~4. **비슷하다. 다만 GAS는 "답 먼저"가 없다** |
| 2국면 | **없음** | 있음 |
| 채점 | 근거 사용률·힌트 수·수정 수 | 질문 수·관련 질문 수·이해/성취기준/의견 응답(세는 것만) |
| 검토 큐 | 있음 | 없음 (미답변 질문 → 교사 카드가 비슷) |

결론: **GAS 골격 위에 2국면과 "답 먼저" 정책을 얹는 것**이 맞다. 새로 짓지 않는다.

## 4. 2국면을 여기에 넣는 방법

`Phase.gs` 설계(`docs/구글-앱스스크립트-챗봇-2국면-설계.md` 3~4절)를 이 시트 구조에 맞춰 옮긴다.

### 4-1. 시트 열 추가

| 시트 | 더할 열 | 뜻 |
| --- | --- | --- |
| `TURNS` | `phase`(1/2) · `managedKind`(b1/b2/comprehension_medium/comprehension_followup/standard/opinion) · `difficulty`(하/중/상) · `responseScore`(0~5) · `relatedQuestion`(TRUE/FALSE) | 턴마다 상태기가 적는다 |
| `MATERIAL` | `standardCode`(예 `[4국02-03]`) | 지금 `standard` 칸은 학습 목표 문장. 표적 고르기는 성취기준 문장과 교사 메모에서 한다. "중심 내용"이 `main_idea` 표적으로 잡히게 `buildStandardTargets`의 낱말표에 `중심 내용`을 더한다 |
| `DASHBOARD` | 학생별 행: 질문 수 · 관련 질문 수 · 이해 응답 최고 · 성취기준 응답 최고 · 의견 응답 · 더 알아볼 질문 · 도달 난이도 | 세는 것만. 판정 열은 교사가 |

### 4-2. 상태 읽기 — 새 시트 없이

`decidePhase()`는 이 세션의 `TURNS` 행을 읽어 센다. `studentMove`가 이미 있으니 그대로 쓴다.

- 지문 관련 질문 = `ask_definition` 또는 `ask_fact` 이면서 `CHUNKS`·`VOCABULARY` 낱말이 하나라도 든 것. `안녕하세요?`는 낱말이 없어 빠진다(④와 같은 판정기).
- B1 사용 여부 = 봇 행에 B1 문구 포함.
- 물은 2국면 질문 = 봇 행의 `managedKind`.

### 4-3. 어디에 끼우나

```text
학생 발화
  → 기존: studentMove 분류 → 검색 → (AI 분석·조립 | 카드·규칙 응답)
  → 추가: decidePhase(TURNS 행, 발화) ──┐
                                          ▼
      조립 단계에 [지금 할 일] 주입  ──▶  응답
                                          ▼
      enforceManagedQuestion(응답, 결정) ──▶ TURNS에 phase·managedKind·responseScore 기록
```

- **1국면**: `[지금 할 일] 학생 질문에 답하고 되묻지 마세요.` — ②의 "답 먼저"가 여기서 강제된다. 카드 응답 경로도 같은 후처리를 거치므로 `check_evidence` 카드의 되묻기가 1국면에서는 걷힌다.
- **B1/B2**: 3턴 지나 관련 질문 ≤1 → B1 한 번. `없어요` → B2 → 2국면.
- **2국면**: 이해(중) → 이해(상/하, 직전 답 점수로) → 성취기준 표적 ≤2 → 의견. 질문 문구는 저장소 상수를 그대로. 표적 질문의 "이 문장을 먼저 다시 보고" 근거 문장은 **검색된 청크**에서 고른다 — GAS의 검색이 저장소보다 나으니 여기서 이득을 본다.
- **후처리**: 모델이 붙인 물음표 문장을 모두 걷고 상태기의 질문 하나만 붙인다. `close`·`repair`·`safety`면 물음표 0.
- **점수**: `Signals.gs`(저장소 `questioning-target-signals.ts` 이식)로 직전 2국면 질문에 대한 답을 0~5로 재서 `responseScore`에 적는다. 모델에게 묻지 않는다.

### 4-4. 기존 카드 정책과의 관계

| 기존 studentMove | 1국면 | 2국면 |
| --- | --- | --- |
| `ask_definition`, `ask_fact` | 답 먼저, 되묻기 없음. 관련 질문으로 센다 | 답 먼저 + 상태기 질문 하나 |
| `attempt_answer`, `give_evidence`, `revise` | 기존 `check_evidence`·`receive` 유지 (학생 주장에는 근거 확인이 맞다) | 답 점수 매기고 다음 질문 |
| `request_hint`, `express_uncertainty` | 기존 힌트 3단계 유지 | 난이도를 `하`로 내리고 근거 문장 제시 (저장소 `lowFailureFeedback`) |
| `close` | 질문 없이 마침 | 같음. 의견 질문을 못 물었으면 `reflection_opinion` 0 |
| (새) `greeting`, `off_topic`, `repair`, `safety` | 저장소 문구 | 같음. 상태기는 이 턴을 세지 않는다 |
