# 챗봇 스크립트 점검과 수정 방안 · 2026-09-05

점검 대상은 연수용 챗봇 스크립트 세 벌이다.

| 벌 | 파일 | 역할 |
| --- | --- | --- |
| 참조 구현 | `webapp/질문챗봇-단일HTML.html` | 교사가 더블클릭해 쓰는 완성본. 로컬 엔진 + Gemini 지시문 |
| 생성 프롬프트 | `docs/연수용-단일프롬프트-학생챗봇.md` | 수강 교사가 붙여 넣어 자기 HTML을 만들게 하는 프롬프트 |
| 1회성 프롬프트 | `docs/1회성-챗봇-세특-프롬프트.md` | 웹 챗봇에 붙여 넣는 준비→대화→세특 한 덩어리 |

## 1. 어떻게 확인했나

- `main`의 참조 HTML을 Chromium(Playwright)에서 실제로 열어, 회귀 평가 기사(`evals/questioning-chatbot/fixtures/articles.json`의 급식 잔반 기사)를 넣고 **점검표 아홉 마디 + 추가 열여덟 마디**를 쳤다.
- 미머지 비공개 브랜치 40여 개를 `main` 기준으로 훑어, 챗봇 스크립트를 건드린 것을 골라 같은 발화로 다시 돌렸다.
- 웹앱의 2국면 로직(`lib/questioning-conversation-phase.ts`)·대화 정책(`lib/questioning-dialogue-policy.ts`)과 단일 HTML을 견주었다.

## 2. 확인 결과

### 2-1. `main`의 참조 HTML — 점검표 아홉 마디는 통과, 그 밖에서 여섯 곳이 깨진다

점검표 아홉 마디는 모두 서로 다른 답이 나왔고 페이지 오류는 0건이다. 그러나 점검표가 **"서로 다른 답인가"만 보고 "맞는 답인가"는 보지 않아서** 다음이 그대로 남아 있다.

| # | 학생 발화 | 실제 응답 | 왜 문제인가 |
| --- | --- | --- | --- |
| 1 | `왜 그렇게 됐어요?` | "그건 이 글에 나오지 않아요." | 지문에 `영양교사는 … 영향을 주었을 수 있다고 설명했다`가 있다. 원인 문장 판정이 `때문·덕분·탓·로 인해·원인·-져서`뿐이라 `영향을 주었을 수 있다`를 못 잡는다. **종료 인사로 오인하지 않는 것만 확인했지, 답이 맞는지는 확인하지 않았다.** |
| 2 | `잔반이 뭐예요?` → `이 글에서는 어떤 뜻이야` | "'잔반'이 쓰인 문장을 자료에서 찾지 못했어요." | `잔반`이 제목에만 있고 본문은 `남은 음식`이라 쓴다. 제목을 근거에서 뺀 규칙(#25)이 어휘 2단계까지 막았다. |
| 3 | `42%가 뭐예요` | "그건 이 글에 나오지 않아요." | 같은 원인. 제목의 수치를 물으면 "없다"고 답한다. |
| 4 | `선택 배식이 뭐예요?` 두 번 | 완전히 같은 문장 반복 | 점검표의 "같은 질문 두 번" 항목이 실제로는 걸러지지 않는다. |
| 5 | `왜 자꾸 물어봐요 그냥 설명만 해줘요` | 근거 문장 + "왜 그렇게 되었을지 짐작해 볼까요?" | 질문을 그만하라는 말에 다시 물었다. 웹앱에는 있는 관계 회복(`repairPattern`)이 단일 HTML에는 없다. |
| 6 | [선생님 화면] → [학생 화면 시작] | 이전 학생의 대화창과 번호가 그대로 남음 | 태블릿 한 대를 여러 학생이 돌려 쓰는 흐름(문서 「수업에서 쓰는 흐름」 2번)이 새로고침 없이는 안 된다. `lastTerm`·`lastEvidence`도 남는다. |

그 밖에 실행으로는 못 잡지만 코드에서 보이는 것:

- **Gemini 호출이 빈 응답으로 떨어질 위험.** `maxOutputTokens: 500`인데 `gemini-2.5-flash`는 기본으로 사고(thinking) 토큰을 쓰고 이 한도에 포함된다. 사고가 길어지면 본문 없이 끝나 `"빈 응답"` → 로컬 대체로 조용히 넘어간다. 교사는 "AI 연결이 잠시 막혀"만 본다. (`thinkingConfig.thinkingBudget: 0` 또는 한도 상향으로 해결 — 이 환경에서 Gemini 문서에 접근할 수 없어 **실제 키로 확인 필요**.)
- **학생용 링크가 파일 배포 흐름에서는 쓸모가 없다.** 링크는 `location.origin + pathname + #s=…`라 더블클릭으로 연 파일에서는 교사 PC의 경로가 들어간다. 학생 기기에서 열 수 없다. 서버에 올렸을 때만 의미가 있다.
- **기록이 학생 기기 브라우저에만 남는다.** 문서는 "수업이 끝나면 [기록 내려받기]"라고 하지만, 학생 기기로 나눠 준 경우 교사 화면에는 아무 기록도 없다. 학생 쪽에서 내보내는 경로가 없다.
- **2국면이 없다.** README와 웹앱은 "질문 4개 뒤 챗봇이 이해→성취기준→의견 순으로 되묻는다"를 핵심으로 두는데, 연수용 프롬프트·참조 HTML·Gemini 지시문 어디에도 없다. 1회성 프롬프트(규칙 21~25)에만 있다. 연수생이 만드는 챗봇은 학생 질문에 답만 하다 끝난다.
- 문서 안내가 코드와 어긋난다 — "대화 규칙 15개"라 쓰고 16개를 싣고, "8개 블록" 표에 9줄이 있으며, "왕드"는 오타다.

### 2-2. 비공개 브랜치 — 고친 것과 되돌린 것이 섞여 있다

챗봇 스크립트를 건드린 미머지 브랜치는 다음과 같다. 전부 `main`과 충돌한다(같은 파일을 그 뒤 PR들이 다시 고쳤다).

| 브랜치 | 날짜 | 무엇 | 상태 |
| --- | --- | --- | --- |
| `codex/standalone-html-five-session-eval` | 08-26 | 단일 HTML·프롬프트 **19개 규칙**, [새 학생], 활용형 낱말 찾기, 수치·측정·전이·가설·안전 갈래, 자료별 기록, 웹앱 개인정보 가리기·가설 응답 | **핵심 개선. 그러나 #25·#26·#28·#31 이전 main에서 갈라져** 그 수정이 빠져 있다 |

`codex/standalone-html-five-session-eval`의 HTML을 같은 발화로 돌린 결과:

| 발화 | `main` | codex 브랜치 |
| --- | --- | --- |
| `왜 그렇게 됐어요?` | 없다고 답함 (틀림) | **종료로 오인** (#26 미반영, 더 나쁨) |
| `적게 받은 학생은 어떻게 됐어요?` | 근거 문장 답변 | **종료로 오인** |
| `맞벌이가 뭐예요?` (교사 낱말) | 교사 뜻 답변 | `'맞벌'은 자료에서 찾지 못했어요` (#28 미반영) |
| `글쓴이 주장이 뭐예요?` | 첫·끝 문장 요약 | 낱말로 오인 |
| 자료명 | `먹고 싶은 만큼…` | `# 먹고 싶은 만큼…` (#25 미반영) |
| `다른 학교도 똑같이 될까요?` | 없다고 답함 | **조건 차이를 설명** (개선) |
| `왜 자꾸 물어봐요…` | 되물음 | 근거만 답하고 끝냄 (개선) |
| `한빛초는 몇 학년이 했어요?` | 근거 + 되물음 | 근거만 (개선) |
| [선생님 화면]→[학생 화면 시작] | 이전 대화 잔류 | **번호 선택으로 초기화** (개선) |
| `42%가 뭐예요` | 없다고 답함 | 엉뚱한 문장(`4학년`, `2주`가 든 첫 문장) |

결론: **어느 쪽도 그대로 쓸 수 없다.** codex 브랜치의 개선을 `main` 위에 다시 얹되, 그 브랜치가 모르는 뒤의 수정(#25·#26·#28·#31·2국면 패러프레이즈)을 잃지 않아야 한다. 브랜치를 머지하는 방식보다 **개선 항목을 골라 `main`의 HTML에 다시 심는 쪽**이 안전하다.

## 3. 수정 방안

### P0 — 지금 바로 (참조 HTML 한 파일, 반나절)

**① codex 브랜치의 개선을 `main` HTML에 이식.** 가져올 것만 고른다.

- `resetConversationState()` + [새 학생] 버튼. `startStudent()`와 [시작하기]에서 호출해 `chatLog`·`studentNo`·`lastTerm`·`lastEvidence`·`followUpAt`을 비운다.
- `termVariants()`/`sentenceHasTerm()` — `주저하다`로 `주저했습니다`를 찾는다.
- 교사 낱말 뜻 문장을 `‘X’은 “…”이라는 뜻이에요`로. (`망설이다을 뜻해요` 방지)
- 전이(`다른 학교도…`)·가설(`…때문에 …거죠?`)·안전(`주소 보여도 돼요?`)·측정 방법 갈래와, 까닭 답 뒤 되묻기 생략.
- 기록에 `lesson`·`grade`·`engine` 열, 현재 자료 기록만 내려받기.
- 가져오지 않을 것: `isClosing`·`askedWord`·제목 처리는 `main` 것을 유지. codex의 수치 가중치(`/\d/`만 보고 +6)는 42% 오답을 냈으므로 **묻는 숫자가 실제로 든 문장**만 가점하도록 바꿔 넣는다.

**② 까닭 문장 판정 확장.** `findEvidence`의 원인 패턴에 `영향을\s*주|수\s*있다고|이유|까닭|-면서|덕에|덕분` 를 더하고, 까닭 질문인데 키워드가 하나도 안 겹칠 때(`왜 그렇게 됐어요?`처럼 지시어만 있는 질문)는 **직전 근거 문장(`lastEvidence`) 다음 문장**과 원인 패턴 문장을 후보로 본다. 학생의 "그렇게"는 대개 직전 답을 가리킨다.

**③ 제목에만 있는 낱말·수치.** 제목은 여전히 근거 인용에서 빼되, 낱말 2단계와 수치 질문에서 본문에 없고 제목에 있으면 `제목에 “…”라고 나와요. 본문에서는 이것을 “남은 음식”이라고 풀어 써요`처럼 **제목 갈래**로 답한다. 본문 쪽 문장은 교사 뜻풀이의 낱말(`남긴`, `음식`)과 겹치는 문장을 고른다.

**④ 같은 질문 반복.** 직전 학생 발화와 정규화(공백·문장부호 제거)해서 같으면 같은 답을 내지 않고 `아까 그 문장이에요. 이번에는 문장에서 낱말 하나를 골라 어떤 뜻일지 말해 볼까요?`로 지문에 되돌린다. 세 번째부터는 근거를 다른 문장으로 바꾼다.

**⑤ 관계 회복.** 웹앱의 `repairPattern`을 그대로 옮긴다. 걸리면 근거 문장만 답하고 **물음표를 붙이지 않는다.** Gemini 지시문에도 같은 줄을 넣고, `geminiReply()`의 물음표 처리에서 회복 턴이면 물음표를 모두 마침표로 바꾼다.

**⑥ Gemini 호출 안정화.** `generationConfig`에 `thinkingConfig: { thinkingBudget: 0 }`, `maxOutputTokens: 1024`. 실패 시 로컬로 넘기기 전에 **한 번 재시도**(`thinking-card-simulation` 브랜치가 웹앱에서 한 것과 같다). 429(무료 키 분당 한도)는 재시도하지 말고 즉시 로컬로 넘기되 안내 문구를 "무료 키 한도"로 구분한다 — 24명이 한 키를 동시에 쓰면 반드시 만난다.

**⑦ 문서 정합.** 규칙 개수·블록 수·오타를 고치고, 점검표에 "맞는 답인가" 열을 추가한다(아래 6절).

### P1 — 다음 (연수 전, 하루)

**⑧ 2국면 이식.** 연수용 챗봇이 웹앱과 같은 수업을 하려면 이것이 있어야 한다. 서버가 없으므로 **브라우저 JS가 상태기를 맡고** 두 엔진에 같은 지시를 준다.

- 상태: 지문 관련 질문 수(웹앱 `isPassageRelatedQuestion`을 옮김), B1 사용 여부, 이미 물은 2국면 질문 종류.
- 전환: 관련 질문 4개 → 2국면. 3턴 지나 관련 질문 ≤1 → B1(`혹시 지문에서 모르는 단어나…`) 한 번 → 없다고 하면 B2 → 2국면.
- 2국면 질문 3종은 웹앱 문구를 그대로 쓴다: 이해 확인(중) → 성취기준 표적(`buildStandardTargets`의 `askTemplate` 7종 중 성취기준 낱말로 고른 것) → 생각·의견. 한 턴에 하나.
- Gemini 경로: 매 턴 `contents` 마지막 user 파트 앞에 `[지금 할 일] 학생 말에 먼저 답한 뒤, 마지막에 다음 질문 하나만 덧붙여: "…"`를 붙인다. 로컬 경로: `localReply()` 결과의 물음표 문장을 지우고 같은 질문을 붙인다(웹앱 `appendOneQuestion`).
- 프롬프트 문서에는 「■ 두 국면」 블록 하나를 더한다. 1회성 프롬프트 규칙 21~25를 옮기면 된다.

**⑨ 기록에 관찰 수치.** 2국면이 있으면 CSV 한 줄을 더 남길 수 있다: `번호, 스스로 만든 질문 수, 지문 관련 질문 수, 이해 응답, 성취기준 응답, 의견 응답, 더 알아볼 질문`. 점수는 매기지 않는다 — 웹앱 원칙("모델에게 몇 점이냐고 묻지 않는다")대로 **세는 것만** 남기고 판정은 교사가 한다. 이 CSV는 이미 저장소에 있는 `webapp/수업도우미-검수.html`(CSV 읽기·미제출 찾기·루브릭 채점)이 바로 읽을 수 있다. 두 파일이 처음으로 이어진다.

**⑩ 학생 기기 기록 수집.** 학생 화면 하단에 [내 기록 내려받기] — 그 학생 번호의 기록만 CSV로. 교사는 여러 CSV를 `수업도우미-검수.html`에 한꺼번에 떨어뜨린다(이미 드롭 영역이 있다). 파일 이름은 `질문기록_자료명_7번.csv`.

**⑪ 배포 경로 둘로 정리.**

- **링크 트랙**: `claude/host-standalone-chatbot`을 최신 HTML로 다시 만들어 `public/chatbot.html`로 올린다. 이때만 [학생용 링크 만들기]가 산다. 빌드 때 `webapp/` 파일을 `public/`으로 복사하는 한 줄을 `package.json`에 넣어 두 벌이 어긋나지 않게 한다.
- **파일 트랙**: [학생용 파일 만들기] 버튼 — 현재 HTML 자신을 읽어(`document.documentElement.outerHTML`) 설정을 `<script id="preset">`으로 심고 **키는 비운 채** `질문챗봇-학생용.html`로 내려받게 한다. 학생 기기에서는 더블클릭만 하면 학생 화면이 바로 열린다. 문서의 "키를 넣은 파일을 그대로 주지 마세요" 경고가 버튼 하나로 해결된다.

### P2 — 구조 (연수 뒤)

**⑫ 연수 프롬프트를 두 트랙으로.** 지금 프롬프트는 LLM이 900줄 HTML을 처음부터 다시 쓰게 한다. 문서 스스로 인정하듯 "생성형 AI가 매번 만드는 HTML은 코드 구조가 달라" 5회 돌려 잡은 열네 가지 오류가 연수생 파일마다 되살아난다(작업정리 문서의 "짚었군요가 로컬 엔진에 다시 들어갔다"가 그 예다).

- **트랙 A(5분)**: 참조 HTML을 그대로 받아 「■ 내 수업」 세 칸만 화면에서 채운다. 대부분의 교사는 여기서 끝난다.
- **트랙 B(연수 체험)**: 프롬프트로 **자기 것을 만들되**, 프롬프트에 "아래 참조 구현의 대화 규칙과 내장 엔진 조건을 그대로 지켜라"를 넣고 참조 HTML의 로컬 엔진 부분을 붙여 준다. 생성 범위가 화면·문구로 좁아져 실패가 준다.
- 두 트랙 모두 마지막에 같은 점검표를 돌린다.

**⑬ 규칙을 한 곳에서.** 지금 대화 규칙이 네 곳에 따로 산다 — 웹앱 Gemini 지시(`lib/gemini/questioning-board.ts`), 웹앱 로컬 엔진(`lib/questioning-board.ts`), 단일 HTML 지시문, 단일 HTML 로컬 엔진, 여기에 프롬프트 문서 둘. 번호도 다르다(문서 16, HTML 14, codex 19). 최소한 **규칙 번호와 문구를 한 표(`docs/챗봇-대화규칙.md`)로 두고** 네 곳이 그 번호를 인용하게 한다. 규칙을 고칠 때 어디를 함께 고쳐야 하는지 표 한 줄로 보인다.

**⑭ 회귀 점검 스크립트를 저장소에.** 이번 점검에 쓴 Playwright 스크립트를 `scripts/check-standalone-chatbot.mjs`로 정리해 넣는다. 발화 목록과 **기대 조건**(종료 아님, 특정 문장 포함, 물음표 개수 ≤1, 직전과 다름)을 함께 두면 웹앱의 `eval:questioning`처럼 단일 HTML도 자동으로 돈다. 지금은 사람이 아홉 마디를 치는 것이 전부다.

**⑮ 작은 것들.** CSV 셀이 `=`, `+`, `-`, `@`로 시작하면 엑셀이 수식으로 읽는다 — 앞에 `'`를 붙인다. `showRecords()`가 표를 보여 주는 동시에 내려받기까지 하는데 둘을 나눈다. 개인정보 안내 뒤에도 Gemini `history`에 이름이 남아 다음 턴에 다시 부를 수 있다 — codex 브랜치의 `redactPersonalInformation`을 단일 HTML `geminiReply()`의 history에도 적용한다.

## 5. 1회성 프롬프트에 대해

`docs/1회성-챗봇-세특-프롬프트.md`는 2국면과 평가 모드가 있어 구조가 가장 완전하다. 세 가지만 손본다.

- 규칙 4(어휘 두 걸음)에 **제목에만 있는 낱말** 처리를 한 줄 더한다(P0 ③과 같은 문제).
- 3단계 채점표의 `질문하기` 기준이 웹앱(`countableQuestions`: 5개↑=5, 4=4, 2~3=3, 1=2, B1 뒤 1=1)과 같으니 그대로 두되, "지문 밖 추론 질문도 센다"는 문장이 웹앱과 맞는지 확인한다 — 웹앱은 `beyondQuestions`를 `질문하기`에 세고 `성찰·의견`에는 신호로만 붙인다. 문서도 그렇게 적혀 있어 일치한다.
- 교사 암호를 프롬프트 맨 위에 두면 대화 첫 화면에 그대로 보인다. 학생이 화면을 넘기면 읽을 수 있다. 암호를 **1단계 준비 완료 뒤 교사가 따로 입력**하게 바꾸면 화면에 남지 않는다.

## 6. 점검표 보강 — "다른가"에서 "맞는가"로

기존 아홉 마디에 아래를 더하고, 각 줄에 기대 조건을 붙인다.

| 발화 | 기대 |
| --- | --- |
| `왜 그렇게 됐어요?` | 종료 아님 **그리고** 원인 문장(`영향`, `때문`, `덕분`…) 인용 |
| `(제목에만 있는 낱말)이 뭐예요?` → `이 글에서는?` | "찾지 못했어요"가 아니라 제목 인용 + 본문의 바꿔 쓴 말 |
| `(제목의 수치)가 뭐예요` | 제목 인용 |
| 같은 질문 두 번 | 두 번째 답이 첫 답과 다르고 지문으로 되돌림 |
| `왜 자꾸 물어봐요` | 물음표 0개 |
| `다른 학교도 똑같이 될까요?` | 조건 차이 언급, 보장하지 않음 |
| `…때문에 줄어든 거죠?` | "가설"이라고 구분 |
| [새 학생] 뒤 `이 글에서는?` | 앞 학생 낱말을 기억하지 않음 |
| 지문 관련 질문 4개 뒤 | 챗봇이 이해 확인 질문 하나를 덧붙임 (P1 ⑧ 뒤) |
