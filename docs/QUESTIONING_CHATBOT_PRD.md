# 질문하기 수업 HTML 보드형 챗봇 PRD

## 1. 목적

교사가 성취기준을 고르고, 학생 평가 루브릭을 확인한 뒤, 수업 자료 이미지를 넣어 자료 범위 안에서만 작동하는 질문 도우미 챗봇을 준비하는 보드형 도구를 만든다.

이 챗봇은 학생 대신 정답을 작성하지 않는다. 학생이 수업 자료를 바탕으로 질문을 만들고, 질문 유형을 확인하며, 자료 속 근거를 찾고, 더 나은 질문으로 고쳐 쓰도록 돕는다.

구현은 두 개의 HTML 화면으로 나눈다.

- 교사용 보드: `/questioning-board`
- 학생용 질문 도우미 챗봇: `/questioning-chatbot`

## 2. 핵심 사용자

| 사용자 | 사용 목적 |
| --- | --- |
| 교사 | 성취기준 선택, 평가 루브릭 확인, 수업 자료 입력, 챗봇 제작 PRD 준비 |
| 학생 | 수업 자료에 대한 질문, 근거 확인, 질문 수정 |
| 교사/실습생 | 학생 질문 유형, 대화 내용, 개선 제안을 평가·피드백 자료로 활용 |

## 3. 주요 흐름

1. 교사가 학년·교과·단원을 적고 성취기준을 선택하거나 직접 입력한다.
2. 보드는 선택한 성취기준에 맞는 0~5점 평가 루브릭을 만든다.
3. 교사가 수업 재료 이미지를 업로드하고, 필요하면 자료 요약을 직접 보완한다.
4. AI가 이미지 내용을 분석해 자료 요약, 핵심 개념, 질문 씨앗, 오개념 가능성을 정리한다.
5. 교사용 보드는 학생용 챗봇에 들어갈 제작 PRD와 설정을 생성한다.
6. 학생용 챗봇은 교사용 보드 설정을 읽어 자료 범위 안에서만 짧게 답한다.
7. 챗봇은 질문을 사실·추론·적용·성찰 질문으로 분류하고, 근거 확인과 질문 개선을 안내한다.
8. 교사는 학생의 첫 질문, 근거 표시, 고친 질문, 성찰 문장, 챗봇 피드백을 평가 자료로 활용한다.

## 4. 기능 요구사항

| 영역 | 요구사항 |
| --- | --- |
| 성취기준 선택 | 기본 성취기준 샘플과 직접 입력 모드를 제공한다. |
| 루브릭 제작 | NIE 루브릭 제작 흐름을 반영해 성취기준·자료 연결, 자료 근거 확인, 질문 유형 확장, 질문 개선·성찰을 0~5점으로 제시한다. |
| 루브릭 토글 | 교사용 보드에서는 전체 루브릭을 하나의 토글로 펼쳐 확인한다. |
| 이미지 자료 입력 | 교사가 이미지를 업로드하고 미리 볼 수 있다. |
| AI 자료 분석 | OpenAI API 키가 있으면 이미지 내용을 분석한다. API 키가 없으면 교사가 직접 요약을 입력해 사용할 수 있다. |
| 챗봇 제작 PRD | 교사용 보드의 5번 영역에서 학생용 챗봇에 반영할 수업 정보, 지식베이스, 루브릭, 기록 필드, 안전 규칙을 정리한다. |
| 학생용 질문 챗봇 | 수업 자료 요약과 성취기준 범위 안에서만 답한다. |
| 질문 분류 | 사실 질문, 추론 질문, 적용 질문, 성찰 질문, 범위 밖 질문, 안전 확인으로 분류한다. |
| 평가 자료화 | 학생 질문, 질문 유형, 근거 확인, 고친 질문, 성찰 문장, 교사 피드백 문장을 기록한다. |
| 안전장치 | 개인정보, 정답 대필, 자료 밖 질문, 원문 전체 복사 요청을 제한한다. |

## 5. 평가 루브릭 구조

NIE 수업의 루브릭 제작 방식처럼 점수만 제시하지 않고, 교사가 실제 산출물에서 볼 수 있는 관찰 증거와 다음 피드백 방향을 함께 제공한다.

| 항목 | 관찰 증거 | 배점 |
| --- | --- | --- |
| 성취기준·자료 연결 | 첫 질문, 근거 표시, 답 확인 메모에서 성취기준의 핵심 행동이 드러나는가 | 0~5점 |
| 자료 근거 확인 | 챗봇 답을 자료 속 문장·장면·표로 다시 확인했는가 | 0~5점 |
| 질문 유형 확장 | 사실 질문에서 추론·적용·성찰 질문으로 사고가 확장되는가 | 0~5점 |
| 질문 개선·성찰 | 처음 질문을 고쳐 쓰고 개선 이유를 설명하는가 | 0~5점 |

## 6. 챗봇 응답 규칙

1. 답변은 2-4문장으로 짧게 한다.
2. 수업 자료 요약·핵심 개념·교사 메모 안에서만 답한다.
3. 질문 유형을 사실·추론·적용·성찰 중 하나로 분류한다.
4. 자료 밖 질문은 추측하지 않고 수업 자료와 연결된 질문으로 돌린다.
5. 이름, 연락처, 사진 속 학생 식별 정보, 상담 정보 입력은 금지한다.
6. 활동지 정답 전체 작성이나 수행평가 대필은 거절하고 사고 단계를 안내한다.
7. 모든 답변 뒤에 자료 속 근거를 찾도록 안내한다.

## 7. 테스트 케이스

| 테스트 | 입력 예시 | 기대 동작 |
| --- | --- | --- |
| 사실 질문 | 자료에서 확인할 수 있는 문제는 무엇인가요? | 자료 요약 안에서 답하고 근거 위치 확인을 요구한다. |
| 추론 질문 | 왜 이런 일이 생겼을까요? | 단서 기반 설명을 하되 추측과 근거를 구분한다. |
| 적용 질문 | 우리 반에서는 어떻게 해결할 수 있나요? | 조건과 실천 가능성을 따져 보게 한다. |
| 성찰 질문 | 내 질문은 더 좋아질 수 있나요? | 질문의 명확성, 자료 연결, 다음 질문을 점검한다. |
| 범위 밖 질문 | 오늘 급식은 뭐예요? | 자료 밖 질문임을 알리고 수업 질문으로 전환한다. |
| 개인정보 | 제 이름과 전화번호는... | 개인정보 입력 금지를 안내한다. |
| 정답 대필 | 활동지 답을 다 써 주세요. | 대필을 거절하고 생각할 순서를 안내한다. |

## 8. 구현 메모

- 교사용 보드 경로: `/questioning-board`
- 학생용 챗봇 경로: `/questioning-chatbot`
- API 경로: `/api/questioning-board/analyze-image`, `/api/questioning-board/chat`
- OpenAI 모델: `OPENAI_QUESTIONING_MODEL`, 없으면 `OPENAI_EVALUATION_MODEL`, 없으면 기본 모델 사용
- 이미지와 대화 내용은 기본적으로 저장하지 않는다.
- 교사용 보드와 학생용 챗봇은 같은 브라우저의 `localStorage` 설정으로 연결한다.
- API 키가 없을 때도 교사가 직접 자료 요약을 입력하면 로컬 분류·피드백 모드로 사용할 수 있다.
