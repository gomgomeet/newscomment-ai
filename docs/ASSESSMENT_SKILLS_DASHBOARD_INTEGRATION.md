# 두 평가 스킬의 과정중심평가 대시보드 반영

## 목적

평가 준비 스킬과 자동채점 스킬을 별개의 프롬프트로 끝내지 않고, 한 수업활동 안에서 다음 순서로 실행되게 한다.

`Feed Up 평가설계 → 1~3건 시험 채점 → 교사 검토 → Feedback → Feed Forward`

챗봇 활동과 NIE 댓글처럼 서로 다른 활동은 각각 별도의 수업활동과 평가설계를 갖는다. 여러 활동의 결과는 나중에 학생 성장 추세를 볼 때만 함께 해석하며, 한 활동의 기준으로 다른 활동을 직접 채점하지 않는다.

## 구현된 흐름

1. 교사는 수업활동에 루브릭을 연결한다.
2. `3F 평가 작업 흐름`에서 성취기준, 평가목표, 핵심 질문, 학습 증거, 판단 보류 조건을 기록한다.
3. 실제 Notion DB의 학생·결과물·피드백 속성 이름을 기록한다.
4. 교사가 설계를 승인하면 `assessment-spec-v1`으로 저장된다.
5. AI 초안 생성은 승인된 설계가 있을 때만 실행된다.
6. 처음 3건은 시험 채점으로 표시하고, 이후 결과는 일괄 채점 단계로 표시한다.
7. AI는 기준별 점수와 근거, 종합 피드백, 다음 활동을 위한 피드포워드를 제안한다.
8. 교사는 결과를 `유지`, `수정`, `보류` 중 하나로 검토하여 저장한다.

## 저장 데이터

- `projects.assessment_spec`: 평가 준비 스킬이 만든 승인 계약
- `evaluations.rubric_version`: 채점에 사용한 평가설계 버전
- `evaluations.execution_id`: AI 실행 식별자
- `evaluations.evaluation_stage`: `manual`, `trial`, `batch`
- `evaluations.review_status`: `pending`, `kept`, `revised`, `held`
- `evaluations.feedforward`: 다음 활동에서 시도할 구체적 방향

## 적용 순서

1. Supabase에 `supabase/migrations/007_assessment_skill_workflow.sql`을 적용한다.
2. 앱을 배포하거나 로컬에서 실행한다.
3. 기존 수업활동 하나를 열고 루브릭을 확인한다.
4. 평가설계를 작성하되 처음에는 승인하지 않고 저장 결과를 확인한다.
5. 교사 승인 후 익명화된 실제 결과물 1~3건으로 AI 초안을 만든다.
6. 점수·근거·피드백을 원문과 대조하여 유지·수정·보류한다.
7. 시험 채점에서 기준이 흔들리면 설계 버전을 올려 다시 승인한다.
8. 안정된 뒤 남은 결과물을 처리하고 기준별 평균과 우선 검토 학생을 확인한다.

## 현재 범위와 다음 보완

현재 버전은 한 건씩 AI 초안을 생성해 시험 3건을 꼼꼼히 검토하는 초보자용 흐름이다. 다음 단계에서는 시험 3건의 교사 검토가 끝난 경우에만 3~5건 일괄 실행을 허용하고, 보류 사유 및 평가 버전별 재채점 이력을 별도 화면으로 제공한다.
