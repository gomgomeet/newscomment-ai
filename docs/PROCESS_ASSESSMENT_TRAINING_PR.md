## 1. 이번 교안 개편의 결론

연수명은 **노션×Claude로 완성하는 과정중심평가**로 확정한다. 이 연수는 도구 기능을 나열하는 수업이 아니라, 백워드 설계로 평가기준을 먼저 만들고 Claude의 평가 초안을 교사가 검수한 뒤 그 결과를 다음 학습과 학생기록으로 연결하는 3차시 실습이다.

최종 흐름은 다음과 같다.

`성취기준 → 평가기준안·루브릭 승인 → NIE 결과물 → Claude 자동채점 초안 → 교사 원문 검수 → 최종평가 → 피드백·평가 포워드 → Notion 결과 페이지 저장 → 3F 보드 → 다음 수업 → 후속 결과 → 성장 확인 → 학생기록 준비`

핵심 원칙은 세 가지다.

- 학생 결과물을 본 뒤 평가기준을 사후에 만들지 않는다.
- Claude 결과는 교사가 검토할 초안이며 최종평가는 교사가 확정한다.
- 후속 결과가 없으면 성장이나 향상을 확정하지 않는다.

현재 교안의 기준 페이지는 [노션×Claude로 완성하는 과정중심평가](https://app.notion.com/p/3c9c5f01a4a481208db0f4254f039211)다.

## 2. 교안 범위와 제외 범위

### 이번 3차시에서 반드시 다루는 것

- 성취기준에서 평가목표·성공 기준·수용 가능한 증거·루브릭을 먼저 설계한다.
- 복제한 NIE Notion 템플릿과 준비된 실제 사례를 사용한다.
- Claude–Notion 평가 스킬로 결과물 한 건의 자동채점 초안을 만든다.
- 교사가 학생 원문과 승인된 루브릭으로 유지·수정·보류를 결정한다.
- 승인된 교사 판단·피드백·평가 포워드만 Notion 최종 결과 페이지에 저장한다.
- 3F 과정중심평가 보드에서 다음 수업, 후속 결과, 1회성·누적 학생기록으로 연결한다.

### 이번 핵심 실습에서 제외한 것

- 질문중심 챗봇 수업과 챗봇 제작 실습
- 결과물을 보고 평가기준을 만드는 사후 기준 설정
- Google Sheets, 캡처 이미지, PDF·Word 전체 문서의 자동 수집·평가
- 개인별 Notion 템플릿 자동 생성과 학생별 페이지 일괄 생성
- AI가 교사 확인 없이 최종평가나 학생기록을 확정하는 기능
- 웹 평가보드의 현재 OpenAI 평가 결과를 Claude 결과라고 안내하는 것

Google Sheets·이미지·PDF·Word는 다출처 평가의 후속 확장 경로로 기록한다. 이번 연수는 **Notion 페이지 연결과 NIE 결과물 한 건의 평가 완주**에 집중한다.

## 4. 1차시: 결과물보다 평가 설계를 먼저 한다

1차시는 결과물을 살펴보고 평가기준을 정하는 시간이 아니다. 기존 NIE 수업 설계 교수안의 백워드 설계를 따라 다음 순서로 운영한다.

1. 성취기준에서 학생이 이해해야 할 핵심 아이디어를 정한다.
2. 수업이 끝났을 때 학생이 보여 줄 수행과 수용 가능한 증거를 정한다.
3. 평가과제와 성공 기준을 설계한다.
4. 수준별 기술문이 포함된 루브릭 초안을 만든다.
5. 활동–증거–평가기준의 정렬을 확인하고 교사가 버전을 승인한다.
6. 승인된 루브릭으로 익명 샘플 한 건의 Notion AI 초안 화면만 짧게 확인한다.

Notion AI 시연은 평가기준 설계보다 앞설 수 없다. AI 영역과 교사 영역을 분리하고, 원문이나 기사 맥락을 읽지 못하면 `확인 불가`로 남긴다.

## 5. 2차시: Claude 초안을 교사 최종평가로 바꾼다

2차시의 주제는 Notion AI와 Claude의 독립 비교가 아니다. **Claude–Notion 평가 스킬로 결과물 한 건을 읽고 자동채점 초안을 만든 뒤, 교사가 검수하고 승인된 결과만 다시 Notion에 저장하는 기본 평가 과정**을 완주하는 것이다. Notion AI 비교는 보조 설명이나 선택 확장으로만 사용한다.

### 시연 프로토콜

1. **읽기 전 확인**
   - 연수용 데모 공간인지 확인한다.
   - 학생·기사·원본 제출 Relation과 익명화 여부를 확인한다.
   - 1차시에서 승인한 루브릭 버전을 고정한다.
2. **읽기 전용 점검**
   - Claude에게 아직 평가하거나 수정하지 말고 대상 URL·학생 ID·관계·빠진 자료만 보고하게 한다.
3. **AI 초안 작성**
   - 평가 요소별 제안 수준·점수, 직접 근거, 기준 연결, 불확실성, 강점·보완점, 피드백·평가 포워드 초안을 만든다.
   - 최초 실행에서는 AI 초안 영역만 쓴다.
4. **교사 검수**
   - 학생 원문과 수준별 기술문으로 유지·수정·보류를 결정한다.
   - 수정 이유와 추가로 필요한 근거를 남긴다.
5. **저장 전 재확인**
   - Claude가 저장 대상 페이지와 필드의 현재값→새값을 먼저 보여 준다.
6. **명시적 승인 후 저장**
   - 교사가 검수 완료와 저장 대상을 명시한 경우에만 교사 판단·피드백·평가 포워드·평가 버전을 쓴다.
   - 저장 뒤 실제 값과 3F 진행 상태를 다시 읽어 확인한다.

연결이 실패하면 익명 원문과 승인된 루브릭을 복사·붙여넣어 같은 검수 과정을 수행하고, 승인된 결과만 Notion에 직접 기록한다. 연결 성공 자체가 수료 기준은 아니다.

## 6. Claude–Notion 연결 방식

초보자 연수에서는 **검증된 플러그인 또는 공식 Notion 커넥터**를 우선한다.

- Claude Code·Cowork에서는 Notion MCP, 평가 Skill, 명령, 안전 규칙을 한 묶음으로 배포할 수 있는 플러그인이 절차 재현에 유리하다.
- 일반 Claude 웹에서는 `클로드 평가 데모 ZIP`과 공식 Notion 커넥터를 사용한다.
- 공식 연결은 참가자가 Notion 내부 통합 토큰을 직접 입력하는 수업이 아니라 사용자 OAuth 승인 방식으로 안내한다.
- 연결된 Claude는 사용자가 접근할 수 있는 Notion 범위에서 읽고 쓸 수 있으므로 실제 학생 자료가 있는 전체 교사 계정보다 데모 워크스페이스를 사용한다.
- 평가보드 서버의 단일 `NOTION_API_KEY`와 참가자의 Claude–Notion OAuth 연결은 서로 다른 경로다.

연결 과정은 [사전 준비｜Claude와 Notion 연결·권한 점검하기](https://app.notion.com/p/3cac5f01a4a4815b9dc3c86d27d846ee)에 분리했다. 교안 본 수업에서는 연결 설정 자체보다 **읽기 확인 → 초안 → 교사 검수 → 승인 후 쓰기**를 학습 성취로 본다.

### Claude 웹 배포본

Claude 웹은 ZIP 하나를 하나의 Custom Skill로 등록하므로 `edu-rubric`과 `edu-evidence-judge` 폴더를 ZIP 최상위에 나란히 넣지 않는다. 대신 최상위 Skill 하나가 두 차시 모듈을 선택하도록 구성했다.

- 배포 이름: **클로드 평가 데모 ZIP**
- 파일: [`claude-evaluation-demo.zip`](../public/downloads/claude-evaluation-demo.zip)
- Skill 내부 이름: `notion-evaluation-demo` (`claude`는 예약어이므로 YAML `name`에 사용하지 않음)
- 1차시 모듈: 백워드 설계 기반 평가기준안·루브릭 설계
- 2차시 모듈: Notion 읽기 확인 → Claude 평가 초안 → 교사 검수 → 피드백·평가 포워드 → 승인 후 결과 저장
- Claude 웹 등록: `Customize → Skills → + → Create skill → Upload a skill`에서 ZIP을 풀지 않고 업로드한 뒤 활성화
- Notion 접근: ZIP에 토큰을 넣지 않고 Claude의 공식 Notion 커넥터를 별도로 OAuth 연결
- 연결 실패: 익명 원문과 승인된 루브릭을 복사·붙여넣는 대체 경로 사용

기존 개별 스킬 파일은 개발·검수용 원본으로 유지한다. 연수 참가자에게는 통합 ZIP 하나만 배포한다.

## 7. 3차시: 3F 보드를 실제 수업 운영에 사용한다

3차시는 새 피드백 문장을 처음부터 만드는 시간이 아니다. 2차시에서 완성한 최종 결과 페이지를 보드에서 추적하여 다음 수업과 후속 결과, 학생기록으로 연결한다.

기본 상태는 다음과 같다.

`1 피드업 → 2 근거 수집 → 3 Claude 초안 → 4 교사 검토 → 5 피드백 → 6 피드포워드 → 7 후속 확인 → 8 기록 준비 → 완료`

### 교안에서 사용하는 핵심 보기

| 보기 | 수업에서 하는 일 |
| --- | --- |
| ⑭ 처리 가능한 결과물 | Relation과 원본 제출이 확인된 평가 대상을 찾는다. |
| ⑮ 3F 진행 현황 요약 | 학생별 평가가 현재 어느 단계에 있는지 확인한다. |
| ⑲ 교사 검토 대기 | Claude 분석 뒤 교사 확정이 남은 결과를 처리한다. |
| ⑥ 피드백·피드포워드 | 강점·수정 행동·완료 기준을 다음 수업 활동으로 바꾼다. |
| ⑰ 후속 결과 대기 | v2·새 과제·교사 관찰을 연결하고 변화를 확인한다. |
| ⑱ 기록 준비 후보 | 교사 확인과 근거가 갖춰진 미확정 기록을 찾는다. |
| ⑧ 학생기록 준비 | 1회성·누적 학생기록 초안과 근거 맵을 교사가 검수한다. |

[3F 과정중심평가 연결 허브](https://app.notion.com/p/3c9c5f01a4a481a990cdddd7f6e4b58d)는 수업 자료, 학생 제출, 평가 결과와 보드 보기를 연결하는 진입점이다. [3F 과정중심평가 보드 v0.1](https://app.notion.com/p/bd8e535783674f6c8d9fabcb665766e6)은 처리 공간이다.

### 보드 사용 주기

- 매 수업 전: 처리 가능한 결과물과 루브릭 버전, Relation, 개인정보를 확인한다.
- 제출 직후: 누락·중복·오연결을 정리하고 소수 사례부터 Claude 초안을 만든다.
- 교사 검수 시간: 교사 검토 대기에서 유지·수정·보류를 확정한다.
- 다음 수업 설계 전: 반복되는 어려움을 찾아 개별·소그룹·전체 지원을 결정한다.
- 후속 제출 뒤: v1과 v2를 같은 기준으로 비교해 실제 변화·부분 변화·미확인을 구분한다.
- 월말·학기말: 학생별 시간순 확정 근거를 검토해 1회성·누적 학생기록을 구분한다.

### 학생기록 판단

- 교사 확정 평가 한 건은 해당 활동의 **1회성 학생기록 초안**으로만 사용한다.
- 여러 시점의 교사 확정 평가와 비교 가능한 직접 근거가 있을 때만 **누적 종합 학생기록 초안**을 만든다.
- 후속 결과가 없거나 활동 목표가 달라 비교할 수 없으면 성장 기록을 만들지 않고 `미확인` 또는 `작성 보류`로 남긴다.
- AI가 학생기록을 확정하지 않으며 교사가 학교·교육청 지침과 실제 수업 맥락으로 최종 수정한다.

[① 결과처리 전체](https://app.notion.com/p/bd8e535783674f6c8d9fabcb665766e6?v=8efd436d5bac47358c0350f1992aba1d)는 필터가 없는 관리자용 전체 목록이다. 현재 1~3차시, 연결 허브, 초보 교사용 실행 안내에서는 이 보기의 이름이나 링크를 사용하지 않는다.

2026-08-28 점검 시점에는 24건이 표시됐으며 교사 확인 미완료 20건, 부분 연결 19건, 개인정보 확인 미완료 23건이 섞여 있었다. 따라서 연수 화면이나 참가자 실습에는 적합하지 않다.

결정은 다음과 같다.

- 교안과 참가자 실습에서는 사용하지 않는다.
- 삭제하지 않고 `🔒 관리자용｜전체 결과 원본`으로 이름을 바꾸어 마지막 순서에 보존하는 방안을 권장한다.
- 누락 기록, 필터 오류, 상태값 이상을 점검할 때만 관리자 보조 보기로 사용한다.
- 실제 이름 변경과 보기 순서 조정은 별도 승인 후 수행한다.

## 9. 템플릿과 평가자료 확장 원칙

이번 연수에서는 강사가 제공한 NIE 기본 템플릿을 참가자가 복제하고, 복제된 결과 페이지를 평가 흐름에 연결한다. Notion 안에서 평가 템플릿을 자동 생성하는 기능은 후속 방법으로 남긴다.

평가자료 입력은 세 경로를 장기 구조로 유지한다.

1. Notion 전체 페이지 링크 읽기
2. Google Sheets의 학생별 행·탭과 수정 이력 읽기
3. 캡처 이미지·PDF·Word 등 파일형 결과물 읽기

이번 3차시의 집중 경로는 1번이다. 2번과 3번은 평가 근거의 확장 가능성을 소개하되 참가자 필수 실습이나 수료 기준에 넣지 않는다.

## 10. 교사 권한과 안전 규칙

- AI 초안 영역과 교사 최종평가 영역을 분리한다.
- 학생 원문, 승인된 루브릭, 수식 속성은 AI가 수정하지 않는다.
- 교사 확인은 교사가 명시적으로 승인한 경우에만 `완료`로 바꾼다.
- Relation이 불명확하거나 개인정보가 남은 행은 분석·저장 대상에서 제외한다.
- 실제 학생 자료와 합성·재구성 사례를 같은 공개 보기에 섞지 않는다.
- 원본 결과물은 덮어쓰지 않고 v1·v2를 별도 근거로 보존한다.
- 다른 활동은 같은 학생의 결과라도 자동 합산하지 않는다.
- 웹 평가보드가 사용하는 실제 모델과 연수에서 안내하는 모델 명칭을 일치시킨다.
