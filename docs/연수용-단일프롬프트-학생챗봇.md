# 연수용 단일 프롬프트 — 나만의 학생 질문 챗봇 만들기

수강 선생님이 **이 한 덩어리만 복사해서** Gemini나 Claude에 붙여 넣으면
`.html` 파일 하나가 나옵니다. 그 파일을 더블클릭하면 바로 학생용 챗봇이 열립니다.

- 서버·설치·회원가입이 필요 없습니다. 파일 하나로 끝납니다.
- Gemini API 키를 넣으면 답이 훨씬 자연스러워지고, 키가 없어도 지문 기반으로 동작합니다.
- 완성 예시가 궁금하면 `webapp/질문챗봇-단일HTML.html`을 열어 보세요.

## 쓰는 순서

1. 아래 프롬프트를 통째로 복사합니다.
2. 맨 위 `■ 내 수업` 세 칸(학년 / 과목·성취기준 / 지문)을 내 수업으로 고칩니다.
3. Gemini(또는 Claude)에 붙여 넣습니다.
4. 나온 코드를 메모장에 붙여 넣고 `질문챗봇.html`로 저장합니다. **인코딩은 UTF-8.**
5. 더블클릭 → 선생님 화면에서 지문·인원을 확인 → [학생 화면 시작].

> **API 키 주의**
> 키는 챗봇 화면에서 선생님이 직접 입력하고 **그 브라우저에만** 저장됩니다.
> 프롬프트나 HTML 파일 안에 키를 절대 적지 마세요. 파일을 학생과 공유하면 키까지 넘어갑니다.
> 무료 키는 입력 내용이 구글 모델 개선에 쓰일 수 있으니, 학생 글이 오가는 실제 수업에서는
> 결제를 등록한 키를 쓰세요.

## 이 프롬프트는 어떻게 생겼나 — 8개 블록

길어 보이지만 **`■` 표시 여덟 덩어리**일 뿐입니다. 구조를 알면 고칠 곳이 보입니다.

| 블록 | 무엇을 정하나 | 교사가 손대나 |
| --- | --- | --- |
| 머리말 3줄 | 역할과 출력 형식(코드만, 설명은 세 줄) | ✖ |
| **■ 내 수업** | 학년 · 성취기준 · 지문 | **⭕ 여기만** |
| ■ 이 챗봇이 하는 일 | 정답 대필이 아니라 질문을 돕는 도구라는 정체성 | ✖ |
| ■ 화면 구성 | 선생님 화면 / 학생 화면 / 기록 세 화면 | △ 입력칸을 더하고 싶을 때만 |
| ■ 답변 엔진 | **Gemini 호출 방법 + 키 없을 때의 대체** | ✖ |
| ■ 대화 규칙 15개 | 답의 품질을 결정하는 핵심 | △ 내 수업에 맞게 더해도 됨 |
| ■ 내장 엔진 | 키 없이도 이만큼은 돼야 한다는 최저선 | ✖ |
| ■ 기술 조건 | 단일 파일 · UTF-8 · 한글 엔터 처리 | ✖ |
| ■ 마지막으로 | 코드 내놓기 전 스스로 돌려볼 아홉 마디 | ✖ |

**대화 규칙 15개가 왕드입니다.** 나머지는 그릇을 만드는 설명이고, 답이 어색해지는 것은
거의 다 이 15개 중 한 줄이 무너졌기 때문입니다. 브라우저에서 5회 돌리며 실제로 깨졌던
것만 모아 쓴 줄들입니다.

## ⭕ 교사가 직접 적어야 하는 칸 — 딱 세 개

| 칸 | 어떻게 쓰나 | 비워 두면 |
| --- | --- | --- |
| **학년** | `4학년`처럼 숫자로. 답변의 말 높이가 여기서 정해집니다 | 중학생처럼 말해서 아이들이 못 알아듣습니다 |
| **성취기준** | 코드와 문장을 그대로. 매 턴 끌고 가지 않고 대화의 나침반으로만 씁니다 | 대화가 엉뚱한 데로 퍼집니다 |
| **지문** | 학생이 읽을 글 **전문을 그대로**. 요약하지 마세요 | 챗봇이 근거로 들 문장이 없어 답을 지어냅니다 |

**선택으로 더하면 좋은 것** — 프롬프트가 아니라 **완성된 챗봇 화면에서** 넣습니다.

- **어려운 낱말 뜻** (`잔반: 먹고 남은 밥이나 반찬`) — 넣으면 어휘 답변이 확 좋아집니다.
  비워 두면 "사전 뜻은 제가 가진 자료에 없어서 지어내지 않을게요"라고 정직하게 말합니다
- **학급 인원** — 번호 고르기 목록이 만들어집니다
- **대화 방향 메모** — 챗봇이 참고만 하고 학생에게 그대로 말하지는 않습니다
- **Gemini API 키** — 아래 유의사항을 꼭 읽으세요

## ⚠️ 유의사항

**1. 키를 프롬프트나 HTML에 적지 마세요.** 키는 완성된 챗봇 화면의 입력칸에 넣고, 그
브라우저에만 저장됩니다. 파일 안에 적으면 **학생과 공유하는 순간 키가 그대로 넘어갑니다.**

**2. 학생 기기에는 키 없는 파일을 주세요.** 키 없이도 지문 기반으로 동작합니다. 또는 교사
기기 한 대를 모둠이 돌아가며 씁니다.

**3. 무료 키는 시연용으로만.** 무료 키는 입력 내용이 구글 모델 개선에 쓰일 수 있습니다.
**학생 글이 오가는 실제 수업에서는 결제를 등록한 키**를 쓰세요.

**4. 지문은 저작권을 확인하세요.** 교과서 본문을 통째로 옮기지 말고, 기사는 출처를 밝혀 쓰세요.

**5. 학생 실명을 받지 않는 것이 설계입니다.** 번호만 고르게 되어 있고, 이름을 말하면
부드럽게 되돌립니다. 편하자고 이름칸을 더하면 개인정보가 됩니다.

**6. 메모장 저장 시 인코딩을 UTF-8로.** ANSI로 저장하면 한글이 전부 깨집니다.

**7. 만들자마자 나눠 주지 말고 아홉 마디를 먼저 쳐 보세요.** 아래 점검표가 그 목록입니다.

**8. 챗봇 답은 항상 교사가 확인합니다.** 지문에 근거하게 만들었지만 AI는 틀릴 수 있습니다.
학생에게 "답을 믿지 말고 자료에서 다시 찾자"라고 말해 주세요 — 그게 이 수업의 목표이기도 합니다.

## 복사할 프롬프트

```text
너는 초등 교사와 함께 수업 도구를 만드는 개발자야.
아래 조건을 모두 만족하는 **단일 HTML 파일 하나**를 완성해서 코드만 출력해.
설명은 코드 뒤에 세 줄 이내로만 붙여.

■ 내 수업 (여기만 고쳐서 쓰세요)
- 학년: 4학년
- 성취기준: [4국02-02] 글에서 중심 생각을 파악한다
- 지문:
"""
(여기에 학생이 읽을 글 전체를 붙여 넣으세요)
"""

■ 이 챗봇이 하는 일
학생이 위 지문을 읽고 궁금한 점을 물으면, 지문에 근거해서 답해 주고
스스로 더 좋은 질문을 하도록 돕는다. 정답을 대신 말해 주는 도구가 아니다.

■ 화면 구성 (파일 하나 안에 전부)
1. 선생님 화면 — 자료 이름, 지문, 학년, 학급 인원, 성취기준, 어려운 낱말 뜻
   (`낱말: 뜻` 형식 여러 줄), 대화 방향 메모, Gemini API 키 입력칸.
   [학생 화면 시작] [이 브라우저에 저장] [기록 내려받기] 버튼.
2. 학생 화면 — 자료 이름과 지문 전문을 위에 보여 주고, 그 아래에 대화창.
   학생은 **번호만 고르고 시작한다. 이름은 절대 묻지 않는다.**
3. 기록 — 번호·질문·답변·시각을 표로 보여 주고 CSV로 내려받게 한다.
   CSV는 엑셀에서 한글이 깨지지 않게 BOM을 붙인다.

■ 답변 엔진 (두 갈래, 반드시 둘 다 넣을 것)
- 키가 있으면: Gemini API를 브라우저에서 직접 호출한다.
  `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent`
  에 POST, 헤더 `x-goog-api-key`. 지문·학년·성취기준·낱말 뜻·아래 대화 규칙을
  systemInstruction에 담고, 최근 대화 8개를 contents에 함께 보낸다.
  temperature 0.4.
- 키가 없거나 호출이 실패하면: **말없이 죽지 말고** 지문에서 문장을 찾아 답하는
  내장 엔진으로 넘어가고, 화면 아래에 "AI 연결이 잠시 막혀 지문에서 찾아 답했어요"라고
  한 줄 알린다.
- 키는 localStorage에만 저장한다. 코드 안에 키를 하드코딩하지 않는다.

■ 대화 규칙 (Gemini 지시문과 내장 엔진에 똑같이 적용)
1. 지문에 없는 사실을 지어내지 않는다. 없으면 "그건 이 글에 나오지 않아요"라고
   정직하게 말하고 함께 확인할 질문으로 남기자고 한다.
2. 학생이 물으면 **먼저 답한다.** 되묻기는 그다음이다.
3. 한 턴에 물음표는 하나까지. 질문 없이 설명만 하고 끝내도 된다.
4. 낱말 뜻은 **두 걸음으로** 답한다. 처음 물으면 짧은 사전 뜻만.
   학생이 "이 글에서는?"이라고 이어 물을 때 그 낱말이 쓰인 지문 문장을 근거로
   문맥 뜻을 설명한다. 직전에 물어본 낱말을 기억해야 한다.
5. 지문 문장을 인용할 때는 "자료에는 "…"라고 나와 있어요"처럼 **감싼다.**
   기사 문체(-한다, -했다)가 챗봇 존댓말에 그대로 섞이면 말투가 어긋난다.
   단, 문장 한가운데 넣을 때는 감싸는 말 없이 따옴표만 쓴다. 안 그러면
   "…나와 있어요. 여기에 쓰였어요"처럼 두 번 맺는 문장이 된다.
6. 학생이 한 말을 그대로 되풀이하지 않는다. 특히 학생의 **질문**을
   "…라고 짚었군요"로 받지 않는다. 질문은 되받을 것이 아니라 답할 것이다.
7. 인사에는 인사로 답한다.
8. 까닭을 물으면 **원인을 밝힌 문장**(때문에·덕분에·-아져서)을 근거로 든다.
   낱말만 겹치는 문장은 답이 아니다.
9. 같은 근거 문장을 연달아 두 번 쓰지 않는다. 마무리 발문도 서너 개를 돌려 쓴다.
   같은 문장이 반복되면 대화가 아니라 안내문이 된다.
10. 학생이 그만하고 싶어 하면 새 과제를 주지 말고 따뜻하게 마친다.
11. 이름·전화번호 같은 개인정보를 묻지 않는다. 학생이 이름을 말하면
    "번호만으로 충분해요"라고 부드럽게 알린다.
12. "답 대신 써 줘" 같은 부탁은 들어주지 않는다. 대신 학생이 자기 생각에서
    시작할 작은 한 걸음을 안내한다.
13. "몰라요"라고만 답하면 다그치지 말고, 첫 문장을 보여 주며
    낯선 낱말 하나만 짚어 보게 한다.
14. 수업과 상관없는 딴 이야기는 나무라지 말고 부드럽게 글로 데려온다.
    다만 **자료 밖 질문과 딴소리는 다르게 받는다.** 질문은 정직하게 "없다"고
    답하고, 딴소리는 "그 이야기도 재미있겠네요"로 받아 준다.
15. 위 학년 눈높이로 2~4문장. 어려운 말은 풀어 쓴다.

■ 내장 엔진이 지켜야 할 것 (키 없이도 이만큼은 되어야 함)
- 지문을 문장 단위로 자르되, **마크다운 제목·목록·물음표로 끝나는 줄은 근거로 쓰지 않는다.**
  제목 줄을 근거라고 내미는 것이 가장 흔한 실수다.
- 낱말을 찾을 때 한국어 조사(은/는/이/가/을/를/에서/이라는…)를 떼고 본다.
  '석 달이' → '석 달'처럼 띄어쓴 낱말도 살려야 한다.
- 조사를 붙일 때는 받침을 보고 고른다. "잔반은/배식은"이지 "잔반는"이 아니다.
  '은(는)' 같은 표기를 학생에게 그대로 보이면 안 된다.
- 숫자·수량("42킬로그램")과 "그래서 결론이 뭐야" 같은 말은 낱말 질문이 아니다.
  낱말로 오인해서 "사전에 없어요"라고 답하지 않게 판정을 좁힌다.
- "결론/요약/중심 생각"을 물으면 첫 문장과 마지막 문장을 이어 보여 준다.

■ 기술 조건
- 외부 라이브러리·CDN·빌드 도구 없이 순수 HTML/CSS/JS 한 파일.
- `<meta charset="utf-8">` 필수. 모바일에서도 읽히게 반응형.
- 엔터로 보내고 Shift+엔터는 줄바꿈. **한글 조합 중 엔터는 보내지 않는다**
  (`e.isComposing` 확인). 이걸 빠뜨리면 글자를 치다가 문장이 잘려 나간다.
- localStorage 접근은 try/catch로 감싼다. 저장이 막혀도 수업은 굴러가야 한다.
- 학생 입력을 화면에 넣을 때 HTML로 해석되지 않게 처리한다.

■ 마지막으로
코드를 내놓기 전에 스스로 이 흐름을 점검해:
"안녕하세요" → "(낱말)이 뭐예요?" → "이 글에서는 어떤 뜻이야" → "왜 그렇게 됐어요?"
→ "몰라요" → "답 대신 써 줘" → "내 이름은 ○○이야" → "나 배고파" → "그만할래요".
아홉 개 모두 서로 다른 답이 나와야 하고, 어느 하나도 지문에 없는 사실을 말하면 안 돼.
```

## 만들고 나서 5분 점검

프롬프트 마지막의 아홉 마디를 그대로 쳐 보세요. 연수 준비 중 실제로 걸렸던 것들입니다.

| 학생이 한 말 | 이렇게 나오면 고쳐야 함 |
| --- | --- |
| `잔반이 뭐예요?` | `‘잔반’는 …` — 받침에 맞는 조사가 아님 |
| `이 글에서는 어떤 뜻이야` | 앞 낱말을 잊고 엉뚱한 답 — 2단계 어휘가 빠짐 |
| `42킬로그램이 뭐예요` | "사전에 없어요" — 숫자를 낱말로 오인 |
| `그래서 결론이 뭐야` | "‘그래서 결론’을 찾지 못했어요" — 판정이 너무 넓음 |
| `우리 학교도 하면 좋겠다` | "…라고 짚었군요" — 학생 말을 그대로 되풀이 |
| `내 이름은 ○○이야` | 이름을 받아 적음 — 개인정보 규칙 누락 |
| `답 대신 써 줘` | 답을 써 줌 |
| `나 배고파` | 자료 밖 질문과 똑같이 처리 |
| 같은 질문 두 번 | 완전히 같은 문장 반복 |

한 줄이라도 걸리면 그 줄을 그대로 Gemini에 붙여 넣고
"이 경우에 이렇게 나오는데 규칙 ○번대로 고쳐 줘"라고 이어 말하면 됩니다.

## 수업에서 쓰는 흐름

1. 선생님 화면에 지문과 인원을 넣고 [이 브라우저에 저장].
2. 파일을 학생 기기에 나눠 줍니다. **키를 넣은 파일을 그대로 주지 마세요.**
   학생 기기에서는 키 없이(지문 기반) 쓰거나, 교사 기기 한 대를 모둠이 돌아가며 씁니다.
3. 수업이 끝나면 [기록 내려받기]로 CSV를 받아 질문을 살펴봅니다.
   번호만 남으므로 그대로 두어도 개인정보가 되지 않습니다.
