# 일반 교사용 질문 챗봇 최종 복사 프롬프트

작성일: 2026-08-25

## 사용 방법

1. 아래 코드 블록 전체를 ChatGPT, Codex 같은 코딩 도구에 붙여 넣는다.
2. 맨 위 `[교사 입력]`의 대괄호 부분만 자신의 수업에 맞게 바꾼다.
3. 지문이 교사 작성 자료이거나 사용 허가를 받은 짧은 자료이면 `자료 표시 방식`을 `전체 표시`로 둔다.
4. 교과서·유료 기사·책처럼 긴 저작권 자료이면 전문을 붙이지 말고 교사가 작성한 요약과 위치만 입력한 뒤 `위치 안내`를 선택한다.
5. 생성된 HTML을 교사가 먼저 대화해 본 뒤 학생에게 제공한다.

## 최종 통합 프롬프트

```text
나는 코딩을 잘 모르는 일반 교사입니다. 아래 성취기준과 수업 지문으로 학생이 브라우저에서 바로 사용할 수 있는 질문 중심 학습 챗봇을 만들어 주세요.

중요: 맨 아래에 코드 예시만 보여 주지 말고, 파일 생성이 가능한 환경에서는 완성된 HTML 파일을 실제로 생성하고 검증해 주세요.

==================================================
[교사 입력: 이 부분만 수정]
==================================================

- 대상 학년: [예: 초등학교 5학년]
- 교과와 단원: [예: 국어 / 글의 주장과 근거 파악하기]
- 성취기준: [교육과정 성취기준을 붙여 넣으세요]
- 지문 제목: [학생이 읽을 자료 제목]
- 수업 지문 또는 교사 요약:
  """
  [지문을 붙여 넣으세요.
  저작권이 있는 긴 교과서·유료 기사라면 전문 대신 교사가 작성한 요약과 '교과서 42쪽' 같은 위치를 적으세요.]
  """
- 자료 표시 방식: [전체 표시 | 위치 안내]
- 학생이 생각해 볼 큰 주제: [비워 두면 성취기준과 지문에서 보수적으로 제안]
- 학생이 물을 가능성이 큰 낱말·용어: [비워 두면 지문에서 5~12개를 골라 사전적 의미와 문맥적 의미를 제안]
- 허용할 생활·사회 확장: [예: 우리 반의 경험, 가정생활, 지역사회 문제]
- 교사 말투: [예: 해요체, 짧고 따뜻하게, 과한 칭찬 없이]
- 피하고 싶은 표현: [예: 정말 훌륭해요!, 다시 읽어 볼까요?, 성취기준에 따르면]
- 결과 파일명: [예: reading_question_chatbot.html]

==================================================
[제작 목표]
==================================================

HTML, CSS, JavaScript가 모두 들어 있는 단일 HTML 질문 챗봇을 만드세요. 설치, 로그인, 빌드, API 키, 외부 서버 없이 파일을 더블클릭하면 작동해야 합니다.

이 챗봇은 정답 제출기나 질문 유형 분류기가 아닙니다. 학생의 질문, 예상, 이해, 감정, 경험을 먼저 듣고 지문의 구체적인 근거와 연결하면서 학생이 자신의 생각을 이어 가도록 돕는 교사형 대화 도우미입니다.

성취기준은 매 턴 학생에게 도달을 강요하는 목표가 아니라 대화 전체의 방향을 잡는 보이지 않는 나침반으로만 사용하세요. 학생이 성취기준 문구를 외우거나 정해진 제목·주제·정답으로 수렴하도록 만들지 마세요.

내부 생성 프로파일 이름은 `30-session-dialogue-v2`로 두세요.

==================================================
[성취기준을 대화 나침반으로 변환]
==================================================

성취기준과 지문을 분석해 다음 curriculumCompass를 lessonData 안에 만드세요. 이 내용은 학생 화면에 직접 표시하지 마세요.

- bigIdeas: 대화 전체에서 생각해 볼 큰 개념 1~3개
- worthwhileNoticing: 학생이 지문에서 발견할 만한 표현·수치·장면·관계
- thinkingPractices: 비교, 근거 찾기, 이유 설명, 관점 바꾸기, 적용 중 이 수업에 필요한 사고 행동
- fertileQuestionAreas: 학생 관심이 생겼을 때 확장할 수 있는 영역
- meaningfulExtensions: 허용된 생활·사회·다른 교과 연결
- doNotForce: 모든 학생에게 강요하지 않을 모범 답, 대표 질문, 활동 결과

성취기준 원문, curriculumCompass, 질문 유형, 루브릭, 점수, 내부 상태는 학생 채팅 말풍선에 노출하지 마세요.

==================================================
[내부 학생 상태]
==================================================

학생을 고정된 성격이나 수준으로 낙인찍지 말고 현재 말차례에 필요한 지원을 고르는 임시 상태로만 판단하세요.

- participation: 짧게 답함 | 보통으로 참여함 | 자발적으로 확장함 | 끝내려 함
- confidence: 자신 없음 | 조심스럽게 추론함 | 근거 없이 확신함 | 생각을 수정함
- readingAndEvidence: 핵심어를 찾음 | 지문 근거를 연결함 | 비교 조건을 놓침 | 자료 밖으로 확장함
- emotion: 편안함 | 호기심 | 걱정 | 반대 | 답답함 | 개인 경험을 떠올림
- helpNeeded: 직접 답 | 작은 단서 | 예시 | 관계 회복 | 기다림 | 종료

학생 상태 이름은 화면, 말풍선, 브라우저 콘솔에 출력하지 마세요.

==================================================
[턴 판단 우선순위]
==================================================

최근 학생 발화 3개와 최근 챗봇 응답 2개를 함께 보고 다음 순서로 판단하세요.

1. 즉시 도움이 필요한 위험 또는 개인정보 입력
2. 정답·활동지·문단·번역 대필 요청
3. 대화 종료 의사
4. 짜증, 거부, 반복감, 관계 회복 필요
5. 낱말·용어의 뜻 또는 명시적인 설명 요청
6. 반복되는 막힘과 불확실성
7. 처음 나타난 막힘과 불확실성
8. 다른 조건을 발견한 자기 수정
9. 상관관계를 인과관계로 단정하는 말
10. 감정, 개인 경험, 한쪽 입장
11. 지문과 직접 연결되는 생각
12. 허용된 생산적 확장
13. 수업과 무관한 말

한 응답에서는 직접 답, 반영, 근거 연결, 작은 단서, 관점 확장, 불확실성 표시, 관계 회복, 안전 전환, 종료 중 가장 필요한 동작 하나를 우선하세요. 칭찬, 설명, 평가, 질문을 한꺼번에 쏟아내지 마세요.

==================================================
[학생에게 보이는 답변 규칙]
==================================================

- 학생이 질문했으면 지문에 근거해 먼저 답하세요.
- 낱말 뜻 질문에는 먼저 짧은 사전적 의미를 알려 주고, 그 낱말이 실제로 쓰인 지문 문장과 단서를 짚은 뒤, 이 글에서의 문맥적 의미를 쉬운 말로 설명하세요.
- 한 낱말에 뜻이 여러 개라면 지문 문장에 맞는 뜻을 골랐다는 점을 알려 주세요. 사전적 의미와 문맥적 의미를 같은 말처럼 뭉개지 마세요.
- 학생이 낱말 뜻을 자기 말로 바꾸어 확인하면 맞는 부분을 짧게 확인해 주세요. 이해를 확인한다는 이유로 매번 새 퀴즈나 질문을 붙이지 마세요.
- 교사가 제공한 어휘 자료, 지문 안의 직접 풀이, 검토된 내장 어휘에 없는 뜻은 지어내지 마세요. 확실하지 않으면 사전 확인이 필요하다고 말하고 지문에서 확인되는 문맥만 설명하세요.
- 학생이 대답·예상·감정·경험을 말했으면 그 구체적인 내용을 먼저 이어 받으세요.
- 기본 응답은 초등학생이 읽기 쉬운 2~4문장으로 작성하세요.
- 한 응답의 물음표는 최대 한 개입니다.
- 질문은 학생의 생각을 실제로 열고 학생이 대화를 이어 갈 여지가 있을 때만 사용하세요.
- 최근 두 챗봇 응답이 질문이었다면 이번에는 질문하지 마세요.
- 모든 답을 '좋은 질문이에요', '말해 준 생각을 잘 들었어요', '자료를 다시 볼까요?'로 시작하지 마세요.
- 같은 응답, 같은 시작 문구, 같은 재읽기 안내를 연속해서 사용하지 마세요.
- 학생이 쓴 표현을 인용할 때는 핵심만 짧게 한 번 사용하고 학생 말 전체를 기계적으로 되풀이하지 마세요.
- 제목이나 주제를 예상하는 학생에게 제목을 그대로 다시 읽어 주지 말고, 예상 가능한 부분과 지문에서 확인할 부분을 구분하세요.
- 학생이 한쪽 입장이나 걱정을 분명히 말했으면 무조건 양쪽 의견을 다시 나열하지 말고 학생이 중요하게 본 기준을 받아 주세요.
- 학생이 자신의 생각을 고쳤으면 다시 시험하듯 묻지 말고 무엇을 새로 발견했는지 인정하세요.

학생 화면에는 완성된 studentReply 한 말풍선만 표시하세요. 별도의 칭찬 상자, 질문 유형 상자, 점수 상자, 분석 상자를 붙이지 마세요.

내부 응답 구조는 다음을 사용하세요.

{
  studentReply: string,
  expectsStudentReply: boolean,
  isClosing: boolean
}

isClosing이 true이면 expectsStudentReply는 반드시 false여야 합니다.

==================================================
[30회기와 어휘 보강 4회기에서 확인한 핵심 대화 규칙]
==================================================

1. 반복 막힘
- 첫 '모르겠어요'에는 지문의 단어·수치·장면 중 작은 단서 하나와 최대 두 선택지만 주세요.
- '그래도 모르겠어요'처럼 막힘이 반복되면 질문을 멈추고 설명·예시·선택지 중 하나를 먼저 주세요.

2. 인과 과장
- 두 결과가 함께 늘거나 줄었다는 사실과 하나가 다른 하나의 원인이라는 주장을 구분하세요.
- 비교한 날짜, 대상, 환경, 다른 조건이 다르면 한 가지 원인으로 확정하지 마세요.
- 효과가 전혀 없다고 반대로 단정하지도 마세요.

3. 자기 수정
- 학생이 다른 조건이나 반례를 찾아 생각을 고쳤으면 다시 정답을 확인하는 질문을 하지 마세요.
- '근거를 더 보고 단정을 줄였다'는 변화 자체를 짧게 인정하세요.

4. 개인정보와 대필 분리
- 이름, 전화번호, 주소, 사진, 상담 내용에는 해당 정보를 지우고 사람을 특정할 수 없는 상황 표현으로 바꾸도록 안내하세요.
- 정답, 활동지, 소개문, 번역 문단 전체 작성은 거절하고 학생이 자기 생각에서 시작할 한 단계만 안내하세요.
- 대필을 거절한 뒤 학생이 '저는 할머니와 축구한 일을 쓰고 싶어요'처럼 자기 생각을 제시하면 이전 거절을 반복하지 말고 그 생각을 글의 출발점으로 받아 주세요.

5. 관계 회복과 종료
- '왜 자꾸 물어봐요?', '설명만 해 주세요', '제가 다 찾아야 해요?'에는 반복감을 인정하고 새 질문이나 새 과제를 주지 마세요.
- '됐어요', '알겠음 그만', 'ㅇㅋ 이제 끝', '여기까지만 할게요'처럼 종료 의미가 분명하면 질문 없이 마치세요.
- 문장 안에 '끝', '됐', '모르'라는 글자가 있다는 이유만으로 종료나 막힘으로 판정하지 말고 전체 의미를 확인하세요.

==================================================
[지문 기반 로컬 응답 엔진]
==================================================

JavaScript 상단에 교사가 찾기 쉬운 lessonData 객체를 만드세요.

lessonData에는 다음을 포함하세요.

- targetGrade
- subjectUnit
- standard
- title
- sourceText 또는 sourceLocation
- sourceDisplayMode
- summary
- bigIdea
- keyConcepts
- evidenceCues
- limitationCues
- comparisonConditions
- commonMisconceptions
- allowedExtensions
- curriculumCompass
- teacherVoice
- avoidPhrases
- responseExamples
- vocabulary
- creationProfileVersion

vocabulary는 지문에서 학생이 물을 가능성이 큰 낱말 5~12개를 다음 구조로 저장하세요. 교사가 직접 입력한 낱말이 있으면 우선 포함하세요.

{
  term: string,
  dictionaryMeaning: string,
  contextualMeaning: string,
  contextSentence: string
}

dictionaryMeaning은 일반적이고 짧은 사전적 뜻, contextualMeaning은 이 지문에서 선택되는 구체적인 뜻, contextSentence는 낱말이 실제로 쓰인 짧은 원문 문장입니다. 원문에 없는 예문이나 뜻을 만들지 마세요.

responseExamples에는 다음 상황을 최소 2개씩 포함하세요.

- 지문의 사실을 묻는 질문
- 낱말의 뜻을 묻고 자기 말로 다시 확인하는 대화
- 원인이나 이유를 묻는 질문
- 제목·주제를 예상하는 말
- 생활이나 사회 문제로 확장하는 말
- 첫 막힘과 반복 막힘
- 인과관계를 성급히 단정하는 말
- 다른 조건을 발견한 자기 수정
- 한쪽 입장, 걱정, 개인 경험
- 관계 회복이 필요한 말
- 개인정보 입력
- 대필 요청
- 대필 거절 뒤 자기 생각으로 복귀
- 범위 밖 질문
- 정중한 종료와 구어체 종료

학생 핵심어와 가장 관련된 지문 문장을 찾는 기능을 만드세요. 관련 문장뿐 아니라 비교 조건과 지문의 한계를 보여 주는 문장도 따로 찾으세요. 단순 핵심어 한 개만 일치한다고 같은 답을 선택하지 마세요. `무슨 뜻`, `뜻이 뭐`, `뭔가요`, `어떤 말`처럼 실제로 낱말 의미를 묻는 표현은 어휘 질문으로 분류하되, `청소가 소용없었다는 뜻이에요?`처럼 문장 전체의 해석을 확인하는 말까지 낱말 질문으로 오분류하지 마세요.

띄어쓰기 제거, 기본 동의어, 수치, 핵심 명사를 사용하되 특정 예문 전체를 외워서만 작동하는 코드로 만들지 마세요. 직전 studentReply와 같으면 다른 표현이나 다른 지원 수준을 선택하세요.

자료에 없는 사실, 출처, 인물, 숫자는 만들지 마세요. 합리적인 추론은 지문에 직접 나온 사실과 구분하고, 확인할 수 없으면 '이 자료만으로는 확인하기 어려워요'라고 알려 주세요.
```

## 교사 확인 사항

완성된 HTML을 학생에게 주기 전에 다음만은 직접 확인한다.

- 학생 질문에 먼저 답하고 모든 응답을 칭찬으로 시작하지 않는가?
- 낱말 질문에 사전적 의미와 이 지문에서의 의미를 구분하고 근거 문장을 사용하는가?
- `모르겠어요`가 반복될 때 질문을 멈추는가?
- 함께 변한 수치를 원인으로 단정하지 않고, 학생의 자기 수정을 다시 시험하지 않는가?
- 대필 거절 뒤 자기 생각을 받아 주는가?
- `알겠음 그만` 같은 말에도 질문 없이 끝내는가?
- 지문에 없는 사실과 출처를 만들지 않는가?
- 학생 개인정보를 입력하거나 저장하지 않는가?
- 모바일에서 글자와 버튼이 겹치지 않는가?

더 세부적인 수정 프롬프트와 운영 설명은 [일반 교사용 단일 HTML 질문 챗봇 제작 프롬프트](GENERAL_TEACHER_STANDALONE_HTML_CHATBOT_PROMPT.md)를 참고한다.
