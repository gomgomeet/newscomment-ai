# Notion × Claude 자동채점

Notion 평가 DB에 쌓인 학생 결과물을 교사가 승인한 평가 준비안과 루브릭으로 자동채점하고, AI 점수·직접 근거·피드백·피드포워드·처리 상태를 기록한다.

## 선행조건

자동채점 전에 `notion-claude-assessment-prep`으로 확정한 다음 정보가 있어야 한다.

- 활동명과 대상 학년
- 성취기준 또는 평가 목표
- 평가 영역 2~4개
- 영역별 수준 설명과 점수 범위
- 평가할 결과물 원문 속성
- 학생 식별 속성
- 기사·지문 원문 또는 원문 연결 방식
- AI 결과를 기록할 속성
- 판단 유보 조건

준비안이 없거나 루브릭이 승인되지 않았으면 자동채점을 시작하지 않는다. 먼저 평가 준비 스킬을 실행하거나, 사용자에게 준비안을 승인받는다.

## 평가 실행 명세 검증

`notion-claude-assessment-prep`이 생성한 `assessment-spec-v1` 명세를 읽고 다음을 검증한다.

- 승인 상태가 `승인`인가
- 활동 ID·루브릭 버전·평가 기준 ID가 있는가
- 모든 기준에 점수 범위와 수준 설명이 있는가
- 실제 DB 속성 매핑과 허용 상태값이 있는가
- 판단 유보 조건과 수정 금지 속성이 있는가
- 시험 채점 건수와 배치 크기가 있는가

누락되거나 DB 스키마와 불일치하면 자동으로 추정하지 않는다. 1번 스킬로 명세를 보완한 뒤 다시 시작한다.

## 시작 시 받을 Notion 링크

- 학생 결과물·제출물 DB 링크
- 평가 결과를 기록할 DB 링크
- 기사·지문 DB 또는 원문 페이지 링크
- 평가 준비안·루브릭 페이지 링크가 있으면 그 링크
- 학생 명단 DB 링크 또는 비식별 ID 사용 여부

링크를 받은 뒤 읽기·편집 권한, 데이터소스, 실제 속성명과 속성 유형을 확인한다. 속성명을 추측하지 않는다.

## 채점 전 확인표

실제 DB에 쓰기 전에 다음을 사용자에게 짧게 보여 주고 승인을 받는다.

- 활동명과 평가 대상 행 수
- 적용할 성취기준·평가 목표
- 평가 영역과 점수 범위
- 읽을 원문 속성
- 기록할 AI 속성
- 수정하지 않을 교사 속성
- 시험 채점할 첫 1~3건

사용자가 이미 동일한 대상·루브릭·기록 범위를 명시적으로 승인한 현재 작업에서는 중복 승인을 요구하지 않는다.

## 채점 대상 선정

1. 기본 대상은 AI 분석 상태가 비어 있거나 `대기`인 행이다.
2. 사용자가 학생 ID, 활동, 기사, 기간을 지정하면 해당 조건만 적용한다.
3. 재채점은 사용자가 명시한 경우에만 수행한다.
4. 서로 다른 활동은 같은 배치에 섞지 않는다.
5. 배치는 같은 활동·같은 루브릭 기준으로 3~5건씩 처리한다.

## 기사·지문 확인

기사 이해나 지문 근거를 평가하는 영역은 반드시 원문과 학생 결과물을 함께 읽는다.

- 원문이 확인되면 영역별 근거와 정확성을 평가한다.
- 원문 연결이 없거나 읽을 수 없으면 기사 이해·사실 정확성·기사와 생각 연결 영역은 점수를 확정하지 않고 `판단 유보`로 둔다.
- 의견의 명료성처럼 결과물만으로 확인 가능한 영역은 루브릭이 허용할 때 별도로 채점할 수 있다.
- 원문 부재를 낮은 점수로 자동 변환하지 않는다.

## 자동채점 절차

각 결과물마다 다음 순서로 처리한다.

1. 학생 ID, 결과물 ID, 활동명을 확인한다.
2. 결과물 원문을 보존하고 평가에 사용한 문장을 직접 근거로 추출한다.
3. 기사·지문 원문과 대조한다.
4. 승인된 루브릭의 각 영역을 지정 점수 범위의 정수로 채점한다.
5. 각 점수에 직접 근거와 판단 이유를 붙인다.
6. 평가에 필요한 근거가 없으면 해당 영역을 유보한다.
7. 학생 눈높이의 피드백을 작성한다.
8. 다음 활동에서 시도할 행동이나 질문을 피드포워드로 작성한다.
9. AI 분석 상태를 `완료`, `교사 검토 필요`, `판단 유보`, `오류` 중 실제 DB가 지원하는 값으로 기록한다.

## 결과 기록

DB의 실제 속성과 다음 역할을 매핑한다. 속성이 없으면 새 속성 생성 여부를 사용자에게 확인한다.

- 영역별 AI 점수
- AI 총점 또는 자동 수식
- 기준별 직접 근거
- AI 평가 초안
- 학생 피드백
- 평가 포워드
- AI 확신도 또는 판단 유보 사유
- 분석 상태
- 평가 버전과 평가일
- 평가 실행 ID
- 루브릭 버전
- 재채점 여부
- 이전 AI 점수 또는 이전 평가 기록 링크

한 행의 여러 AI 속성은 가능하면 한 번의 업데이트로 기록한다. 수식·롤업·읽기 전용 속성은 직접 쓰지 않는다.

## 수정 금지 영역

- 교사 영역별 점수
- 교사 총점과 교사 최종 판단
- 교사 피드백
- 교사 확인 상태
- 학생 원문
- 학생기록·세특 최종 문장
- 기존 Relation과 원본 링크

AI 자동채점은 교사 최종 평가를 덮어쓰지 않는다.

## 실행 이력과 재채점

- 자동채점 실행마다 고유한 평가 실행 ID를 만든다.
- 같은 결과물·같은 루브릭 버전의 완료 기록이 있으면 기본적으로 건너뛴다.
- 재채점은 사용자가 요청한 경우에만 수행하고 이전 AI 결과를 보존한다.
- 가능하면 학생 제출 행을 덮어쓰기보다 별도 AI 평가 실행 DB에 새 기록을 만들고 제출물과 연결한다.
- 기존 DB에 직접 기록해야 한다면 이전 점수·루브릭 버전·평가일을 이력 속성에 남긴다.

## 피드백 작성

피드백은 2~4문장으로 쓴다.

1. 원문에서 확인한 강점
2. 현재 활동에서 보완할 한 가지
3. 학생이 시도할 수 있는 구체적 행동 또는 질문

찬성·반대 입장 자체, 글의 길이, 맞춤법만으로 높은 점수나 낮은 점수를 주지 않는다.

## 피드포워드 작성

피드포워드는 다음 활동에서 확인할 행동과 증거를 한 가지로 좁힌다.

```text
현재 근거 → 보완할 점 → 다음 활동의 행동 → 확인할 새 결과물
```

다른 활동의 결과를 현재 활동 점수에 합산하지 않는다.

## 시험 채점과 일괄 기록

1. 먼저 1~3건의 채점 초안을 채팅에 보여 준다.
2. 점수, 근거, 피드백, 피드포워드가 루브릭과 일치하는지 확인한다.
3. 승인 후 같은 기준으로 나머지 배치를 기록한다.
4. 한 행의 기록 실패가 전체 배치를 중단시키지 않게 해당 행만 `오류`로 격리한다.
5. 배치마다 처리 건수와 오류 건수를 확인한다.

## 교사 검토와 결과 확정 지원

자동채점 이후 별도 스킬로 넘기지 않고 다음 검토 흐름을 이어서 지원한다.

1. 다음 행을 교사 우선 검토 대상으로 모은다.
   - 판단 유보 또는 낮은 AI 확신도
   - 기준별 점수 차이가 큰 행
   - 기사 원문 연결이 불완전한 행
   - 재채점된 행
   - 교사 판단과 AI 점수가 크게 다른 행
2. 각 행에 학생 원문, 직접 근거, AI 점수, 판단 이유를 나란히 제시한다.
3. 교사가 `유지`, `수정`, `보류` 중 하나를 선택하도록 돕는다.
4. 교사 수정 내용은 AI 결과를 덮어쓰지 않고 교사 영역에 별도로 기록한다.
5. 교사가 확인한 피드백을 학생 전달용 문장으로 정리한다.
6. 학생별 피드포워드와 학급의 공통 어려움을 묶어 다음 수업 활동을 제안한다.
7. 후속 결과물이 들어오면 이전 활동 점수를 다시 계산하지 않고 새로운 증거로 비교한다.

교사 승인 없이 교사 최종 점수, 교사 확인 상태, 학생기록을 자동 확정하지 않는다.

## 학급 경향과 다음 수업

개인별 채점 완료 후 필요할 때 다음을 요약한다.

- 공통 강점과 공통 어려움
- 가장 많이 유보된 평가 기준
- 다음 수업에서 다시 확인할 핵심 증거
- 소그룹 지원이 필요한 기준
- 다음 활동의 질문·모델링·수정 과제

학생 순위보다 어떤 기준에서 어떤 지원이 필요한지를 중심으로 제시한다.

## 완료 보고

- 활동명과 적용 루브릭 버전
- 조회한 행, 채점 완료, 판단 유보, 오류 건수
- 영역별 평균과 분포는 사용자가 요청하거나 수업 성찰에 필요할 때만 제시
- 교사가 우선 검토할 행과 이유
- 기록한 AI 속성과 수정하지 않은 교사 속성
- 다음 활동 설계에 참고할 공통 피드포워드
- 교사 검토의 유지·수정·보류 건수
- 학급 공통 경향과 다음 수업 제안

자동채점 결과를 교사 확정 평가나 학생기록으로 표현하지 않는다.
