# Google Apps Script 판 질문 챗봇 — 2국면 반영 설계 · 2026-09-05

연수용 챗봇은 지금 두 판이다. 더블클릭으로 여는 **단일 HTML**과 Vercel·Supabase 위의 **Next.js 웹앱**. 이 문서는 그 사이에 **세 번째 판**을 둔다 — 교사의 구글 계정 하나로 돌아가는 **Google Apps Script(GAS) 웹앱**이다. 여기에 웹앱의 2국면(질문 4개 뒤 챗봇이 이해→성취기준→의견 순으로 되묻기)을 그대로 넣는다.

## 1. 왜 세 번째 판인가

단일 HTML의 구조적 한계 두 가지가 GAS에서는 저절로 풀린다.

| 단일 HTML의 한계 | GAS에서는 |
| --- | --- |
| **기록이 학생 기기에만 남는다** — 교사가 모을 길이 없다 | 모든 턴이 교사의 **구글 시트 한 장**에 쌓인다. 수업 중에 열어 보면 된다 |
| **API 키가 브라우저에 있다** — 학생에게 파일을 주면 키가 넘어간다 | 키는 **스크립트 속성**에만 있다. 학생 화면에는 절대 내려가지 않는다 |
| 학생용 링크가 파일 배포에서는 무의미 | 배포하면 **주소 하나**가 나온다. QR로 띄우면 끝 |
| 2국면 상태를 브라우저마다 따로 들고 있어야 한다 | 상태를 시트에서 매 턴 다시 센다 — 웹앱과 같은 방식 |

Next.js 웹앱과 견주면 잃는 것도 있다.

| | 단일 HTML | **GAS 웹앱** | Next.js 웹앱 |
| --- | --- | --- | --- |
| 필요한 것 | 파일 하나 | 구글 계정 + 시트 하나 | Vercel·Supabase·Notion |
| 설치 시간 | 0분 | **15분** (붙여 넣기 → 속성 → 배포) | 반나절 |
| 학생 접속 | 파일 열기 | 링크 | 링크 + 수업 코드 |
| 기록 | 기기별 localStorage | **시트** | Supabase + Notion |
| 2국면 | 없음 (P1 ⑧) | **있음 (이 문서)** | 있음 |
| 채점 신호 | 없음 | **세는 것만** (점수 판정은 교사) | 4항목 0~5점 |
| 생각 카드·리서치 | 없음 | 없음 | 있음 |
| 동시 접속 | 제한 없음 | **약 30** (GAS 동시 실행 한도) | 제한 없음 |
| 응답 지연 | 즉시 / Gemini 2~4초 | Gemini 2~4초 **+ GAS 1~2초** | Gemini 2~4초 |

한 학급(24~30명)이 한 시간 쓰는 수업이면 GAS 한도 안에 든다. 학년 전체가 동시에 쓰면 넘친다 — 그때는 Next.js 판이다.

## 2. 전체 구조

```text
학생 브라우저 (index.html)
   │  google.script.run.chat({cls, num, text})
   ▼
Code.gs  doGet / chat()
   ├─ Sheet.gs     설정 읽기, 대화 읽기·쓰기 (LockService)
   ├─ Phase.gs     2국면 상태기 — 대화 시트에서 매 턴 다시 센다
   ├─ Gemini.gs    UrlFetchApp → generateContent (키는 스크립트 속성)
   ├─ Local.gs     키 없거나 실패 시 지문 기반 답 (단일 HTML 로컬 엔진 이식)
   └─ Signals.gs   답에서 신호 찾기 (lib/questioning-target-signals.ts 이식)
   ▼
구글 시트: 설정 · 대화 · 결과 · 현황
```

**상태를 따로 저장하지 않는다.** 웹앱 `applyQuestioningConversationPhase()`처럼, 이 학생의 대화 행을 시트에서 읽어 "지문 관련 질문이 몇 개였나, B1을 이미 썼나, 2국면 질문 중 무엇을 물었나"를 매 턴 다시 센다. 상태 시트가 따로 있으면 동시 쓰기에서 어긋난다.

### 시트 네 장

| 시트 | 열 | 누가 쓰나 |
| --- | --- | --- |
| `설정` | 자료 이름 · 지문 · 학년 · 성취기준 · 낱말표(`낱말: 뜻`) · 대화 방향 메모 · 반별 인원 · 수업 코드 | 교사가 손으로 |
| `대화` | 시각 · 반 · 번호 · 역할(학생/챗봇) · 내용 · 국면 · 질문종류 · 난이도 · 응답점수 · 근거문장 · 엔진 · 미리보기 | 스크립트가 턴마다 |
| `결과` | 반 · 번호 · 스스로 만든 질문 수 · 지문 관련 질문 수 · 이해 응답 최고 · 성취기준 응답 최고 · 의견 응답 · 더 알아볼 질문 · 도달 난이도 · **교사 판정(빈 열)** | 스크립트가 턴마다 갱신, 교사가 마지막 열 |
| `현황` | 반 · 인원 · 참여 · 미제출 번호 | 수식 (`결과`에서) |

`결과`의 숫자는 **센 것**이지 점수가 아니다. 웹앱 원칙("모델에게 몇 점이냐고 묻지 않는다")을 그대로 둔다. 4항목 0~5점 판정은 `lib/questioning-conversation-phase.ts`의 `evaluation()` 규칙을 옮기면 되지만, 첫 판에서는 세는 것까지만 하고 판정은 교사 열에 맡긴다. `현황`은 `claude/google-sheets-plan` 브랜치의 A3 안(보드에는 참여 현황만, 대화 전문은 시트에서)과 같다.

## 3. 2국면 상태기 — `Phase.gs`

웹앱 로직을 그대로 옮긴다. 다른 점은 입력이 `conversation` 배열이 아니라 `대화` 시트의 행이라는 것뿐이다.

```javascript
// Phase.gs — 2국면 상태기. lib/questioning-conversation-phase.ts 이식.
const B1 = "혹시 지문에서 모르는 단어나 이해하기 어려운 문장이 있나요?";
const B2 = "혹시 글에 대해서 질문하기가 어려우면 제가 질문해도 될까요? 제 질문에 대한 답을 지문에서 찾아보세요.";
const Q_COMPREHENSION_MID = "글에서 가장 중요한 사실 한 가지를 찾아 자기 말로 말해 줄래요?";
const Q_COMPREHENSION_HIGH = "글에 나온 결과와 그 까닭을 구분해서 말해 줄래요?";
const Q_OPINION = "이 글을 읽고 어떤 생각이나 느낌이 들었어? 네 생각이 궁금해.";

/**
 * 이 학생의 대화 행(시간순)과 현재 발화로 다음 동작을 정한다.
 * 반환: { phase: 1|2, managedQuestion: string|"", allowQuestion: boolean, kind, difficulty, feedback }
 */
function decidePhase(rows, currentTurn, settings) {
  const targets = buildStandardTargets(settings.standard, settings.memo);   // Signals.gs
  const student = rows.filter(r => r.role === "학생").map(r => r.text);
  const bot = rows.filter(r => r.role === "챗봇");
  const asked = bot.map(r => classifyBotQuestion(r.text, targets)).filter(Boolean);
  const b1Used = bot.some(r => r.text.includes(B1));
  const b2Used = bot.some(r => r.text.includes(B2));
  const related = [...student, currentTurn].filter(t => isPassageRelatedQuestion(t, settings)).length;
  const protectedMove = isClosing(currentTurn) || isRepair(currentTurn) || isSafety(currentTurn);

  if (protectedMove) return { phase: asked.length ? 2 : 1, managedQuestion: "", allowQuestion: false };

  // B1에 "없어요" → B2 → 2국면
  const last = bot[bot.length - 1];
  if (last && last.text.includes(B1) && NO_DIFFICULTY.test(currentTurn)) {
    return { phase: 2, managedQuestion: B2, allowQuestion: true, kind: "b2" };
  }
  // 2국면: 이해(중) → 이해(상/하) → 성취기준 표적 ≤2 → 의견
  if (asked.length > 0 || b2Used || related >= 4) {
    const lastQ = asked[asked.length - 1] || null;
    const score = lastQ ? answerScore(lastQ, currentTurn, settings) : 0;     // Signals.gs
    const next = nextPhaseQuestion(asked, lastQ, score, targets, settings);
    return { phase: 2, managedQuestion: next.text, allowQuestion: Boolean(next.text),
             kind: next.kind, difficulty: next.difficulty, feedback: next.feedback, lastScore: score };
  }
  // 1국면인데 3턴 지나도 관련 질문 ≤1 → B1 한 번
  if (!b1Used && student.length + 1 >= 3 && related <= 1) {
    return { phase: 1, managedQuestion: B1, allowQuestion: true, kind: "b1" };
  }
  return { phase: 1, managedQuestion: "", allowQuestion: true };
}

function nextPhaseQuestion(asked, lastQ, score, targets, settings) {
  if (asked.length === 0) return { kind: "comprehension_medium", text: Q_COMPREHENSION_MID, difficulty: "중", feedback: "" };
  const nextDifficulty = score >= 3 ? "상" : "하";
  const support = supportSentence(settings);                                  // 첫 근거 문장
  const feedback = lastQ && lastQ.difficulty === "하" && score <= 2
    ? `여기에는 “${support}”라고 나와 있어요. 이 문장에서 답을 찾을 수 있어요. ` : "";
  if (!asked.some(q => q.kind === "comprehension_followup")) {
    const text = nextDifficulty === "상" ? Q_COMPREHENSION_HIGH
      : `자료의 “${support}”를 다시 봐요. 이 문장에 나온 사실 한 가지는 무엇인가요?`;
    return { kind: "comprehension_followup", text, difficulty: nextDifficulty, feedback };
  }
  const askedKeys = new Set(asked.filter(q => q.kind === "standard").map(q => q.target.key));
  const target = targets.find(t => !askedKeys.has(t.key));
  if (target) {
    const text = nextDifficulty === "하" ? `자료의 “${support}” 이 문장을 먼저 다시 보고 ${target.askTemplate}` : target.askTemplate;
    return { kind: "standard", text, target, difficulty: nextDifficulty, feedback };
  }
  if (!asked.some(q => q.kind === "opinion")) return { kind: "opinion", text: Q_OPINION, difficulty: "중", feedback };
  return { kind: "done", text: "", difficulty: "중", feedback };
}
```

`classifyBotQuestion`·`isPassageRelatedQuestion`·`answerScore`·`buildStandardTargets`(표적 7종 + 기본 1종, `askTemplate` 포함)는 TypeScript 원본을 타입만 걷어 내면 그대로 GAS(V8)에서 돈다. 정규식·문자열 처리뿐이라 옮길 때 바뀌는 것이 없다. **원본과 이식본이 같은 회귀 세트를 통과하는지**는 6절에서 확인한다.

## 4. 질문은 상태기가 소유한다 — Gemini 지시와 후처리

모델에게 "질문을 세어서 네 개가 넘으면 되물어라"라고 시키지 않는다. 모델은 세지 못하고, 셌다고 해도 턴마다 다르게 센다. **어떤 질문을 언제 붙일지는 `Phase.gs`가 정하고, 모델은 학생 말에 답하는 것만 한다.**

### 4-1. 지시문 (systemInstruction)

단일 HTML의 14개 규칙(개선안 P0 ⑤·⑥ 반영 뒤)에 2국면 규칙 세 줄을 더한다.

```text
15. 대화에는 두 국면이 있습니다. 1국면에서는 학생이 묻고 당신이 답합니다.
    되묻지 않습니다. 2국면에서는 학생 말에 먼저 답한 뒤, [지금 할 일]에 적힌
    질문 하나를 마지막 문장으로 붙입니다. 그 밖의 질문은 하지 않습니다.
16. [지금 할 일]에 "질문 없이"라고 적혀 있으면 물음표를 쓰지 않습니다.
17. [지금 할 일]에 피드백 문장이 있으면 그 문장을 답 앞에 그대로 넣습니다.
    학생이 앞 질문에 막혔을 때 볼 곳을 짚어 주는 문장입니다.
```

### 4-2. 턴마다 붙이는 `[지금 할 일]`

`decidePhase()` 결과를 마지막 user 파트 앞에 붙인다.

```javascript
// Gemini.gs
function buildTaskLine(decision) {
  if (!decision.allowQuestion) return "[지금 할 일] 학생 말에 답만 하세요. 질문 없이.";
  if (!decision.managedQuestion) return "[지금 할 일] 1국면입니다. 학생 질문에 답하고 되묻지 마세요.";
  const feedback = decision.feedback ? ` 피드백 문장: "${decision.feedback.trim()}"` : "";
  return `[지금 할 일] 2국면입니다. 학생 말에 먼저 답한 뒤, 마지막 문장으로 이 질문 하나만 붙이세요: "${decision.managedQuestion}"${feedback}`;
}

function geminiReply(history, turn, decision, settings) {
  const key = PropertiesService.getScriptProperties().getProperty("GEMINI_API_KEY");
  const body = {
    systemInstruction: { parts: [{ text: systemPrompt(settings) }] },
    contents: [...history.slice(-8), { role: "user", parts: [{ text: buildTaskLine(decision) + "\n\n" + redact(turn) }] }],
    generationConfig: { temperature: 0.4, maxOutputTokens: 1024, thinkingConfig: { thinkingBudget: 0 } },
  };
  const res = UrlFetchApp.fetch(
    "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent",
    { method: "post", contentType: "application/json", headers: { "x-goog-api-key": key },
      payload: JSON.stringify(body), muteHttpExceptions: true });
  if (res.getResponseCode() === 429) throw new Error("rate_limited");   // 재시도 없이 로컬로
  if (res.getResponseCode() !== 200) throw new Error("gemini_" + res.getResponseCode());
  const data = JSON.parse(res.getContentText());
  const text = (data.candidates?.[0]?.content?.parts || []).map(p => p.text || "").join("").trim();
  if (!text) throw new Error("empty");
  return text;
}
```

### 4-3. 후처리 — 모델이 안 지켜도 결과는 같다

```javascript
// Code.gs
function enforceManagedQuestion(reply, decision) {
  // 모델이 넣은 물음표 문장은 모두 걷어 낸다. 질문은 상태기 것만 남긴다.
  let text = reply.replace(/[^.!?？]*[?？]/g, "").replace(/\s+/g, " ").trim();
  if (!decision.allowQuestion) return text || reply.replace(/[?？]/g, ".");
  if (decision.managedQuestion) {
    if (!text.includes(decision.managedQuestion)) text = [text, decision.feedback, decision.managedQuestion].filter(Boolean).join(" ");
    return text;
  }
  // 1국면: 모델이 스스로 붙인 질문은 하나까지만 허용
  let seen = false;
  return reply.replace(/[?？]/g, () => (seen ? "." : ((seen = true), "?")));
}
```

웹앱의 `appendOneQuestion()`과 같다. 이 한 함수 때문에 **Gemini든 로컬 엔진이든 2국면 질문은 정확히 한 번, 정해진 순서로** 나간다. 로컬 엔진(`Local.gs`)은 단일 HTML `localReply()`를 옮긴 뒤 같은 함수를 거친다.

### 4-4. `chat()` 한 턴

```javascript
function chat(req) {
  const settings = readSettings();
  if (req.code !== settings.lessonCode) return { error: "수업 코드가 다릅니다." };
  const sid = `${req.cls}-${req.num}`;
  const lock = LockService.getScriptLock(); lock.waitLock(10000);
  try {
    const rows = readConversation(sid);
    const decision = decidePhase(rows, req.text, settings);
    let reply, engine = "gemini";
    try { reply = geminiReply(toHistory(rows), req.text, decision, settings); }
    catch (e) { reply = localReply(req.text, rows, settings); engine = e.message === "rate_limited" ? "local(한도)" : "local"; }
    reply = enforceManagedQuestion(reply, decision);
    appendTurn(sid, "학생", req.text, decision, "", req.preview);
    appendTurn(sid, "챗봇", reply, decision, engine, req.preview);
    updateResult(sid, settings);                      // 결과 시트 한 행 갱신 (센 것만)
    return { reply, phase: decision.phase, engine };
  } finally { lock.releaseLock(); }
}
```

`LockService`는 시트 쓰기 순서를 지키기 위한 것이다. 30명이 동시에 보내도 행이 섞이지 않는다. 대신 **잠금 안에서 Gemini를 부르면 한 학생이 4초씩 줄을 세운다** — 실제 구현에서는 Gemini 호출을 잠금 밖으로 빼고, 잠금은 `readConversation` → `appendTurn` 사이만 잡는다. 그러면 상태 판단과 기록 사이에 다른 턴이 끼어들 수 있는데, 같은 학생의 턴은 화면이 `sending` 중이라 못 보내므로 문제가 없다.

## 5. 결과 시트 — 세는 것만

`updateResult()`가 턴마다 이 학생의 행 하나를 다시 쓴다. 모두 `Phase.gs`가 이미 계산한 값이다.

| 열 | 어떻게 세나 | 원본 |
| --- | --- | --- |
| 스스로 만든 질문 수 | 1국면 학생 발화 중 `isCountableStudentQuestion` | `evaluation()` `countableQuestions` |
| 지문 관련 질문 수 | 그중 `isPassageRelatedQuestion` | `relatedQuestions` |
| 이해 응답 최고 | `comprehension_*` 질문 뒤 답의 `scoreComprehensionResponse` 최대 | `comprehensionResponse` |
| 성취기준 응답 최고 | `standard` 질문 뒤 답의 `scoreStandardResponse` 최대 | `standardResponse` |
| 의견 응답 | `opinion` 질문 뒤 답의 `scoreOpinionResponse` | `opinionScore` |
| 더 알아볼 질문 | 셀 수 있는데 지문 관련이 아닌 질문 목록 | `moreToExploreQuestions` |
| 도달 난이도 | 물은 2국면 질문 중 가장 높은 난이도 | `reachedDifficulty` |
| **교사 판정** | 비워 둔다 | — |

이 표는 그대로 `webapp/수업도우미-검수.html`이 읽는 CSV 형식과 맞춘다(개선안 P1 ⑨). 시트를 CSV로 내려받아 떨어뜨리면 미제출 찾기와 루브릭 채점이 이어진다.

## 6. 검증

- **이식 동일성**: `evals/questioning-chatbot/fixtures/sessions.json`의 49회기 학생 발화를 `Phase.gs`에 순서대로 넣고, 웹앱이 낸 `conversationPhase`·2국면 질문 순서·`rubricScores`와 같은지 비교한다. GAS는 `clasp`으로 내려받아 Node에서 그대로 실행할 수 있으므로(V8 문법이 같다) `scripts/run-questioning-dialogue-eval.mjs`에 `--engine=gas` 갈래 하나를 더하면 된다.
- **브라우저**: 단일 HTML 점검 스크립트(`scripts/check-standalone-chatbot.mjs`)의 발화 18개를 배포된 웹앱 주소로 돌린다. 화면 요소 ID를 맞춰 두면 같은 스크립트를 쓴다.
- **2국면 전용 점검**: 지문 관련 질문 4개 → 5번째 답 끝에 `Q_COMPREHENSION_MID`가 정확히 한 번 · 1국면에서 3턴 내내 딴소리 → B1 한 번, 두 번 아님 · B1에 `없어요` → B2 · 2국면 중 `그만할래요` → 질문 없이 종료 · `왜 자꾸 물어봐요` → 물음표 0 · 의견 답 뒤 → 질문 없음.
- **동시성**: 30개 탭에서 같은 초에 전송 → `대화` 시트 행 수 = 60, 반·번호 뒤섞임 없음.

## 7. 교사 배포 절차 (연수용, 15분)

1. 구글 시트 새로 만들기 → `설정`·`대화`·`결과`·`현황` 네 시트 이름 그대로 (템플릿 시트를 복사하면 1분).
2. 확장 프로그램 → Apps Script → `Code.gs` `Phase.gs` `Gemini.gs` `Local.gs` `Signals.gs` `Sheet.gs` `index.html` 붙여 넣기.
3. 프로젝트 설정 → 스크립트 속성 → `GEMINI_API_KEY` 입력. **코드에 키를 적지 않는다.**
4. `설정` 시트에 지문·학년·성취기준·낱말표·반별 인원·수업 코드 입력.
5. 배포 → 새 배포 → 웹 앱 → 실행 계정 **나** · 액세스 **모든 사용자** → 주소 복사 → QR.
6. 교사가 먼저 `미리보기` 체크로 들어가 18개 발화를 쳐 본다. 미리보기 행은 `결과`·`현황`에서 제외된다.

"실행 계정: 나"이므로 학생은 로그인하지 않는다. 대신 주소를 아는 누구나 보낼 수 있으므로 **수업 코드**로 막고, 수업이 끝나면 배포를 **보관**한다.

## 8. 조심할 것

- **한도** — 개인 계정 `UrlFetchApp` 하루 20,000회, 동시 실행 30, 한 실행 6분. 한 학급 한 시간(약 30명 × 15턴 = 450회)은 넉넉하다. 무료 Gemini 키의 분당 한도가 먼저 걸린다 → 429는 재시도 없이 로컬로 넘기고 엔진 열에 `local(한도)`로 남긴다. 교사는 `대화` 시트에서 그 비율을 본다.
- **개인정보** — 시트는 교사 계정에만 있다. 학생 발화는 `redact()`(codex 브랜치 `redactPersonalInformation` 이식)로 이름·전화번호를 가린 뒤 Gemini에 보내고, 시트에도 가린 뒤 적는다. 이름을 밝히면 정해진 문구로 돌린다. 반·번호만 받는다.
- **지연** — GAS 웹앱은 호출마다 1~2초가 붙는다. 화면에 "생각하는 중…"을 반드시 띄우고, 전송 중 다시 보내지 못하게 한다(단일 HTML의 `sending` 플래그).
- **모델이 [지금 할 일]을 무시할 때** — 4-3의 후처리가 잡는다. 모델이 붙인 질문을 지우고 상태기의 질문을 붙이므로, 최악의 경우에도 "답 + 정해진 질문 하나"다.
- **시트가 커질 때** — 한 학기 30회 수업이면 `대화`가 2만 행이다. `readConversation`은 반·번호로 필터해 읽으므로 느려지지 않지만, 학기마다 시트를 새로 만드는 것이 깔끔하다. `설정`의 수업 코드가 시트를 가른다.
- **저작권** — 지문은 `설정` 시트에 교사 자료로만 넣는다. 교과서 본문은 단일 HTML과 같은 원칙(요약·위치)이다.
