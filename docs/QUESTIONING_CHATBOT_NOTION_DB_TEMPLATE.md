# 질문 챗봇 노션 DB 템플릿 안내

질문 챗봇 웹앱을 노션과 연결하려면 수업 준비용 DB와 학생 결과용 DB를 각각 만든다. Notion 토큰은 브라우저에 넣지 않고 서버에서만 사용한다. 1차 구현형은 서버 환경변수에 저장하고, 여러 교사가 함께 쓰는 운영형은 Supabase 같은 서버 저장소에 암호화해 보관한다.

## 1. 챗봇 수업 준비 DB

교사용 보드에서 성취기준, 질문 자료, 평가 루브릭, 챗봇 PRD를 저장하는 DB다.

권장 속성은 다음과 같다.

| 속성 | 유형 | 용도 |
| --- | --- | --- |
| `수업명` | 제목 | 저장되는 수업 준비 페이지 제목 |
| `대상` | 텍스트 | 학년 또는 대상 |
| `교과/단원` | 텍스트 | 교과와 단원 |
| `성취기준` | 텍스트 | 선택 또는 직접 입력한 성취기준 |
| `질문 자료` | 텍스트 | 자료 이름 |
| `학생용 주소` | 텍스트 또는 URL | 학생용 챗봇 주소 |
| `상태` | 상태 또는 선택 | 준비 완료 여부 |
| `저장일` | 날짜 | 저장 시각 |
| `루브릭` | 텍스트 | 평가 루브릭 요약 |
| `챗봇 PRD` | 텍스트 | 챗봇 제작 PRD 요약 |

전체 질문 자료, 성취기준 분석, 루브릭, PRD 전문은 각 DB 행의 페이지 본문에 함께 저장된다.

## 2. 챗봇 수업 결과 DB

학생이 챗봇과 나눈 질문과 답변을 `학교_반_번호` 페이지에 누적 저장하는 DB다.

권장 속성은 다음과 같다.

| 속성 | 유형 | 용도 |
| --- | --- | --- |
| `학교_반_번호` | 제목 | 학생 실명 대신 쓰는 식별값 |
| `수업 자료` | 텍스트 | 질문 자료 이름 |
| `성취기준` | 텍스트 | 연결된 성취기준 |
| `질문 유형` | 선택 또는 텍스트 | 내부 분석 질문 유형 |
| `질문하기` | 숫자 | 1국면에서 스스로 만든 질문의 수와 이어 간 행동 |
| `지문 이해` | 숫자 | 두 국면에서 낱말·사실·관계를 이해한 정도 |
| `성취기준 점수` | 숫자 | 수업의 표적 질문과 응답에서 드러난 도달 정도 |
| `성찰질문과 의견 표현` | 숫자 | 마지막 질문에 자기 생각을 표현한 정도 |
| `총점` | 숫자 | 기준별 점수 합계 |
| `점수 근거` | 텍스트 | 점수 판단 근거 |
| `도달 난이도` | 선택 또는 텍스트 | 2국면에서 도달한 하·중·상 난이도 |
| `더 알아볼 질문` | 텍스트 | 지문 밖으로 이어진 학생 질문 목록 |
| `질문모음` | 텍스트 | 학생 질문 누적 |
| `챗봇 답변모음` | 텍스트 | 챗봇 답변 누적 |
| `세특용 피드백` | 텍스트 | 교사용 피드백 초안 |
| `업데이트` | 날짜 | 마지막 저장 시각 |

학생이 질문할 때마다 같은 `학교_반_번호` 페이지에 질문, 챗봇 답변, 후속 질문, 평가 분석, 피드백이 페이지 본문으로 추가된다.

## 3. Notion 연동 절차

1. <https://www.notion.so/my-integrations>에서 내부 연동을 만든다.
2. 권한은 읽기와 쓰기 권한을 켠다.
3. 준비 DB와 결과 DB 페이지에서 `Connections`에 해당 연동을 추가한다.
4. 교사용 보드에서 Gemini API 키와 Notion API 토큰을 입력한다.
5. `Supabase에 저장`을 누르면 웹앱 서버가 Integration이 연결된 준비 DB와 결과 DB를 자동으로 찾는다.

구형 고정 Notion DB 방식으로 한 명의 교사 또는 한 개의 템플릿만 서버 환경변수에 묶어 쓸 때만 아래 값을 사용한다.

```bash
NOTION_API_KEY=ntn_your-internal-integration-token
NOTION_API_VERSION=2022-06-28
NOTION_QUESTIONING_PREP_DATABASE_ID=your-questioning-preparation-database-id
NOTION_QUESTIONING_RESULT_DATABASE_ID=your-questioning-result-database-id
```

환경변수를 바꾼 뒤에는 개발 서버 또는 Vercel 배포를 다시 실행한다.

## 4. 수업 운영 흐름

1. 교사용 보드에서 1번 성취기준, 2번 루브릭, 3번 질문 자료, 4번 챗봇 PRD를 준비한다.
2. 교사용 보드 상단의 연결 영역에 Gemini API 키와 Notion API 토큰을 입력한다.
3. `Supabase에 저장하고 수업 코드 만들기`를 누르면 준비 DB에 수업 준비 페이지가 생성되고, Supabase에는 암호화된 연결정보와 수업 코드가 저장된다.
4. 학생은 `/questioning-chatbot?lesson=수업코드` 링크로 들어가거나 학생 화면에서 수업 코드를 입력한다.
5. 학생은 학교, 반, 번호만 입력하고 질문한다.
6. 학생 질문과 챗봇 답변은 결과 DB의 `학교_반_번호` 페이지에 누적된다.

## 5. 주의

- 학생 실명, 전화번호, 상담 내용 등 개인정보를 입력하지 않는다.
- Notion 토큰은 코드나 문서에 넣지 않는다. 운영형에서는 교사용 보드에서 입력한 토큰을 서버가 암호화해 저장한다.
- 공유 앱에서 여러 교사가 각자 노션 워크스페이스를 연결하려면 교사별 Notion 토큰과 자동 탐색된 준비 DB/결과 DB 연결값을 암호화해 저장하는 서버 구조가 필요하다.
- 현재 권장 운영형은 공통 Vercel 웹앱 1개를 유지하고, Supabase에는 수업 코드와 교사별 연결정보만 저장하며, 학생 질문과 챗봇 답변 본문은 교사 개인 Notion 결과 DB에 저장하는 방식이다.
