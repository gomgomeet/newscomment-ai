# Track A — Notion 설정 기록

연수용 자료(사용 설명서·교사용 PPT)에 그대로 반영할 목적의 작업 로그입니다.
Notion 데이터베이스에 가한 변경을 **무엇을 · 왜 · 교사에게 어떻게 설명할지**로 남깁니다.

이 문서는 한국 교사 대상 연수 자료로 바로 이어지는 작업 기록이므로 한글로 작성합니다.

대상 데이터베이스: `💬 학생 댓글 · 생각 나누기`
(`7f88a558-0743-440a-a98b-ed759275b301`)

---

## 결정 사항

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 평가 척도 | **0~5**, 3영역, 총점 15 | 사용자 결정 (2026-08-21). PRD §13 미결정 항목을 확정 |
| 평가 완결 위치 | **Notion 페이지 안에서** 최대한 완결 | 왕초보 교사가 도구를 오가지 않도록 |
| 웹도구 역할 | 진행자 시연용 | 참가자는 배포·설정하지 않음 |

## 2026-08-21 · 스키마 정리

### 1. 영역 점수의 주체를 이름에 드러냄

| 이전 | 이후 |
| --- | --- |
| `기사 이해` | `AI 이해` |
| `생각 연결` | `AI 연결` |
| `생각 표현` | `AI 표현` |

**왜**: 이름만 봐서는 AI 점수인지 교사 점수인지 알 수 없었습니다.

**교사에게 설명할 말**: "AI가 매긴 점수와 선생님이 매긴 점수를 나란히 두려고 이름을 나눴습니다."

### 2. 교사용 영역 점수 신설

`교사 이해` · `교사 연결` · `교사 표현` (숫자, 0~5)

**왜**: 이전에는 교사 쪽에 총점 하나뿐이라 **AI가 어느 영역에서 틀렸는지 짚을 수 없었습니다.**
PRD §F5가 요구하는 AI-교사 대조가 성립하지 않았고, 연수의 핵심 메시지(AI 판단을 교사가
고친다)를 보여줄 수단이 없었습니다.

**교사에게 설명할 말**: "AI가 세 영역으로 나눠 봤으니, 선생님도 같은 세 영역으로 봐 주세요.
그래야 어디서 생각이 갈리는지 보입니다."

### 3. 총점을 손입력에서 수식으로

| 속성 | 이전 | 이후 |
| --- | --- | --- |
| `AI 총점` | 숫자 (손입력) | 수식 = AI 이해 + AI 연결 + AI 표현 |
| `교사 총점` | 숫자 (손입력) | 수식 = 교사 이해 + 교사 연결 + 교사 표현 |

수식 (빈 칸을 0으로 처리해 채점 도중에도 총점이 보이도록):

```
if(empty(prop("AI 이해")), 0, prop("AI 이해"))
  + if(empty(prop("AI 연결")), 0, prop("AI 연결"))
  + if(empty(prop("AI 표현")), 0, prop("AI 표현"))
```

**왜**: 총점은 계산 결과지 입력값이 아닙니다. 손으로 넣으면 영역 점수와 어긋납니다.

**교사에게 설명할 말**: "총점 칸은 건드리지 마세요. 세 영역만 넣으면 저절로 더해집니다."

### 4. 중복 속성 제거

- `AI 점수`(0~5) 삭제 — `AI 총점`과 중복. 전 행에 값이 없어 손실 없음.

**왜**: 3영역이 있는데 별도 총괄 점수가 또 있으면 교사가 "어느 게 진짜 점수인가"에서 멈춥니다.

### 5. 학생 명단 DB 신설

`🧑‍🎓 학생 명단 · 참여 현황` (`f9f36374f8c249f39c796ea211fa4730`)

| 속성 | 유형 | 비고 |
| --- | --- | --- |
| `학생 ID` | 제목 | `S001` 형식. 실명 아님 |
| `이름` | 텍스트 | 선택. 비워도 모든 집계 동작 |
| `모둠` | 선택 | 1~5모둠 |
| `댓글` | **관계** (양방향) | 댓글 DB에 `학생` 속성이 자동 생성됨 |
| `제출 수` | **롤업** (개수) | 자동 |
| `제출 여부` | 수식 | `제출` / `미제출` |
| `참여 수준` | 수식 | `적극`(3건+) / `보통`(1건+) / `미참여` |

**왜**: 미제출자 확인과 참여도 집계를 사람이 세지 않게 하려고. 관계를 한 번 걸면 나머지는
자동으로 따라옵니다.

**교사에게 설명할 말**: "명단과 댓글을 한 번 연결해 두면, 누가 안 냈는지는 필터 하나로 끝납니다."

**중요**: 폼에서 학생이 `학생` 관계 칸으로 **자기 ID를 고르게** 해야 합니다. 타이핑하면 오타가
나고, 오타가 나면 위 집계가 전부 어긋납니다.

### 6. 루브릭 문서를 척도에 맞춰 개정

`📏 01｜교사용 평가 루브릭` **v1.0 → v2.0**

DB는 0~5로 바꿨는데 루브릭 문서는 `1~4수준 · 총점 12점`이었습니다. 그대로 두면 교사가 4수준
표를 보면서 0~5 칸에 점수를 넣는 어긋남이 생깁니다.

| 항목 | v1.0 | v2.0 |
| --- | --- | --- |
| 척도 | 1~4수준 | 0~5점 |
| 총점 | 12점 | 15점 |
| 근거 없음 | 1수준 | 0점 (쓴 내용이 있으나 미흡하면 1점) |
| 최상위 | 4수준 · 깊이 있음 | 5점 · 다른 입장, 질문, 대안까지 나아감 |
| 총점 입력 | 교사가 계산 | Notion이 자동 계산 |

**표 구성도 바꿨습니다.** 6단계를 한 표에 가로로 넣으면 프로젝터에서 읽을 수 없어서, 영역별로
표를 나누고 `점수 | 판단 기준` 세로 배치로 만들었습니다. 연수장 화면에서 읽히는 것이 우선입니다.

`교사 기록 형식` 항목도 실제 DB 속성명(`교사 이해`·`교사 연결`·`교사 표현` 등)과 일대일로
대응하도록 다시 썼습니다.

### 7. 연수생용 안내 페이지 신설

`🧭 오늘의 연수 · 생각을 나누는 뉴스 읽기` (`3c2c5f01a4a481ab80fcd82f13957eb6`)

연수는 Notion 안에서 진행되므로, 참가자가 **이 페이지 하나만 따라가면** 끝나도록 구성했습니다.

- 오늘 하는 것 / **하지 않는 것**(코딩·배포·API 키·결제 없음)을 앞에 명시해 기대를 잡음
- 시작 전 체크 3줄 + "로그인 안 되면 지금 손 드세요" 안내
- 3시간 시간표에 **`여러분은` 열**을 두어 직접 하기/관람/듣기를 구분
- 단계 1~6 각각을 참가자 행동 단위로 서술
- 단계 3에 "일부러 잘 쓰지 않아도 좋다 / 몇 분은 일부러 제출하지 말아 달라" 안내
  → 단계 6-1 미제출자 찾기에서 실제 이름이 뜨게 하기 위한 장치
- 마지막에 오늘의 한 문장을 남김

### 8. 학생 제출 폼 뷰 생성

`💬 학생 댓글` DB에 `✍️ 학생 댓글 제출` 폼 뷰를 추가했습니다.

기사 선택은 **관계 드롭다운**으로 갑니다. 텍스트로 `기사 ID`를 타이핑시키면 오타가 나고, 오타가
나면 미제출자 집계와 기사별 분석이 전부 어긋납니다.

**한계**: 폼 **질문 구성은 MCP 도구로 되지 않습니다.** `SHOW` 지시어가 표·보드 뷰의 표시 속성에만
적용되고 폼 질문에는 반영되지 않아, 생성된 폼에는 `댓글 제목` 질문 하나만 들어 있습니다.
Notion UI에서 직접 `학생`·`연결된 기사`·`댓글` 세 질문을 추가하고 `댓글 제목` 질문을 지워야 합니다.

**`댓글 제목` 질문을 빼는 이유**: 4학년에게 `S001-A01 홍길동` 형식을 타이핑시키면 오타가 나는데,
같은 정보를 `학생` 관계로 이미 정확하게 받습니다. 제출된 행이 표에서 "제목 없음"으로 보이지만
기능에는 영향이 없고, 제목 열을 숨기면 눈에도 띄지 않습니다.

### 9. 목적의식 도입부와 기사 수집 방법 추가

**목적의식 도입부**를 연수생 페이지 앞부분(`시작하기 전에 · 도구보다 목적이 먼저입니다`)에
넣었습니다. 요지는 이렇습니다.

- 생성형 AI 에듀테크 수업은 교사의 자유도를 반영한 활동이 목적. 쉽고 빠른 적용만 원한다면
  이미 만들어진 도구를 쓰는 편이 더 쉽다.
- 역량을 키우는 동기는 기술이 아니라 **목적의식** — 어떤 수업 / 어떤 평가 / 어떤 업무 효율
- 목적의식 없이 바이브 코딩을 하면 "굳이 이걸 해야 하나"로 귀결된다
- 장기적으로는 엄청난 도움이지만, **단기적으로는 시간·시선·에너지·돈을 가져가는 과정**

이 내용을 **맨 앞에 두는 것이 중요합니다.** 뒤에 두면 이미 도구에 마음이 기운 뒤라 경고로만
들리지만, 앞에 두면 "그래서 오늘 무엇을 바꾸고 싶은가"를 스스로 정하고 실습에 들어가게 됩니다.

**기사 수집 방법**을 단계 6-3으로 추가했습니다.

| 방법 | 내용 | 주의 |
| --- | --- | --- |
| Notion 웹 클리퍼 | 기사 페이지를 자료실로 바로 담기 | **저작권** — 전문 복제 금지, 발췌 + 출처·링크 필수 |
| 생성형 AI 리서치 | 조건을 준 프롬프트로 기사 후보 + 요약 + 핵심 질문 받기 | **AI는 없는 기사를 지어냅니다.** 링크를 반드시 직접 열어 확인 |

웹 클리퍼는 **확장 프로그램 설치**가 필요해 40명이 당일에 하면 시간이 무너집니다. 페이지에
"설치는 연수 후에 하셔도 됩니다"를 명시해 두었습니다.

### 10. 명단에 실제 데이터를 채우고 연결 완성

관계와 롤업만 만들어 두고 데이터를 넣지 않아 **연결이 끊긴 상태**였습니다. 이대로였다면 연수
당일 폼의 `학생` 드롭다운에 고를 항목이 하나도 없고, 샘플 댓글의 `제출 수`도 전부 0으로 나왔을
것입니다. 스키마를 만드는 것과 쓸 수 있는 상태로 만드는 것은 다른 일입니다.

| 채운 것 | 내용 |
| --- | --- |
| `S001` ~ `S040` | 연수 참가자 40명용. `모둠`을 8명씩 5개로 미리 배정 |
| `S901` ~ `S906` | 샘플 학생. 기존 샘플 댓글 6건과 `학생` 관계로 연결 |
| `🔴 미제출 학생` 뷰 | `제출 여부 = 미제출` 필터, 학생 ID 오름차순 |

확인 결과 `S901`~`S906`은 연결됨, `S001`~`S040`은 연결 없음(= 미제출)으로 정상입니다.
참가자가 폼을 제출하는 순간 자기 번호가 미제출 목록에서 사라집니다.

**하나의 명단이 두 가지로 쓰입니다.** 연수 중에는 참가 교사 40명의 번호이고, 교실로 가져가면
그대로 내 반 학생 번호가 됩니다. 이 점을 연수생 페이지 6-1에 적어 두었습니다.

**폼에서는 반드시 드롭다운으로 고르게 합니다.** `학생 ID`를 타이핑시키면 오타가 나고, 오타가
나면 관계가 연결되지 않아 제출했는데도 미제출로 잡힙니다. 페이지 단계 3에 이 안내를 넣었습니다.

### 11. 기사 자료실 정리 — 원문 클립 보존, 학생용 분리, 템플릿 신설

원문 클립 6건이 표에서 **비어 보였습니다.** `상태`·`핵심 질문`·`기사 본문(수업용)`·`출처`가 전부
빈칸이어서 삭제 대상으로 보였는데, 페이지 본문을 열어 보니 **기사 전문이 그대로 들어 있었습니다.**
사진, 어동이·어솜이 찬반 토론 자료, 원문 링크까지. 수업용 6건은 이 원문들을 다듬어 만든 것으로
보입니다.

**속성이 비었다고 페이지가 빈 것이 아닙니다.** 지우기 전에 본문을 확인해야 합니다.

이 6건은 연수 자료로도 쓸모가 있습니다. 단계 6-3에서 가르치는 **웹 클리퍼의 결과물 실물**이라,
수업용 기사와 나란히 놓으면 설명이 필요 없습니다.

```
웹 클리퍼로 담아온 원문   →  제목이 길고 지저분, 속성 비어 있음
수업용으로 다듬은 기사    →  제목 정리, 본문 발췌, 핵심 질문 추가
```

**처리 방법**: `상태`(status 타입: 읽기 전 → 활동 중 → 완료)에 옵션을 끼워 넣지 않고, 별도 속성
`자료 구분` SELECT(`원문(교사용)`, `템플릿`)을 새로 만들었습니다. `상태`는 읽기 진행 단계이고
자료 종류는 다른 축이라, 한 칸에 섞으면 모델이 무너집니다.

| 자료 구분 | 건수 | 용도 |
| --- | --- | --- |
| (비움) | 6 | 학생용 수업 기사. `📖 학생용 기사` 뷰에 표시 |
| `원문(교사용)` | 6 | 웹 클리퍼 원문. 학생 뷰에서 제외, 연수 예시로 활용 |
| `템플릿` | 1 | 새 기사 만들 때 복제할 양식 |

**비움을 기본값으로 둔 이유**: 교사가 새 기사를 넣을 때 아무것도 고르지 않아도 학생에게 보입니다.
자주 하는 일에 추가 조작을 요구하지 않는 쪽이 맞습니다.

### 12. 새 기사 템플릿

`📝 새 기사 템플릿 — 복제해서 쓰세요` (`3c2c5f01a4a481839dabfeeeec3ad063`)

본문에 **자기점검 체크리스트와 댓글 폼 링크를 미리 넣어 두었습니다.** 복제하면 그대로 따라오므로
새 기사마다 폼 링크를 다시 붙일 필요가 없습니다. 기사가 늘어날수록 이 차이가 커집니다.

본문에 채울 항목과 이유를 표로 적어 두었고, 특히 이 둘을 강조했습니다.

- `핵심 질문` — 있고 없고가 댓글 질을 가릅니다
- `기사 링크`·`출처` — **반드시** 남겨야 합니다. 저작권 문제를 피하는 최소 조건입니다

복제 후 `자료 구분`을 비워야 학생에게 보인다는 안내도 본문 맨 위에 넣었습니다.

### 13. 폼을 링크가 아니라 임베드로 — Notion이 공개 주소를 삼킵니다

처음에는 공개 폼 주소를 **링크**로 기사 하단에 붙였습니다. 나중에 페이지를 다시 읽어 보니
Notion이 주소를 바꿔 놓았습니다.

```
넣은 것:      https://judicious-ursinia-2c0.notion.site/33c361cb...   (공개 폼)
저장된 것:    https://app.notion.com/p/33c361cb...                    (내부 페이지)
```

`.notion.site` 링크를 같은 워크스페이스의 내부 페이지 참조로 자동 변환합니다. **학생이 눌러도
로그인 벽에 막힙니다.** 겉보기에는 멀쩡한 링크라 눌러 보지 않으면 모릅니다.

**해결**: 링크 대신 `<embed>` 블록을 씁니다. 임베드는 `src`가 그대로 보존되고, 폼이 페이지 안에
바로 뜨므로 학생이 창을 옮길 필요도 없습니다.

**배치**: 기사 **맨 위**에 안내 문구 + 임베드를 넣고, 하단에는 자기점검 체크리스트만 남긴 뒤
"위로 올라가 쓰세요"로 안내합니다. 안내 문구를 "기사를 읽고 나서"로 시작해 읽기 → 쓰기 순서를
말로 잡아 둡니다.

수업용 기사 6건과 `📝 새 기사 템플릿`에 모두 적용했습니다. 템플릿에는 **"폼은 반드시 임베드로
두세요"** 경고를 넣어 두었습니다. 템플릿이 복제되면서 같은 실수가 퍼지는 것을 막기 위해서입니다.

**교사에게 설명할 말**: "폼은 링크 말고 임베드로 넣으세요. Notion이 링크를 내부 주소로 바꿔서
학생이 못 들어갑니다."

### 실습에서 교사가 직접 할 것 / 미리 만들어 둘 것

| | 연수에서 직접 | 템플릿에 미리 |
| --- | --- | --- |
| 관계(Relation) 연결 | O | |
| 롤업(Rollup) 만들기 | O | |
| 필터 뷰 만들기 | O | |
| **수식 입력** | X | O |

**수식을 타이핑시키면 안 됩니다.** 따옴표·괄호 하나 틀리면 오류가 나고, 40명 중 절반이 손을
들면 진행이 멈춥니다. 관계 → 롤업 → 필터 세 가지가 Notion 데이터베이스의 핵심 개념이고,
이 셋만 직접 해보면 충분합니다.

### 40건을 다 채점하지 않는다

교사가 40건을 전수 채점하는 시나리오는 시간상 불가능하고, 가르칠 내용도 아닙니다. 대신:

> "40건을 다 보지 마세요. **AI가 자신 없어 하는 것부터** 보세요."

`AI 확신도 = 낮음` + `교사 우선 검토` 필터가 그 트리아지 역할을 합니다. 연수에서 실제로
채점하는 건 2~3건이면 충분하고, 나머지 시간은 "왜 이것들이 검토 대상으로 올라왔는가"를
읽는 데 씁니다. PRD §3-1 "AI는 초안, 교사가 최종 판단자"를 40건 규모에서 구현하는 방법입니다.

### 짧은 글 = 낮은 점수가 아니다

샘플 두 건이 이 대비를 보여줍니다.

| 학생 | 댓글 | 길이 | 질 |
| --- | --- | --- | --- |
| S902 | "체험학습 좋아요. 많이 가면 좋겠다." | 짧음 | 기사 근거 없음 |
| S905 | "말랑이에서 유해물질이... 확인해 봐야겠다" | 짧음 | 기사 인용 + 행동 |

PRD §F3의 "짧다는 이유만으로 무조건 낮은 점수를 주지 않는다"를 설명할 때 이 두 건을
나란히 띄우면 됩니다. 글자 수는 "성의 없이 낸 사람 훑기"용 참고 지표로만 쓰고, 점수 필드와
분리해 둡니다.

### 개인정보

학생 DB의 제목은 `S001` 형식 ID로 두고 실명은 넣지 않습니다. PRD §F2 "실명 대신 수업용
학생 ID 사용을 기본값으로"에 해당하며, 이 템플릿이 다른 교사에게 복제된다는 점에서 더
중요합니다.

## 부록 · 세특 초안 프롬프트 (연수 자료 하단 수록용)

Notion DB 내용을 복사해 생성형 AI에 주고, 세부능력 및 특기사항 **초안**을 받는 방법입니다.

### 먼저 읽어야 할 두 가지

**① 이건 초안입니다.** PRD §11은 "완전 자동화된 생활기록부 문장 생성"을 범위에서 제외하고
있습니다. AI가 쓴 문장을 그대로 붙여넣는 용도가 아니라, 교사가 관찰한 바를 문장으로 옮기는
시간을 줄이는 용도입니다. **모든 문장은 교사가 읽고 고칩니다.**

**② 실명을 넣지 마세요.** 붙여넣는 표에는 `S001` 같은 학생 ID만 있어야 합니다. 생활기록부
관련 내용을 외부 AI 서비스에 입력하는 것에 대해서는 소속 교육청 지침을 먼저 확인하시고,
확인 전에는 실제 학생 데이터 대신 샘플로 연습하세요.

### 1단계 · Notion에서 표 복사

`💬 학생 댓글` DB의 표 뷰에서 아래 열만 보이게 한 뒤, 행을 드래그해 복사합니다.

```
학생 ID | 기사 ID | 댓글 | 교사 이해 | 교사 연결 | 교사 표현 | 강점 | 피드백 | 평가 포워드
```

한 학생이 여러 기사에 댓글을 썼다면 그 학생의 행을 모두 포함시킵니다. 세특은 한 편의 글이
아니라 **한 학기의 흐름**을 쓰는 것이기 때문입니다.

### 2단계 · 프롬프트

```text
당신은 초등학교 4학년 담임 교사의 기록 작성을 돕는 조수입니다.

[수업 맥락]
신문기사를 읽고 자신의 생각을 댓글로 쓰는 수업을 진행했습니다.
학생 글은 다음 세 영역으로 평가했습니다. 각 영역 0~5점, 총점 15점입니다.
- 기사 내용 이해: 기사의 핵심 내용이나 사실을 정확히 이해했는가
- 기사와 생각 연결: 기사 내용과 자신의 경험·의견·근거를 연결했는가
- 생각 표현: 의견이 구체적이고 이해하기 쉽게 표현되었는가

[작성 규칙]
1. 아래 표에 있는 내용만 근거로 쓰십시오. 표에 없는 활동이나 태도를 지어내지 마십시오.
2. 학생이 실제로 쓴 문장에서 관찰되는 것만 서술하십시오.
3. 점수와 등급은 문장에 쓰지 마십시오. 무엇을 어떻게 했는지로 표현하십시오.
4. 다른 학생과 비교하지 마십시오. "우수함", "뛰어남" 같은 서열 표현을 쓰지 마십시오.
5. 부정적 단정을 쓰지 마십시오. 부족한 부분은 앞으로의 방향으로 바꿔 쓰십시오.
   (예: "근거가 없음" → "자신의 생각에 까닭을 덧붙이면 설득력이 커질 것으로 기대됨")
6. 명사형으로 끝내십시오. (~함, ~임, ~을 보임)
7. 한 학생당 200~300자로 쓰십시오.
8. 학생 이름이나 ID를 문장에 넣지 마십시오.

[출력 형식]
학생 ID를 제목으로 하고, 그 아래에 세특 초안 한 문단만 쓰십시오.
문단 끝에 "교사 확인 필요:" 로 시작하는 한 줄을 덧붙여, 표만으로는 판단할 수 없어
선생님이 직접 확인해야 할 점을 적으십시오.

[학생 자료]
(여기에 Notion에서 복사한 표를 붙여넣으세요)
```

### 3단계 · 결과 예시

위 프롬프트에 샘플 학생 S901의 행을 넣었을 때 기대되는 형태입니다.

> **S901**
>
> 신문기사를 읽고 의견을 쓰는 활동에서 기사의 핵심 주장인 '교실 밖 배움'의 가치를 정확히
> 짚어내고, 갯벌 체험학습에서 교과서로 볼 때보다 잘 이해했던 자신의 경험과 연결하여 근거를
> 제시함. 기사에 함께 실린 교사의 책임 부담 문제도 놓치지 않고, 안전 담당 교사를 따로 두자는
> 대안을 스스로 제안하는 등 찬반 한쪽에 머무르지 않고 해결 방향까지 생각을 넓히는 모습을 보임.
>
> 교사 확인 필요: 이 관점이 이 학생에게 반복적으로 나타나는지, 한 편의 글에서만 보인 것인지
> 다른 기사 댓글과 함께 확인이 필요합니다.

**연수에서 짚을 것**: "교사 확인 필요" 줄이 이 프롬프트의 핵심입니다. AI는 표에 있는 것만 알기
때문에, 한 편의 글로 학생을 단정하지 않도록 스스로 한계를 밝히게 만든 장치입니다.

### 자주 나오는 실패와 대처

| 증상 | 원인 | 대처 |
| --- | --- | --- |
| 표에 없는 활동이 등장함 | 규칙 1이 무시됨 | "표에 없는 내용을 쓰면 안 됩니다"를 다시 강조해 재요청 |
| "매우 우수한" 같은 표현 | 규칙 4 위반 | 해당 문장만 지목해 다시 쓰게 함 |
| 문장이 다 비슷함 | 학생별 자료가 빈약 | 댓글 수가 적은 학생임. 세특보다 **참여 독려**가 먼저 |
| 너무 길거나 짧음 | 글자 수 지시 무시 | 글자 수를 다시 명시하고 한 명씩 나눠 요청 |

### 이 프롬프트가 잘 나오려면 앞이 채워져 있어야 합니다

세특 초안의 질은 **교사가 채운 `강점`·`피드백`·`평가 포워드`** 에 거의 전적으로 달려 있습니다.
그 칸이 비어 있으면 AI가 쓸 수 있는 것은 댓글 원문뿐이고, 결과는 학생별로 비슷해집니다.

연수에서는 이 순서로 보여주는 것이 좋습니다.

```
강점·피드백을 비운 채 → 세특 요청 → 밋밋한 결과
강점·피드백을 채운 뒤 → 세특 요청 → 구체적인 결과
```

같은 학생, 같은 프롬프트로 두 번 돌려 비교하면 "AI를 잘 쓰는 법이 아니라 **관찰을 잘 남기는
법**이 핵심"이라는 메시지가 분명해집니다.
