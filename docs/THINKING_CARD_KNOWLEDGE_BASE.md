# 생각 카드 지식베이스 설계

생각 카드는 "AI가 미리 만든 답변 모음"이 아니다. **AI가 학생 질문에 답하기 위해
미리 조사하고 구조화해 놓은 작은 지식 단위들의 네트워크**다.

이 구조의 핵심 이점은 생성 모델을 갈아 끼워도 카드와 DB는 그대로 남는다는 것이다.
Gemini에서 GPT로 바꾸든, 저비용 모델로 내리든 지식은 유지된다.

## 1. 두 AI의 역할 분리

| | Teacher AI | Student AI |
| --- | --- | --- |
| 시점 | 수업 전 (교사가 자료를 넣을 때) | 수업 중 (학생이 물을 때) |
| 하는 일 | 기사 연구, 추론, 외부 검색, 카드 생성 | 질문 이해, 카드 검색·조합, 쉬운 설명 |
| 필요한 성능 | 높음 — 추론과 조사 품질이 카드 품질을 좌우 | 낮아도 됨 — 좋은 카드를 정확히 찾아 안전하게 조합 |
| 권장 모델 | 고성능 추론 모델 | Gemini Flash급 저비용 모델 |

**Teacher AI는 똑똑해야 하고, Student AI는 빠르고 친절하면 된다.** 학생 응답 품질은
모델 성능보다 카드 품질과 검색 정확도가 좌우한다.

## 2. 카드 8종

| 카드 유형 | `card_type` | 목적 | 핵심 내용 |
| --- | --- | --- | --- |
| 낱말카드 | `vocabulary` | 어휘 이해 | 뜻, 문맥적 의미, 예문, 유의어 |
| 사실카드 | `fact` | 지문 정보 저장 | 지문에 직접 제시된 사실 |
| 추론카드 | `inference` | 숨은 의미 파악 | 원인, 결과, 의도, 관계 추론 |
| 배경지식카드 | `background` | 이해 보충 | 지문 이해에 필요한 사전지식 |
| 리서치카드 | `research` | 외부 정보 보충 | 검색한 최신 정보와 출처 |
| 예상질문카드 | `expected_question` | 학생 질문 대비 | 학생이 물을 가능성이 높은 질문 |
| 확장사고카드 | `extension` | 사고 확장 | 비교, 비판, 적용, 후속 질문 |
| 대화설계카드 | `dialogue_design` | 교사 의도 반영 | 언제·무엇을·왜 묻는지 (교사 메모에서 생성) |

### 카드는 서로 연결된다

기사 문장 하나가 여러 카드로 갈라지고, 그 카드들이 이어진다.

> "출생아 수 감소로 생산가능인구가 줄어들 것으로 전망된다."

```text
[낱말] 생산가능인구 = 경제활동을 할 수 있는 연령대의 인구
   ↓
[사실] 출생아 수가 감소하고 있다
   ↓
[추론] 출생아 감소 → 미래 생산가능인구 감소 가능성
   ↓
[배경지식] 생산가능인구가 경제에 중요한 이유
   ↓
[리서치] 통계청 생산연령인구 전망
   ↓
[예상질문] "사람이 줄어들면 왜 경제가 어려워지나요?"
   ↓
[확장사고] "AI와 로봇이 노동력 감소를 대신할 수 있을까?"
```

## 3. 공통 메타데이터

모든 카드는 근거와 신뢰도를 지고 다닌다. 이것이 "요약 카드"와 갈리는 지점이다.

### `source_type` — 이 정보는 어디서 왔나

```text
passage    지문에 직접 있음
inference  AI가 추론함
external   외부 자료에서 찾음
teacher    교사가 입력함
ai         AI가 생성함 (근거 표시 없음)
```

`source_text`에 실제 근거 문장을, `source_location`에 위치를 저장한다.

```json
{
  "source_type": "passage",
  "source_text": "출생아 수 감소로 생산가능인구가 줄어들 것으로 전망된다.",
  "source_location": "3문단 2번째 문장"
}
```

이렇게 두면 챗봇이 답할 때 근거를 그대로 제시할 수 있다.

> **지문 근거** — 3문단에서 출생아 수 감소가 생산가능인구 감소로 이어질 수 있다고
> 설명하고 있습니다.

### `reasoning_type` — 어떤 사고인가

```text
cause_effect | comparison | prediction | intention
generalization | evidence | problem_solution | sequence
```

나중에 **학생의 사고력 평가**에도 쓴다. 학생이 어떤 유형의 사고를 요구하는 질문을
했는지 분류할 수 있다.

### `confidence` — 얼마나 확실한가

```text
1.0  지문에 명확하게 제시
0.8  근거가 충분한 추론
0.6  여러 가능성 중 하나
0.4  추가 확인 필요
```

지문에서 직접 가져온 사실카드는 0.95~1.0, 문맥 추론은 0.7~0.85, 근거가 얕은 추론은
더 낮게 잡는다.

### `knowledge_status` — 승인 대기 상태가 아니라 출처 등급

```text
verified     지문에 직접 있거나 교사가 쓴 것
researched   외부 자료로 확인함 (출처 A·B)
inferred     AI 추론
needs_review 근거가 얕음
outdated     오래된 정보
```

답변에 쓰는 우선순위: `verified` → `researched` → `inferred` → `needs_review`.
**`needs_review`는 학생 답변 근거로 직접 쓰지 않는다.**

이 값은 교사가 클릭해서 바꾸는 것이 아니라 **카드가 만들어질 때 정해진다**.
교사가 손대는 것은 9절의 두 가지(메모 해석, 리서치 선택)뿐이다.

### `student_level`, `difficulty` — 누구에게 맞는 설명인가

```json
{ "student_level": "elementary_4", "difficulty": 2 }
```

같은 내용을 수준별로 다르게 표현한다. 원본 카드에는

> 생산가능인구 감소는 노동공급 감소와 잠재성장률 하락으로 연결될 가능성이 있다.

라고 저장해 두고, 초등학생에게는

> 일을 할 수 있는 사람이 줄어들면 회사에서 일할 사람이 부족해질 수 있고, 물건이나
> 서비스를 만드는 양에도 영향을 줄 수 있어요.

로 바꿔 말한다.

## 4. 예상질문카드는 라우터다

**답을 예상질문카드 하나에 전부 저장하지 않는다.** 질문카드는 관련 카드를 이어 주는
라우터 역할만 한다.

```json
{
  "card_type": "expected_question",
  "question": "사람이 줄어들면 왜 경제가 어려워져요?",
  "question_intent": "cause",
  "answer_summary": "경제활동을 하는 사람이 감소하면 노동력과 소비가 함께 줄어들 수 있기 때문이다.",
  "related_card_ids": ["fact_12", "inference_7", "background_4", "research_3"],
  "student_level": "elementary_4"
}
```

이렇게 해야 학생이 예상 질문과 **똑같은 표현을 쓰지 않아도** 답할 수 있다. 아래 네
질문은 표현이 다르지만 같은 질문이다.

```text
왜 애가 적게 태어나면 문제예요?
출산율하고 경제가 무슨 관계예요?
사람이 줄어들면 경제가 왜 나빠져요?
저출산이 경제에 영향을 주는 이유가 뭐예요?
```

문자열 검색이 아니라 **embedding 기반 의미 검색**으로 같은 카드 묶음에 연결한다.

## 5. 리서치카드의 출처 관리

```json
{
  "card_type": "research",
  "title": "한국 생산연령인구 전망",
  "claim": "한국의 생산연령인구는 장기적으로 감소할 것으로 전망된다.",
  "source": {
    "organization": "통계청",
    "title": "장래인구추계",
    "url": "...",
    "published_at": "2025-xx-xx",
    "accessed_at": "2026-08-25"
  },
  "reliability": "high"
}
```

출처 신뢰성 등급:

```text
A  정부·국제기구·학술자료
B  주요 언론·전문기관
C  일반 웹사이트
D  검증되지 않은 자료
```

학생용 답변에는 가능하면 **A와 B만** 쓴다.

## 6. 데이터베이스

카드 유형별로 테이블을 나누지 않고 **하나의 `thinking_cards` 테이블에 `card_type`으로
구분**한다. 확장과 검색이 훨씬 쉽다.

| 테이블 | 역할 |
| --- | --- |
| `questioning_documents` | 원본 지문·신문기사 |
| `questioning_thinking_cards` | AI가 만들어 놓은 생각 카드 |
| `questioning_card_relations` | 카드 간 연결 관계 |
| `questioning_student_questions` | 실제 학생 질문과 답변 기록 |

스키마는 `supabase/migrations/004_questioning_thinking_cards.sql` 참조.

## 7. 학생 질문 처리 파이프라인

```text
[학생 질문]
      ↓
Question Normalizer          오타·불완전 문장 정리 (원문도 보존)
      ↓
Intent Classifier            낱말/사실/이해/원인/결과/비교/배경/확장
      ↓
Conversation Context Resolver  "그 사람들이 줄면?" → 직전 턴의 대상 연결
      ↓
Thinking Card Retriever      embedding + 유형 가중치
      ↓
Card Ranker                  최종점수로 상위 3~6개만 추림
      ↓
Evidence Sufficiency Check   답할 수 있는가 판정
      ↓
   충분 → Answer Generator     |  부족 → 제한 답변 / 추가 리서치
      ↓
Student-level Rewriter       학년에 맞는 길이·어휘
      ↓
Safety / Grounding Check
      ↓
[최종 답변] + 질문·사용 카드·응답 저장
```

### 검색 점수

```text
최종점수 = 의미 유사도 × 카드유형 가중치 × 신뢰도 가중치 × 학생 수준 적합도 × 최신성
```

질문 의도별 카드 유형 가중치 예시 (원인 질문):

```text
inference 1.0 | fact 0.9 | background 0.8 | research 0.7 | vocabulary 0.4 | extension 0.3
```

### 근거 충분성 판정

바로 답하게 하지 않고 짧은 판정을 먼저 시킨다.

```json
{ "answerable": true, "confidence": 0.91, "missing_information": null }
```

부족하면:

```json
{ "answerable": false, "confidence": 0.42, "missing_information": "다른 국가의 출산율 비교 자료" }
```

이 단계가 환각을 크게 줄인다.

### "모르겠어요" 임계값

```text
confidence ≥ 0.80   정상 답변
0.60 ~ 0.79         제한적 답변 + 불확실성 표시
< 0.60              직접 답변 금지 → 추가 리서치 또는 교사 확인
```

교육용 AI는 무조건 답하는 것보다 **"지금 생각카드에 충분한 정보가 없어요. 기사에서
알 수 있는 부분은 여기까지예요."** 라고 말할 수 있어야 한다.

## 8. 답변 구조

복잡하게 하지 않는다. 네 단계로 고정한다.

```text
① 바로 대답  ② 쉽게 설명  ③ 근거  ④ 더 생각해 볼 질문
```

> 아이가 적게 태어나면 시간이 지나면서 일을 할 수 있는 사람도 줄어들 수 있기 때문이에요.
> 일을 할 사람이 줄면 회사에서 사람을 구하기 어려워질 수 있고, 물건을 사는 사람도 줄어들 수 있어요.
> 기사에서는 출생아 감소가 미래의 생산가능인구 감소와 연결될 수 있다고 설명하고 있어요.
> 그렇다면 로봇이나 AI가 부족한 일손을 대신할 수 있을까요?

학년별 길이:

```text
초등 1~2   2~3문장, 쉬운 단어, 예시 중심
초등 3~4   3~5문장, 원인·결과 설명
초등 5~6   4~7문장, 근거 + 추론
중학생     개념 + 근거 + 반론 가능
```

내부적으로는 구조화해서 받고, 화면에는 자연스럽게 렌더링한다.

```json
{
  "answer": "아이들이 적게 태어나면...",
  "evidence": [
    { "card_id": "fact_12", "type": "passage" },
    { "card_id": "inference_7", "type": "inference" }
  ],
  "confidence": 0.89,
  "follow_up_question": "AI가 부족한 일손을 대신할 수 있을까요?"
}
```

## 9. 교사 확인은 한 번만, 두 가지만

**대부분의 카드는 교사가 승인할 성질이 아니다.** 낱말 뜻, 지문 사실, 문장 구조,
맥락 이해는 지문에서 기계적으로 나오므로 확인 절차를 걸면 준비 시간만 늘어난다.
37개 카드를 훑게 만드는 순간 웹앱을 쓰는 이유가 사라진다.

확인이 필요한 것은 두 가지뿐이고, **한 화면에 모아 한 번만** 묻는다.

```text
─────────────────────────────────────────────
 챗봇에 반영하기 전에 확인해 주세요
─────────────────────────────────────────────
 ▸ 선생님 메모를 이렇게 이해했습니다
   "제목을 보고 추론하는 질문을 잘 하도록 도와줘"
   → 대화를 시작할 때와 학생이 막힐 때
     "제목을 보고 궁금한 점이 있나요?" 라고 물어봅니다.
   [발문 고치기]

 ▸ 웹에서 찾은 배경 지식 — 쓸 것만 남겨 주세요
   ☑ 통계청 장래인구추계 · 출처 A
   ☑ 교육부 급식 잔반 통계 · 출처 A
   ☐ 블로그 잔반 사례 · 출처 C
   ☐ 저출산이 집값 상승의 원인 · 근거 부족

 나머지 카드(낱말 8 · 사실 6 · 추론 7 · 예상질문 5)는
 지문에서 뽑은 것이라 그대로 사용합니다.
─────────────────────────────────────────────
        [승인하고 적용]   [취소]
─────────────────────────────────────────────
```

규칙 세 가지를 지킨다.

1. **확인할 것이 없으면 창이 뜨지 않는다.** 메모도 없고 리서치 결과도 없으면 ⑧이
   지금처럼 바로 처리한다. 빈 확인 창은 절차만 늘린다.
2. **기본값이 안전하다.** 출처 A·B는 미리 체크, C·D와 근거 부족은 해제. 교사가
   읽지 않고 [승인하고 적용]만 눌러도 위험한 정보는 들어가지 않는다.
3. **자동 카드는 숫자로만 보여 준다.** 낱말 8개를 펼치면 다시 읽을 것이 늘어난다.

같은 자료로 다시 ⑧을 누를 때는 **직전 선택을 기억**한다. 수업 준비 중 두세 번
누르는데 매번 체크를 다시 하게 만들면 성가시다.

### 메모는 승인이 아니라 해석 확인

메모는 교사가 직접 쓴 것이라 내용을 승인받을 이유가 없다. 위험한 것은 **AI가 메모를
잘못 해석했을 가능성**이다. 그래서 체크박스가 아니라 **해석 결과 문장을 직접 고치게**
한다. 손대지 않으면 그대로 쓴다.

교사 메모는 `dialogue_design` 카드가 된다.

> 메모: "제목을 보고 추론하는 질문을 잘 하도록 도와줘"
> → 트리거: 대화 시작 / 학생이 막힘
> → 발문: "제목을 보고 궁금한 점이 있나요?"
> → 목표: 예측 질문 유도

우선 **메모 한 줄 = 카드 한 장**으로 단순하게 시작한다. 긴 메모에 여러 의도가 섞이면
자동 분리가 엉뚱해질 수 있으므로, 실제 메모를 보며 다듬는다.

## 10. 축적되는 자산

`questioning_student_questions`에 질문·사용 카드·응답을 저장하면 나중에 큰 자산이 된다.

```text
AI 예상질문  vs  실제 학생 질문
```

를 비교해 **"생각카드 생성 AI가 학생들의 궁금증을 얼마나 잘 예상했는가"** 를 평가할 수
있고, 카드 생성 모델을 개선하는 근거가 된다. 나아가 질문의 깊이·근거 활용·추론 수준·
확장 질문 여부로 학생 학습 평가까지 확장할 수 있다.

## 11. 현재 구현과의 격차 (2026-08-25 기준)

이 문서는 목표 설계다. 지금 코드는 아직 여기 못 미친다.

### 이미 일치하는 것
- **근거·추론 구분**: `SourceStatus`(`supported` / `reasonable_inference` /
  `source_insufficient` / `out_of_scope`)가 `source_type`에 대응한다. 챗봇이
  "지문에는 없지만 알려진 내용이에요"라고 밝히고 답하는 규칙도 있다.
- **"모르겠어요" 로직**: 근거가 없으면 지어내지 않고 확인 방법을 안내한다.
  다만 숫자 임계값이 아니라 이분법이다.
- **근거 문장 보존**: 생각 카드의 `evidenceSentence`, 어휘의 `contextSentence`.
  `source_location`(몇 문단 몇 번째 문장)은 없다.
- **Teacher AI / Student AI 분리**: 교사 보드는 Gemini로 자료를 분석하고,
  학생 응답은 로컬 엔진이 처리한다.

### 결정적으로 다른 것
1. **카드가 저장되지 않는다.** `buildThinkingCard()`는 호출할 때마다 다시 계산해
   챗봇 지시문 텍스트로 밀어 넣고 버린다. DB가 없어 교사 검토·재사용·학생 질문
   연결 기록이 모두 불가능하다.
2. **검색이 아니라 키워드 매칭이다.** `findEvidence()`가 핵심어 2개 이상 문자열
   포함으로 근거를 고른다. 그래서 "왜 애가 적게 태어나면 문제예요?"와 "저출산이
   경제에 영향을 주는 이유가 뭐예요?"를 다른 질문으로 취급한다.
3. **카드가 7종이 아니다.** 6개 학생 관점으로 질문만 만들고, `fact`/`inference`/
   `background` 같은 지식 단위 카드와 카드 간 연결이 없다. **리서치카드(외부
   정보+출처)는 통째로 빠져 있어** 지문 밖 내용을 조사하지 않는다.
